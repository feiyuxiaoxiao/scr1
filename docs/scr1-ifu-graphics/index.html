环形缓冲容量 = 2 个 32 位字 = 4 个半字槽（:77-78）。写入按指令片段 宽度推进 wptr（:394-396），读出按队头类型推进 rptr （:409-411）。读写指针相等即空（:453）。按半字存储是为了支持 RVC 变长指令与跨块 RVI 拼接（半字是 RVC / RVI / 取指块三者的公共最小单位）。

图 6：跨块 RVI 拼接时序

sequenceDiagram autonumber participant IMEM as IMEM 指令内存 participant IFU as IFU participant Q as 队列四半字 Note over IFU: new_pc 指向非4对齐位置 IFU->>IMEM: 请求块A 地址对齐到4 IMEM-->>IFU: rdata_A 高半槽为某RVI低半 Note over IFU: 高半槽是RVI低半 Note over IFU: instr_hi_rvi_lo_next 置位 IFU->>Q: 按宽度写入 2 槽 IFU->>IMEM: 请求块B 地址加4 IMEM-->>IFU: rdata_B 低半槽为RVI高半 Note over IFU: 低半槽先拼队内悬空低半 IFU->>Q: 继续写入 IFU->>IDU: 输出 q_data_next 拼 q_data_head Note over IDU: 完整 RVI 被还原
32 位 RVI 若从块地址 +2 开始，其低 16 位落在块 A 的高半槽、高 16 位落在块 B 的低半槽，两个半字相隔一次取指延迟到达。IFU 用 1 bit 欠账标志记录状态 （:308-322），到块 B 时把低半槽内容当 RVI_HI 拼接而非独立指令 （:290-293）。

图 7：IMEM 请求-响应握手与在飞计数

sequenceDiagram autonumber participant IFU as IFU participant IMEM as IMEM Note over IFU: pnd=0 discard=0 IFU->>IMEM: req_o=1 addr_o=PC IMEM-->>IFU: req_ack_i=1 握手完成 Note over IFU: pnd 0转1 在飞一笔 IMEM-->>IFU: resp_i=RDY_OK Note over IFU: pnd 1转0 数据入队 IFU->>IMEM: req_o=1 addr_o=PC+4 IMEM-->>IFU: req_ack_i=1 Note over IFU: pnd 0转1 IMEM-->>IFU: resp_i=RDY_ER 错误 Note over IFU: pnd 1转0 Note over IFU: discard 增加 响应作废 Note over IFU: FSM 回 IDLE 停发
请求侧握手：req 与 ack 同时为 1 即成交（:513）。 pending 计数器在握手上沿 +1、响应到达 -1（:543-553），用于支持 IMEM 多拍后响应。 错误响应触发 discard 计数（:569-591），把出错后所有在飞/队列指令按序清掉。

图 8：错误注入 → 精确异常链路

flowchart LR ER["IMEM resp=ER"] --> S1["错误写入队列 q_err 随槽存储"] S1 --> S2["取指侧刹车 FSM回IDLE"] S1 --> S3["队头带错指令出队"] S2 --> S4["丢弃后续在飞指令"] S3 --> S5["ifu2idu_imem_err_o=1"] S5 --> S6["IDU 不译码 生成访问异常"] S6 --> S7["EXU 到 CSR trap"] S7 --> S8["MCAUSE=1 MEPC=出错指令"]
IMEM 出错时错误被伪装成一条指令注入队列，与正常指令一起按序流动，到 IDU/EXU 才翻牌成异常——这是 RISC-V 精确异常的关键（:419-444； scr1_pipe_idu.sv:134-137）。取指侧同时踩刹车清掉错误之后的指令，避免其产生副作用。
