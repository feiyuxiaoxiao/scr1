模块概述

文件信息
路径: src/core/pipeline/scr1_pipe_mprf.sv
行数: 167 行
功能: 实现 32 个 32 位通用寄存器堆, 提供 2 读 1 写端口

MPRF (Multi-Port Register File) 是 唯一直接与 32 个通用寄存器 x0-x31 交互 的模块。它由 EXU 驱动, 被动响应读写请求, 不包含任何控制逻辑。

特性值
寄存器数量32 个 (x0-x31)
位宽32 位 (SCR1_XLEN)
读端口2 个 (rs1 + rs2, 同时读取)
写端口1 个 (rd)
物理存储仅 31 个寄存器 (x0 不占存储, 硬连线为 0)
读取延迟分布式逻辑: 0 周期 / RAM 模式: 1 周期

一、接口信号 -- 与 EXU 单向通信 (第 9-24 行)

MPRF 是完全被动的, 只接收 EXU 的命令, 返回数据。

// 读端口 1 (rs1)
input  logic [4:0]       exu2mprf_rs1_addr_i,  // 读地址: 0-31, 5 位
output logic [31:0]      mprf2exu_rs1_data_o,  // 读数据: 32 位

// 读端口 2 (rs2)
input  logic [4:0]       exu2mprf_rs2_addr_i,  // 读地址
output logic [31:0]      mprf2exu_rs2_data_o,  // 读数据

// 写端口 (rd)
input  logic             exu2mprf_w_req_i,     // 写请求: 1=有效
input  logic [4:0]       exu2mprf_rd_addr_i,   // 写地址
input  logic [31:0]      exu2mprf_rd_data_i    // 写数据
命名规范
所有信号遵循 源2目_信号名 格式: exu2mprf_xxx 表示从 EXU 流向 MPRF, mprf2exu_xxx 表示从 MPRF 流向 EXU。

二、两种实现模式 -- SCR1_MPRF_RAM 宏分叉 (第 62-64 行 vs 第 90-152 行)

通过 `ifdef SCR1_MPRF_RAM 宏, 在编译时选择两种完全不同的物理实现。

为什么 RAM 模式需要 2 个存储体? (第 52-60 行)

FPGA 的 BRAM 是简单双端口: 1 读 + 1 写。但流水线可能同时发生 3 次访问:

  • rs1 读 (例如 ADD x5, x3, x4 中的 x3)
  • rs2 读 (例如 x4)
  • rd 写 (上一条指令的结果写入)

2 个 BRAM 解决了 2 读 1 写的需求: mprf_int 负责 rs1 读 + rd 写, mprf_int2 负责 rs2 读 + rd 写。两个 BRAM 做相同的写入, 保证数据一致。

FPGA 特定优化
ramstyle = "M9K" / "M10K" 属性 (第 52-57 行) 是针对 Intel FPGA 的 BRAM 类型约束, 告诉综合工具使用指定的 RAM 块。

三、x0 硬连线零 -- 核心技巧 (第 71-74 行)

这是 MPRF 中最精妙的设计: 用 3 行代码实现 x0 的零特性, 不消耗任何额外硬件。

assign  rs1_addr_vd  =   |exu2mprf_rs1_addr_i;    // 归约或: 5 位全 0 则结果为 0
assign  rs2_addr_vd  =   |exu2mprf_rs2_addr_i;
assign  wr_req_vd    =   exu2mprf_w_req_i & |exu2mprf_rd_addr_i;  // 写 x0 时 wr_req_vd=0

归约或运算符 | 的作用

输入 addr|addr_vd 结果行为
5'b00000 (x0)00 (无效)输出 '0, 写入被抑制
5'b00001 (x1)11 (有效)正常读写
5'bxxxxx (任意非零)11 (有效)正常读写

三步联动实现 x0=0

// 步骤 1: rs1_addr_vd=0 时...
//   分布式模式 (第 133 行):
mprf2exu_rs1_data_o = (rs1_addr_vd) ? mprf_int[addr] : '0;
//   RAM 模式 (第 100 行):
mprf2exu_rs1_data_o = (rs1_new_data_req_ff) ? rd_data_ff : (rs1_addr_vd_ff) ? rs1_data_ff : '0;

// 步骤 2: rs2_addr_vd=0 时... (同上)

// 步骤 3: wr_req_vd=0 时... (第 122/142 行)
if (wr_req_vd) begin
    mprf_int[rd_addr] <= rd_data;  // 写 x0 时不执行此行
end
寄存器数组索引从 1 开始
mprf_int [1:SCR1_MPRF_SIZE-1] (第 53-64 行), 即 [1:31]。
x0 不占用任何物理存储单元, 只有 x1-x31 需要存储。

四、RAM 模式的写优先旁路 (第 78-111 行)

RAM 模式使用同步读 (1 周期延迟), 导致同一个寄存器被同时读写时, 读出的是旧值。旁路逻辑解决这个读写冲突。

冲突检测 (第 78-80 行)

assign  rs1_new_data_req  = wr_req_vd & (exu2mprf_rs1_addr_i == exu2mprf_rd_addr_i);
assign  rs2_new_data_req  = wr_req_vd & (exu2mprf_rs2_addr_i == exu2mprf_rd_addr_i);
assign  read_new_data_req = rs1_new_data_req | rs2_new_data_req;

当 rs1 或 rs2 的读地址等于 rd 的写地址时, 标记"需要旁路"。

旁路数据选择 (第 100-106 行)

assign  mprf2exu_rs1_data_o = (rs1_new_data_req_ff) ? rd_data_ff
                                                  : (rs1_addr_vd_ff) ? rs1_data_ff
                                                                     : '0;

assign  mprf2exu_rs2_data_o = (rs2_new_data_req_ff) ? rd_data_ff
                                                  : (rs2_addr_vd_ff) ? rs2_data_ff
                                                                     : '0;

时序图: 旁路工作流程 (延迟 2 周期)

周期 N:   IDU 发出 rs1_addr=x5, rd_addr=x5 (同寄存器读写冲突)
          检测到 rs1_new_data_req=1

周期 N+1: RAM 同步读 x5 旧值 → rs1_data_ff=旧值
          同时新数据 rd_data_ff=新值 (第 109-111 行寄存)
          rs1_new_data_req_ff=1 (第 85 行延迟一拍)

周期 N+1: mprf2exu_rs1_data_o = (rs1_new_data_req_ff=1) ? rd_data_ff(新值) : rs1_data_ff(旧值)
          输出新值, 旁路成功
等价于 FPGA BRAM 的 RDW (Read-During-Write)
标准的 FPGA BRAM 不支持 write-first 行为, 此旁路逻辑用外部寄存器和多路选择器模拟了 "读新不读旧" 的 write-first 语义。

五、SVA 断言 (第 154-165 行)

`ifdef SCR1_TRGT_SIMULATION
`ifdef SCR1_MPRF_RST_EN
SCR1_SVA_MPRF_WRITEX : assert property (
    @(negedge clk) disable iff (~rst_n)
    exu2mprf_w_req_i |-> !$isunknown(
        {exu2mprf_rd_addr_i,
         (|exu2mprf_rd_addr_i ? exu2mprf_rd_data_i : `SCR1_XLEN'd0)}
    )
) else $error("MPRF error: unknown values");
`endif
`endif
断言行号检测条件触发时刻
SCR1_SVA_MPRF_WRITEX159-162写请求有效时, 地址和数据必须无 X/Z 态negedge clk

为什么用 negedge clk? 写操作发生在 posedge clk, 到 negedge 时, 来自 EXU 的 rd_addr_i 和 rd_data_i 已经稳定, 此时检查 X 态最可靠。

为什么检查 rd_data_i 时要判断 |rd_addr_i? 当写入 x0 时, 数据会被丢弃, 此时 rd_data_i 是否为 X 并不重要。所以构造检查表达式时, 如果 rd_addr=0 (写入 x0), 就用 32'd0 替代真实数据值, 避免误报。

六、数据流总图

                              SCR1 MPRF 数据流
                              =================

    exu2mprf_rs1_addr_i ──→ [|] → rs1_addr_vd ──→ 读 mprf_int[addr] ──→ ┐
                           [归约或]                                          ├──→ mprf2exu_rs1_data_o
                                                                            │
    exu2mprf_rs2_addr_i ──→ [|] → rs2_addr_vd ──→ 读 mprf_int[addr] ──→ ┤
                           [归约或]                                          ├──→ mprf2exu_rs2_data_o
                                                                            │
    exu2mprf_w_req_i ──→ [&] ──→ wr_req_vd ──→ 写 mprf_int[rd_addr] ←──┤
                           ↑                                               │
    exu2mprf_rd_addr_i ──→ [|] → rd_addr_vd ─────┘                        │
                           [归约或]                                          │
    exu2mprf_rd_data_i ─────────────────────────────────────────────────────┘

    关键点:
    - [|] 是归约或: 地址为 5'b00000 (x0) 时输出 0, 抑制所有读写
    - 寄存器数组 [1:31], x0 不占物理存储
    - 分布式逻辑: 读为组合逻辑 (0 延迟)
    - RAM 宏: 读为同步逻辑 (1 周期延迟) + 旁路处理同周期读写冲突
