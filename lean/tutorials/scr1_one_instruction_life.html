一、为什么你看不懂？

你的两个困惑，根源在这里

困惑 1：缺乏整体主线

教程按周次拆模块（第 8 周 IFU、第 9 周 IDU/EXU、第 10 周 IALU/LSU/MPRF...）。每个模块单独讲都很细，但你不知道它们在一条指令执行中如何接力。就像把汽车拆成发动机、变速箱、车架分别讲三遍，你没看过整车是怎么跑起来的。

困惑 2：信号太多抓不住重点

每个模块有 20-40 个端口。但一条指令在模块间流动时，真正起决定作用的信号 一只手数得过来。其他信号都是"电梯里的按钮"——存在，但你不坐电梯就碰不到。

本页的目标
用一条指令从出生到退休的完整旅程，把 14 周内容串成一根主线。学完这一页，你会得到一个"思维骨架"——之后再看任何一周的细节，都能知道它挂在骨架的哪个位置。

怎么读这张图
  • 指令数据流是自上而下：IFU→IDU→EXU→（MPRF/LSU/CSR）
  • 控制信号（新 PC、反压）是反向/旁路：EXU 往回流
  • 每个箭头都是模块间的一对 握手信号（vd=数据有效，rdy=接收就绪）

三、第一站：取指（IFU）

① 取指 IFU：去内存拿一条指令

职责：按 PC（程序计数器）指定的地址，从指令内存 IMEM 取回指令，放进一个 4 条深的环形队列。

为什么要有队列：IMEM 访问要 1-2 个周期，而执行可能很快。队列让 IFU 提前多取几条，避免 CPU 空转（解决"内存慢"和"执行快"的差距）。

IFU → IDU: idu_req_data_o = 原始指令(32位) │ idu_req_vd_o = 队列有货
IDU → IFU: idu2ifu_rdy_i = IDU 能接收（反压信号）
EXU → IFU: exu2ifu_pc_new_i = 新 PC │ exu2ifu_pc_new_req_i = 要换 PC

关键动作：预解码——IFU 看指令最低 2 位 instr[1:0] 判断这条是 16 位（RVC）还是 32 位（RVI），从而决定队列里占 1 格还是 2 格。

对应源码：src/core/pipeline/scr1_pipe_ifu.sv（队列逻辑在第 320-370 行）

信号很多，但你要记住的只有：idu_req_data_o（指令本身）+ exu2ifu_pc_new_i（下一条去哪）。其余全是辅助。

四、第二站：译码（IDU）

② 译码 IDU：搞懂这条指令要干什么

职责：把原始 32 位指令，翻译成一个 18 字段的命令结构体 type_scr1_exu_cmd_s，告诉下游 EXU"做什么、用哪个寄存器、立即数是多少"。

译码结果就是一条"给 EXU 的命令"。指令里的一切都被拆解：

指令 addi x5, x1, 10 ──译码──▶ idu2exu_cmd_o = {
  ialu_cmd = ADD（做什么运算）,
  rs1_addr = x1（第一个操作数寄存器号）,
  rs2_addr = 0（第二个是立即数）,
  rd_addr = x5（结果写哪）,
  imm = 10（立即数值）,
  rd_wb_sel = IALU（结果从哪来）}

还做一件事：检查这条指令是否合法（非法指令检测）。不认识的操作码 → 置 exc_req 异常标志。

对应源码：src/core/pipeline/scr1_pipe_idu.sv（核心译码在 140-400 行）

一句话记住：IDU 就是"翻译官"，把机器码翻译成硬件能直接执行的结构体命令。

五、第三站：执行（EXU）

③ 执行 EXU：真正干活的地方

职责：拿到 IDU 的命令结构体，读取寄存器值，做运算/跳转/访存/CSR 访问。

EXU 内部有 4 个执行通路，根据命令分派：

通路干什么例子
IALU 主通路整数加减、逻辑、移位、比较add / and / slli / slt
IALU 加法器 2PC+立即数（跳转地址）、LUI/AUIPCjal / auipc
LSU 通路内存读写（load/store）lw / sw
CSR 通路读写控制状态寄存器csrrw / mret
EXU → MPRF: exu2mprf_rs1_addr_o / rs2_addr_o = 要读哪些寄存器
MPRF → EXU: mprf2exu_rs1_data_i / rs2_data_i = 寄存器里的值
EXU 内部: IALU 运算 → 得到结果 ialu_main_res
EXU → MPRF: exu2mprf_w_req_o / rd_addr_o / rd_data_o = 把结果写回

还负责：分支判定（jb_taken）、计算新 PC、检测异常。指令在这里"退休"（退役，commit）。

对应源码：src/core/pipeline/scr1_pipe_exu.sv（EXU 状态机 + 4 通路选择）

一句话记住：EXU 是核心，所有"真正干活"都在这；它向外发出读寄存器、写寄存器、访存、访问 CSR 的请求。

六、第四站：访存与写回（LSU + MPRF）

④ 访存 / 写回：把结果存下来

MPRF：通用寄存器堆（x0-x31）

职责：存 32 个通用寄存器的值。EXU 需要时读出来，算完后写回去。

三个关键特性：

  • x0 硬连线为 0——写入忽略，读出恒为 0
  • 读是组合逻辑（发出地址立即得到值，0 延迟）
  • 写是时钟沿触发（同步写）
写回: exu2mprf_w_req_o = 要写 │ exu2mprf_rd_addr_o = 写 x几 │ exu2mprf_rd_data_o = 写什么值

LSU：访存单元（load/store）

职责：EXU 把访存命令交给它，它负责和内存（DMEM）打交道。load 读回数据、store 写出去。

LSU 是流水线里最"慢"的一环——内存访问要多个周期，所以它会给 EXU 发 rdy=0 反压，让前面的 IFU/IDU 都停下来等它。

EXU → LSU: exu2lsu_cmd_o = 访存命令（读/写/地址/数据）
LSU → EXU: lsu2exu_rdy_o = 忙不忙（反压）│ lsu2exu_data_o = load 读回的数据

对应源码：src/core/pipeline/scr1_pipe_mprf.sv、scr1_pipe_lsu.sv

七、第五站：控制（CSR）

⑤ 控制 CSR：例外与中断的枢纽

职责：管中断/异常。平时它只是"挂着的门卫"，一旦 EXU 报告异常或外设来中断，它就接管 CPU：

EXU → CSR: exu2csr_take_exc_o（有异常）│ exu2csr_take_irq_o（有中断）
CSR 自动: 保存 MEPC/MCAUSE/MTVAL → 关 MIE → 生成新 PC = MTVEC
CSR → EXU: csr2exu_new_pc_i（跳去陷阱处理程序）│ csr2exu_irq_o（有中断要响应）

和正常数据流的关系：CSR 平时不参与运算，只在异常/中断/MRET 时"插入"一条新 PC 给 IFU，改变程序流向。

对应源码：src/core/pipeline/scr1_pipe_csr.sv（陷阱流程 280-300 行，新 PC 生成 998 行）

八、完整例子：一条 ADD 指令的一生

把 5 站串起来，看一条指令 add x5, x1, x2（x5 = x1 + x2）在 SCR1 里如何走完全程：

周期发生的事经过的模块关键信号
T0IFU 按 PC 从 IMEM 取回 add 指令IFU→IMEMimem2ifu_instr_i
T0指令进入队列，IFU 通知 IDU"有货了"IFU→IDUidu_req_vd_o, idu_req_data_o
T1IDU 译码：这是 ADD，rs1=x1, rs2=x2, rd=x5IDUidu2exu_cmd_o（结构体）
T1EXU 读 x1、x2 的值EXU→MPRFexu2mprf_rs1_addr_o
T2IALU 做加法，得到 x1+x2EXU（IALU）ialu_main_res
T2把结果写回 x5；指令退休EXU→MPRFexu2mprf_w_req_o
T3PC 正常加 4，IFU 取下一条EXU→IFUexu2ifu_pc_new_i
注意流水线的"重叠"
上面是"一条指令"的视角。实际运行时 3 条指令重叠：T1 周期 add 在译码时，上一条可能在执行，下一条正在取指。流水线并行就是这个意思——虽然一条指令要 3-4 周期，但平均每个周期都能退休一条（理想情况）。

九、关键信号白名单（解决"信号太多"）

整个 SCR1 流水线有上千个信号，但作为学习者，你只需要盯住这 10 个。看到它们，就能看懂任何一条指令在模块间怎么流动：

#信号方向含义忘记就
1idu_req_data_oIFU→IDU原始指令（32 位机器码）指令从哪来
2idu_req_vd_o / idu2ifu_rdy_iIFU⇄IDU取指级握手：有货 / 就绪流水线推进
3idu2exu_cmd_oIDU→EXU18 字段命令结构体（含操作/寄存器/立即数）译码结果
4idu2exu_vd_o / exu2idu_rdy_iIDU⇄EXU译码级握手流水线推进
5exu2mprf_rs1_addr_o + mprf2exu_rs1_data_iEXU⇄MPRF读寄存器（地址→值）操作数从哪来
6exu2mprf_w_req_o + rd_addr_o + rd_data_oEXU→MPRF写寄存器（结果写回）结果去哪
7exu2ifu_pc_new_i + exu2ifu_pc_new_req_iEXU→IFU新 PC（跳转/异常/中断时）程序流向怎么变
8lsu2exu_rdy_oLSU→EXU访存忙（反压源头）为什么会停顿
9exu2csr_take_exc_o / exu2csr_take_irq_oEXU→CSR异常 / 中断请求出大事了
10csr2exu_new_pc_iCSR→EXU陷阱入口地址（MTVEC）处理程序入口
怎么用这张表
之后再看任何一周教程，遇到新信号先问自己："它属于这 10 个信号中的哪个环节？" 如果对不上，说明它是某个环节内部的辅助信号——先跳过。等你把主线吃透了，再看辅助信号就是水到渠成。

十、隐形主线：反压（Backpressure）

除了"指令向下流"这条明线，还有一条从后往前的暗线——反压。它回答"流水线为什么有时会停顿"。

规则很简单：任何一级没准备好，就通过 rdy 信号让前面一级停下来。

反压传播方向（从后往前） IFU ◄──────── IDU ◄──────── EXU ◄──────── LSU idu2ifu_rdy exu2idu_rdy lsu2exu_rdy （0=停） （0=停） （0=访存忙）

最典型的场景：EXU 执行 load 指令，LSU 去 DMEM 读数据需要好几个周期，期间 lsu2exu_rdy_o=0 → EXU 不能退休 → exu2idu_rdy_o=0 → IDU 停止译码 → idu2ifu_rdy_o=0 → IFU 停止取指。整条流水线为这一条 load 停下来等内存。

为什么理解反压很重要
反压是贯穿所有模块的"控制暗线"。当你看到教程里某模块有一堆 rdy 信号，别慌——它们全是这条暗线的节点，用途只有一句话：我忙，别给我塞活。
