第二课: IALU 主加法器 — 33 位加减器 + 4 个标志位

// scr1_pipe_ialu.sv:73-78
always_comb begin
    main_sum_res = (exu2ialu_cmd_i != SCR1_IALU_CMD_ADD)
                 ? ({1'b0, exu2ialu_main_op1_i} - {1'b0, exu2ialu_main_op2_i})
                 : ({1'b0, exu2ialu_main_op1_i} + {1'b0, exu2ialu_main_op2_i});

设计决策: 所有非 ADD 统一走减法
只有 ADD 是加法, SUB/SLT/分支比较等全部走减法。操作数扩展为 33 位 (高位补 0), 正确捕获进位/借位。

4 个标志位从 33 位结果中提取

标志表达式含义
c (进位/借位)main_sum_res[32]c=0 → 借位 (op1 < op2 无符号), c=1 → 无借位 (op1 >= op2)
z (零)~|main_sum_res[31:0]结果全零 → op1 == op2
s (符号)main_sum_res[31]结果的符号位
o (溢出)pos_ovflw | neg_ovflw有符号溢出

比较命令从标志位派生

命令指令判定解释
CMD_SUB_EQBEQz == 1结果为零 → 相等
CMD_SUB_NEBNEz == 0结果非零 → 不等
CMD_SUB_LTSLT, BLTs ^ o == 1有符号小于
CMD_SUB_LTUSLTU, BLTUc == 0借位 → 无符号小于
CMD_SUB_GEBGEs ^ o == 0不小于即大于等于
CMD_SUB_GEUBGEUc == 1无借位 → 无符号大于等于

第三课: 有符号比较 s ^ o — 为什么不是简单的 s?

无溢出 (o=0): 结果符号位直接反映大小关系

op1 < op2  →  op1 - op2 < 0  →  s = 1  ✓
op1 > op2  →  op1 - op2 > 0  →  s = 0  ✓

有溢出 (o=1): 结果符号和实际大小相反

// 例: op1 = 0x7FFFFFFF (+max), op2 = 0x80000000 (-max)
// 0x7FFFFFFF - 0x80000000 = 0xFFFFFFFF → 结果最高位 = 1, 但 op1 > op2
// 溢出因为: 正数 - 负数 = 正数 + |负数|, 可能超过 +2^31-1
s ^ o 的直觉
o=0 → 符号位直接有效 → s^0 = s
o=1 → 符号位反转 → s^1 = ~s (正好修正)
所以 s ^ o 在有符号减法中给出了正确的"小于"判定。 
// 正溢出: 两个非负数相加后结果为负
main_sum_pos_ovflw = ~op1[31] &  op2[31] &  main_sum_res[31];

// 负溢出: 两个负数相加后结果为正
main_sum_neg_ovflw =  op1[31] & ~op2[31] & ~main_sum_res[31];

第七课: 非恢复式除法器 — 32 周期产生商 + 余数

非恢复式 (Non-Restoring) 除法的核心思想
传统恢复式除法: 每拍尝试减法, 若不够减则恢复余数。非恢复式每拍只做加或减, 从不恢复——用上一次的商位决定下一次加减方向。省掉恢复余数的步骤。

算法伪代码

初始化: 余数 = 被除数, 商 = 0
for i = 0 to 31:
    余数左移 1 位
    if (上一次商位 == 1)  余数 = 余数 - 除数
    else                   余数 = 余数 + 除数
    商位 = ~(余数的符号)
    商 = (商 << 1) | 商位
// CORR 阶段 (有符号): 修正商符号, 修正余数
div_cmd指令符号
00DIV有符号
01DIVU无符号
10REM有符号
11REMU无符号
CORR 阶段: 有符号修正
非恢复式除法的迭代产生无符号商。有符号除法 (DIV/REM) 最后需要一个 CORR 周期: 若被除数与除数异号, 商取反; 若余数符号与预期不符, 余数修正为 除数 - 余数。

命令锁存器 (lsu_cmd_ff) 的必要性

// scr1_pipe_lsu.sv:193-200
lsu_cmd_upd = lsu_fsm_idle & dmem_req_vd;   // 只在进入 BUSY 时锁存

always_ff @(posedge clk, negedge rst_n) begin
    if (~rst_n)
        lsu_cmd_ff <= SCR1_LSU_CMD_NONE;
    else if (lsu_cmd_upd)
        lsu_cmd_ff <= exu2lsu_cmd_i;         // 锁存一整段 BUSY 期间不变
end
为什么需要锁存?
请求发出后 exu2lsu_cmd_i 仅 1 拍有效。DMEM 响应多拍后到达时, LSU 需要用 lsu_cmd_ff 知道当初发的是什么指令 — 用来做符号/零扩展, 以及区分 LD_ACCESS_FAULT 和 ST_ACCESS_FAULT。

第九课: 地址未对齐检测

// scr1_pipe_lsu.sv:224-225
dmem_addr_mslgn = exu2lsu_req_i & (
    (dmem_wdth_hword & exu2lsu_addr_i[0])          // 半字: addr[0]=1 → 未对齐
  | (dmem_wdth_word  & |exu2lsu_addr_i[1:0])     // 字: addr[1:0]≠0 → 未对齐
);
数据宽度对齐要求检测条件异常编码
BYTE (LB/LBU/SB)无不检测—
HWORD (LH/LHU/SH)2 字节addr[0] != 0LD/ST_ADDR_MISALIGN (4/6)
WORD (LW/SW)4 字节|addr[1:0] != 0LD/ST_ADDR_MISALIGN (4/6)
异常阻止 DMEM 请求
地址未对齐被检测后, lsu_exc_req=1 → dmem_req_vd=0 → LSU 不发 DMEM 请求。异常指令不触发实际的存储器访问, 直接报异常。

第十课: 加载数据符号/零扩展 — 使用锁存命令

// scr1_pipe_lsu.sv:317-326 -- 扩展逻辑基于 lsu_cmd_ff (锁存值)
always_comb begin
    case (lsu_cmd_ff)
        SCR1_LSU_CMD_LH :  ldata = {{16{dmem[15]}},  dmem[15:0]};  // 符号扩展
        SCR1_LSU_CMD_LHU:  ldata = { 16'b0,             dmem[15:0]};  // 零扩展
        SCR1_LSU_CMD_LB :  ldata = {{24{dmem[7]}},   dmem[7:0]};   // 符号扩展
        SCR1_LSU_CMD_LBU:  ldata = { 24'b0,             dmem[7:0]}};  // 零扩展
        default         :  ldata = dmem;                            // LW 直通
    endcase
end
为什么用 lsu_cmd_ff 而非 exu2lsu_cmd_i?
exu2lsu_cmd_i 只在请求发出的当拍有效, DMEM 响应几拍后到达。回来看 exu2lsu_cmd_i 已经变成下一条指令了。锁存值 lsu_cmd_ff 在整段 BUSY 期间保持原值。

第十一课: LSU 异常优先级仲裁

// scr1_pipe_lsu.sv:263-271 -- 4 级异常优先级
case (1'b1)
    // P1: DMEM 错误 (最高)
    dmem_resp_er     : exc_code = lsu_cmd_ff_store ? ST_ACCESS_FAULT : LD_ACCESS_FAULT;
    // P2: TDU 断点
    lsu_exc_hwbrk    : exc_code = BREAKPOINT;
    // P3: 加载未对齐
    dmem_addr_mslgn_l: exc_code = LD_ADDR_MISALIGN;
    // P4: 存储未对齐 (最低)
    dmem_addr_mslgn_s: exc_code = ST_ADDR_MISALIGN;
    default          : exc_code = INSTR_MISALIGN;  // 保护值
endcase
优先级设计动因
DMEM 错误 > 断点 > 加载未对齐 > 存储未对齐。数据已损坏时报 Access Fault 优先于一切。断点优先于未对齐: 调试器需要捕获断点事件。加载优先于存储: 防御性设计,同一拍不可能同时有 Load 和 Store。

第十三课: RAM 实现 — 双份副本 + 写优先旁路

两份独立 RAM 副本 rs1_addr ───────▶ mprf_int ──▶ rs1_data_ff ──┐ │ wr_data │ rd_addr ──┬──────▶ mprf_int2 ──▶ rs2_data_ff ─┤ │ │ │ 冲突检测 (组合逻辑) ├──▶ MUX 输出 │ new_data_req = rs_addr==rd │ │ rd_data_ff (旁路寄存器) │ │ │ └──────────────────────────────────────────────┘

为什么两份副本?

FPGA RAM 块只支持简单双端口 (1R1W)。要实现 2R1W, 用两份独立 RAM 分别服务 rs1/rs2 读端口。写操作同时写入两份。

写优先旁路的时序

T0: 读 rs1=x5, 同时写 x5=0xAA → 冲突检测 → rs1_new_data_req=1
    rd_data_ff ← 0xAA                    // 旁路寄存器锁存新数据
T1: rs1_new_data_req_ff=1 → 输出 MUX 选 rd_data_ff → 0xAA  ✓

// 关键代码
rs1_new_data_req = wr_req_vd & (exu2mprf_rs1_addr_i == exu2mprf_rd_addr_i);
mprf2exu_rs1_data_o = rs1_new_data_req_ff ? rd_data_ff
                     : rs1_addr_vd_ff     ? rs1_data_ff
                                          : '0;
同步读引入的 1 拍延迟
RAM 读需要 1 拍: T0 发地址, T1 得数据。控制信号 (addr_vd, new_data_req) 也同步延迟 1 拍对齐。这是为什么旁路没有在 T0 当拍生效——旁路也要等 1 拍,但它能拿到正确的新值 (0xAA) 而非旧值 (RAM 读出的旧 x5 值)。

第十四课: 分布逻辑实现 — 异步读,零延迟

// 异步组合读: 当拍即可得数据
mprf2exu_rs1_data_o = rs1_addr_vd ? mprf_int[rs1_addr] : '0;

// 同步写: 支持可选复位
always_ff @(posedge clk, negedge rst_n) begin
    if (~rst_n)
        mprf_int <= '{default: '0};      // 复位清零 (可选)
    else if (wr_req_vd)
        mprf_int[rd_addr] <= rd_data;
end
分布逻辑实现不需要旁路
异步读 + 同步写 = 同周期读写数据天然可见 (综合为 FF + MUX), 无需像 RAM 实现那样做冲突检测和延迟旁路。代价: 面积大, 功耗高 (LUT 实现寄存器 vs RAM 块)。
