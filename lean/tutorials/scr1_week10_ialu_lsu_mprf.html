第二课: IALU 主加法器 — 33 位加减器 + 4 个标志位

// scr1_pipe_ialu.sv:204-207
always_comb begin
    main_sum_res = (exu2ialu_cmd_i != SCR1_IALU_CMD_ADD)
                 ? ({1'b0, exu2ialu_main_op1_i} - {1'b0, exu2ialu_main_op2_i})
                 : ({1'b0, exu2ialu_main_op1_i} + {1'b0, exu2ialu_main_op2_i});
end
设计决策: 所有非 ADD 统一走减法
只有 ADD 是加法, SUB/SLT/分支比较等全部走减法。操作数扩展为 33 位 (高位补 0), 正确捕获进位/借位。

33 位加法器设计详解

为什么是 33 位而非 32 位? 32 位操作数做减法时, 最宽结果是 32 位 — 但我们需要第 33 位 (位 [32]) 来判断进位/借位。

31 位操作数 + 1 位扩展 = 33 位结果 ┌───────────────────────┐ │ 0 op1[31:0] │ 33-bit operand 1 │ 0 op2[31:0] │ 33-bit operand 2 │ ───────────────── │ │ C res[31:0] │ 33-bit result (C = carry/borrow) └───────────────────────┘
场景main_sum_res[32]含义
ADD: op1 + op21 → 进位产生超 32 位范围
SUB: op1 >= op2 (无符号)1 → 无借位结果为正或零
SUB: op1 < op2 (无符号)0 → 有借位结果为负 (模运算)
SystemVerilog 表达式宽度规则
{1'b0, exu2ialu_main_op1_i} 先做零扩展为 33 位, 再做减法。结果的位宽取两操作数中较宽的那个 — 即 33 位。因此 main_sum_res[32] 直接就是进位/借位输出。

4 个标志位生成 — 组合逻辑一网打尽

always_comb begin
    // 加法器结果
    main_sum_res = (exu2ialu_cmd_i != SCR1_IALU_CMD_ADD)
                 ? ({1'b0, op1} - {1'b0, op2})
                 : ({1'b0, op1} + {1'b0, op2});

    // 正溢出: 正+正=负  (op1 正, op2 负→减法是 op1-(-op2) 即正溢出)
    main_sum_pos_ovflw = ~op1[31] &  op2[31] &  main_sum_res[31];

    // 负溢出: 负+负=正  (op1 负, op2 正→减法是 op1-(+op2) 即负溢出)
    main_sum_neg_ovflw =  op1[31] & ~op2[31] & ~main_sum_res[31];

    // 4 标志位打包
    main_sum_flags.c = main_sum_res[32];              // 进位/借位
    main_sum_flags.z = ~|main_sum_res[31:0];          // 零标志: 低 32 位全 0 归约或非
    main_sum_flags.s = main_sum_res[31];                // 符号标志: 结果 bit 31
    main_sum_flags.o = main_sum_pos_ovflw | main_sum_neg_ovflw;  // 溢出标志
end
标志表达式含义用法
cmain_sum_res[32]进位/借位: c=0→借位 (op1<op2), c=1→无借位 (op1>=op2)SLTU, BLTU, BGEU
z~|main_sum_res[31:0]零: 所有位归约或非, 结果为 0 → z=1BEQ, BNE
smain_sum_res[31]符号: 减法结果的最高位, 无溢出时 s=1 → op1<op2参与 s ^ o
opos_ovflw | neg_ovflw溢出: 有符号减法结果超 [-2^31, 2^31-1] 范围参与 s ^ o

第三课: 有符号比较 s ^ o — 为什么不是简单的 s?

无溢出 (o=0): 结果符号位直接反映大小关系

op1 < op2  →  op1 - op2 < 0  →  s = 1  (正确)
op1 > op2  →  op1 - op2 > 0  →  s = 0  (正确)

有溢出 (o=1): 结果符号和实际大小相反

// 例: op1 = 0x7FFFFFFF (+2^31-1), op2 = 0x80000000 (-2^31)
// 0x7FFFFFFF - 0x80000000 = 0xFFFFFFFF → 结果最高位 = 1, 但 op1 > op2
// 溢出原因: 正数 - 负数 = 正数 + |负数|, 超过 +2^31-1

溢出检测: 看操作数符号

// 正溢出: (正数) - (负数) = 正数 + |负数|, 结果可能"变负"
//   op1 正 (bit31=0), op2 负 (bit31=1), 结果负 (bit31=1) → 溢出!
main_sum_pos_ovflw = ~op1[31] &  op2[31] &  main_sum_res[31];

// 负溢出: (负数) - (正数) = 负数 - 正数, 结果可能"变正"
//   op1 负 (bit31=1), op2 正 (bit31=0), 结果正 (bit31=0) → 溢出!
main_sum_neg_ovflw =  op1[31] & ~op2[31] & ~main_sum_res[31];
场景op1[31]op2[31]结果[31]o实际比较ss ^ o正确?
5 - 3 = 200005 > 300 ^ 0 = 0正确 (不小于)
3 - 5 = -200103 < 511 ^ 0 = 1正确 (小于)
-5 - 3 = -81010-5 < 311 ^ 0 = 1正确 (小于)
+max - (-max)0111+max > -max11 ^ 1 = 0正确 (不小于)
-max - (+max)1001-max < +max00 ^ 1 = 1正确 (小于)
s ^ o 的直觉
o=0 → 符号位直接有效 → s^0 = s
o=1 → 符号位翻转 → s^1 = ~s (正好修正溢出带来的符号翻转)
s ^ o 在有符号减法中给出正确的"小于"判定。

第六课: 乘法器 — 两种实现对比

乘法子命令编码

// scr1_pipe_ialu.sv:397-402 — mul_cmd 编码推导
mul_cmd  = {((cmd == MULHU) | (cmd == MULHSU)),     // bit[1]: 纯无符号? 取高位
            ((cmd == MULHU) | (cmd == MULH))};       // bit[0]: op2 无符号? MULHSU/MULHU
mul_cmd_hi     = |mul_cmd;                           // 任意位置1 → 取高 32 位
mul_op1_is_sgn = ~&mul_cmd;                          // MULHU 时 = 0 → op1 无符号
mul_op2_is_sgn = ~mul_cmd[1];                        // MULHU/MULHSU 时 = 0 → op2 无符号

FAST_MUL 单周期快速乘法器详解

// scr1_pipe_ialu.sv:407-409 — 33 位符号扩展, 33×33 → 64 位
mul_op1 = mdu_cmd_mul ? $signed({mul_op1_sgn, op1}) : '0;
mul_op2 = mdu_cmd_mul ? $signed({mul_op2_sgn, op2}) : '0;
mul_res = mdu_cmd_mul ? mul_op1 * mul_op2           : $signed('0);
ialu2exu_main_res_o = mul_cmd_hi ? mul_res[63:32] : mul_res[31:0];
FAST_MUL 的关键设计
33 位符号扩展: {mul_op1_sgn, op1} 把 32 位操作数扩展为 33 位, 最高位是符号标志。
33×33 → 64 位: SystemVerilog * 运算符自动产生宽结果, 组合乘法器在一个周期完成。
符号处理: 无符号乘法时 mul_op1_sgn = 0, 带符号扩展位 {0, op1} 即为零扩展。有符号时 {sign, op1} 即为符号扩展。
取高/低 32 位: mul_cmd_hi 标志控制 MUX 选 mul_res[63:32] 或 mul_res[31:0]。
指令op1 扩展op2 扩展结果宽度输出
MUL{0, op1} 无符号{0, op2} 无符号33×33→64低 32 位
MULH{sgn, op1} 有符号{sgn, op2} 有符号33×33→64高 32 位
MULHSU{sgn, op1} 有符号{0, op2} 无符号33×33→64高 32 位
MULHU{0, op1} 无符号{0, op2} 无符号33×33→64高 32 位
FAST_MUL 的面积代价
FAST_MUL 用 * 运算符综合为组合乘法器, 面积远大于迭代方案。FPGA 上的 DSP48/DSP 块可以吸收, 但 ASIC 可能面积过大。SCR1 默认不启用 FAST_MUL, 走 Radix-2 迭代路径。

Radix-2 迭代乘法器 — 状态机详解 + 实例

MDU 三状态 FSM

Radix-2 核心: 每拍处理 1 位乘数

// Radix-2 算法的硬件结构

// 初始化 (mdu_fsm_idle + mdu_cmd_mul):

mdu_iter_cnt 初始值为 32'b1 << 30 (bit[30]=1)。每拍右移 1 位。当 mdu_iter_cnt[0] = 1 时, mdu_iter_rdy = 1 → 32 次迭代完成。

第七课: 非恢复式除法器 — 32 周期产生商 + 余数

非恢复式 (Non-Restoring) 除法的核心思想
恢复式: 每拍试减, 若不够减则恢复余数再移位。非恢复式: 每拍只做加或减, 从不恢复 — 用上一次商位决定下一次加减方向。省掉恢复步骤, 33 拍完成 (32 迭代 + 1 CORR)。

算法伪代码

初始化: 余数 = 被除数, 商 = 0, dividend_lo = 被除数 << 1
for i = 0 to 31:
    余数左移 1 位 (串联 dividend_lo 的最高位)
    dividend_lo 左移 1 位
    if (上一次商位 == 1)  余数 = 余数 - 除数
    else                   余数 = 余数 + 除数
    商位 = ~(余数的符号位 ^ 被除数符号)     // 无符号: ~余数符号
    商 = (商 << 1) | 商位

// CORR 阶段 (有符号除法)
if (被除数与除数异号) 商取反
if (余数需要修正)    余数 = 除数 - 余数

硬件结构: 3 个寄存器 + 1 个加法器

CORR 阶段: 有符号修正
非恢复式除法的迭代产生无符号商。有符号除法 (DIV/REM) 最后需要一个 CORR 周期: 若被除数与除数异号, 商取反; 若余数符号与预期不符, 余数修正为 除数 - 余数。

lsu2dmem_req_oexu2lsu_req_i & ~lsu_exc_req & lsu_fsm_idle向 DMEM 发请求: EXU 请求 + 无异常 + FSM 空闲
关键约束: 同一时刻最多 1 个事务
lsu2dmem_req_o = exu2lsu_req_i & ~lsu_exc_req & lsu_fsm_idle
只有在 IDLE 态才能发请求, 进入 BUSY 后即使 EXU 来新请求也不发 DMEM 请求。这保证流水线中 LSU 串行化: 前一个 LD/ST 完成前, 后续 LD/ST 等待。

命令锁存器 (lsu_cmd_ff) 的完整机制

// scr1_pipe_lsu.sv:140-148 — 锁存器更新逻辑
lsu_cmd_upd = lsu_fsm_idle & dmem_req_vd;   // 只在进入 BUSY 当拍锁存

always_ff @(posedge clk, negedge rst_n) begin
    if (~rst_n)
        lsu_cmd_ff <= SCR1_LSU_CMD_NONE;
    else if (lsu_cmd_upd)
        lsu_cmd_ff <= exu2lsu_cmd_i;         // 锁存一整段 BUSY 期间不变
end
为什么需要锁存?
请求发出后 exu2lsu_cmd_i 仅 1 拍有效。DMEM 响应多拍后到达时, LSU 需要用 lsu_cmd_ff 知道当初发的是什么指令 — 用来做符号/零扩展, 以及区分 LD_ACCESS_FAULT 和 ST_ACCESS_FAULT。
波形示意 (假设 DMEM 延迟 2 拍): T0 T1 T2 T3 clk ┌─┐ ┌─┐ ┌─┐ ┌─┐ exu_req ──┐ └───────┘ ┌── (下一条指令) exu_cmd ==LH=====??=============LB== <-- T2 时已变! dmem_ack ──┐ └── fsm ==BUSY==================IDLE== cmd_upd ──┐ └── lsu_cmd_ff==LH======================== <-- BUSY 期间锁定! dmem_rsp ──────────────────┐ └── (T2 响应到达) ldata 扩展逻辑用 lsu_cmd_ff=LH, 而非 exu2lsu_cmd_i=LB → 正确!

第九课: 地址未对齐检测 — 位级逻辑

// scr1_pipe_lsu.sv:206-209 — 逐位检测
dmem_addr_mslgn   = exu2lsu_req_i & (
    (dmem_wdth_hword & exu2lsu_addr_i[0])          // 半字: addr[0]=1 → 未对齐
  | (dmem_wdth_word  & |exu2lsu_addr_i[1:0])     // 字: addr[1:0]≠0 → 未对齐
);
dmem_addr_mslgn_l = dmem_addr_mslgn & dmem_cmd_load;    // 加载未对齐
dmem_addr_mslgn_s = dmem_addr_mslgn & dmem_cmd_store;   // 存储未对齐

位级逻辑分解

宽度标志条件检测表达式位级展开
dmem_wdth_byteLB/LBU/SB不检测—
dmem_wdth_hwordLH/LHU/SHexu2lsu_addr_i[0]最低位 = 1 → 不是 2 的倍数 → 未对齐
dmem_wdth_wordLW/SW|exu2lsu_addr_i[1:0]低 2 位任何一位 = 1 → 不是 4 的倍数 → 未对齐
|exu2lsu_addr_i[1:0] 的含义
| 是一元归约或: 等价于 addr[1] | addr[0]。为 1 表示低 2 位不全为零。
Word 对齐要求 addr[1:0] == 2'b00, 即地址是 4 的倍数。
Halfword 对齐要求 addr[0] == 1'b0, 即地址是 2 的倍数。

异常阻止 DMEM 请求的链式逻辑

// 未对齐检测 → lsu_exc_req 拉高
lsu_exc_req = dmem_addr_mslgn_l | dmem_addr_mslgn_s | lsu_exc_hwbrk;

// lsu_exc_req=1 → dmem_req_vd=0
dmem_req_vd = exu2lsu_req_i & dmem2lsu_req_ack_i & ~lsu_exc_req;

// dmem_req_vd=0 → lsu2dmem_req_o=0 (不发请求)
lsu2dmem_req_o = exu2lsu_req_i & ~lsu_exc_req & lsu_fsm_idle;

// 同时 lsu2exu_exc_o=1 (直接报异常, 不访问存储器)
lsu2exu_exc_o = dmem_resp_er | lsu_exc_req;
异常阻止 DMEM 请求
地址未对齐被检测后, lsu_exc_req=1 → dmem_req_vd=0 → LSU 不发 DMEM 请求。异常指令不触发实际的存储器访问, 直接报异常。这避免了向 DMEM 发起非法地址的访问。

第十课: 加载数据符号/零扩展 — Combinational Case Statement

// scr1_pipe_lsu.sv:240-248 — 基于 lsu_cmd_ff 的纯组合扩展
always_comb begin
    case (lsu_cmd_ff)
        SCR1_LSU_CMD_LH :  lsu2exu_ldata_o = {{16{dmem2lsu_rdata_i[15]}},  dmem2lsu_rdata_i[15:0]};
        SCR1_LSU_CMD_LHU:  lsu2exu_ldata_o = { 16'b0,                            dmem2lsu_rdata_i[15:0]};
        SCR1_LSU_CMD_LB :  lsu2exu_ldata_o = {{24{dmem2lsu_rdata_i[7]}},   dmem2lsu_rdata_i[7:0]};
        SCR1_LSU_CMD_LBU:  lsu2exu_ldata_o = { 24'b0,                            dmem2lsu_rdata_i[7:0]}};
        default         :  lsu2exu_ldata_o = dmem2lsu_rdata_i;   // LW (WORD) 或 NONE 直通
    endcase
end
命令读 DMEM 宽度扩展方式复制位目标 32 位组合
LB1 字节符号扩展dmem[7]{24{dmem[7]}, dmem[7:0]}
LBU1 字节零扩展0{24'b0, dmem[7:0]}
LH2 字节符号扩展dmem[15]{16{dmem[15]}, dmem[15:0]}
LHU2 字节零扩展0{16'b0, dmem[15:0]}
LW4 字节无需扩展—dmem[31:0] 直通
为什么用 lsu_cmd_ff 而非 exu2lsu_cmd_i?
exu2lsu_cmd_i 只在请求发出的当拍有效, DMEM 响应几拍后到达。回来看 exu2lsu_cmd_i 已经变成下一条指令了。锁存值 lsu_cmd_ff 在整段 BUSY 期间保持原值。

扩展逻辑是 always_comb, 纯组合, 无寄存器。当 DMEM 响应到达时, lsu_cmd_ff 仍为原来的命令, dmem2lsu_rdata_i 为有效数据 → 同一拍输出正确的扩展结果。

第十一课: LSU 异常优先级仲裁

// scr1_pipe_lsu.sv:212-224 — 4 级异常优先级
case (1'b1)
    // P1: DMEM 错误 (最高) — 数据已损坏
    dmem_resp_er     : exc_code = lsu_cmd_ff_load  ? LD_ACCESS_FAULT
                                : lsu_cmd_ff_store ? ST_ACCESS_FAULT
                                                   : INSTR_MISALIGN;
    // P2: TDU 断点 — 调试器需要捕获
    lsu_exc_hwbrk    : exc_code = BREAKPOINT;
    // P3: 加载未对齐
    dmem_addr_mslgn_l: exc_code = LD_ADDR_MISALIGN;
    // P4: 存储未对齐 (最低)
    dmem_addr_mslgn_s: exc_code = ST_ADDR_MISALIGN;
    default          : exc_code = INSTR_MISALIGN;  // 保护值
endcase
优先级设计动因
DMEM 错误 > 断点 > 加载未对齐 > 存储未对齐。数据已损坏时 Access Fault 优先于一切。断点优先于未对齐: 调试器需要捕获断点事件。加载优先于存储: 防御性设计, 同一拍不可能同时有 Load 和 Store。

第十二课: MPRF — x0 寄存器的硬连线为零

// 阵列从索引 1 开始, x0 没有物理存储
localparam SCR1_MPRF_SIZE = 32;     // RV32I: 32 个逻辑寄存器
// 实际存储: mprf_int[1:31] — 31 个物理寄存器

读 x0: 地址 = 0 → 数据 = 0

// 地址有效性判定: 全位或 = 0 → x0
rs1_addr_vd = |exu2mprf_rs1_addr_i;    // addr==5'b0 → vd=0 → 输出 0

// 输出 MUX (分布逻辑)
mprf2exu_rs1_data_o = rs1_addr_vd ? mprf_int[rs1_addr] : '0;

// 输出 MUX (RAM 实现 — 加旁路)
mprf2exu_rs1_data_o = rs1_new_data_req_ff ? rd_data_ff
                    : rs1_addr_vd_ff       ? rs1_data_ff
                                           : '0;

写 x0: 被抑制

wr_req_vd = exu2mprf_w_req_i & |exu2mprf_rd_addr_i;  // rd=x0 → wr_req_vd=0

always_ff @(posedge clk) begin
    if (wr_req_vd)  // x0 写请求永远不进入此 if
        mprf_int[rd_addr] <= rd_data;
end
x0 双路径保证
读路径: rs1_addr_vd = |addr_i, 地址全零 → vd=0 → MUX 选 0。
写路径: wr_req_vd = w_req_i & |rd_addr_i, rd=x0 → vd=0 → 不写。
两条独立的路径保证 x0 永远为 0, 即使在同一个周期内对 x0 发读写。

第十三课: RAM 实现 — 双份副本 + 写优先旁路

两份独立 RAM 副本 (2R1W → 1R1W × 2) rs1_addr ───────▶ mprf_int ──▶ rs1_data_ff ──┐ │ wr_data │ rd_addr ──┬─────▶ mprf_int2 ──▶ rs2_data_ff ──┤ │ │ │ 冲突检测 (组合逻辑) ├──▶ MUX 输出 │ rs1_new_data_req = rs1_addr==rd │ │ rd_data_ff (旁路寄存器) │ │ │ └──────────────────────────────────────────────┘

为什么两份副本?

FPGA RAM 块只支持简单双端口 (1R1W)。要实现 2R1W (两读一写), 用两份独立 RAM 分别服务 rs1/rs2 读端口。写操作同时写入两份:

always_ff @(posedge clk) begin
    if (wr_req_vd) begin
        mprf_int[exu2mprf_rd_addr_i]  <= exu2mprf_rd_data_i;   // 写入副本 1
        mprf_int2[exu2mprf_rd_addr_i] <= exu2mprf_rd_data_i;   // 写入副本 2
    end
end
同步读引入的 1 拍延迟
RAM 读需要 1 拍: T0 发地址, T1 得数据。控制信号 (addr_vd, new_data_req) 也同步延迟 1 拍对齐。这是为什么旁路没有在 T0 当拍生效 — 旁路也要等 1 拍, 但它能拿到正确的新值 (0xAA) 而非旧值 (RAM 读出的旧 x5 值)。

写优先旁路 (Write-First Bypass) 的完整时序

// scr1_pipe_mprf.sv:78-112 — 旁路逻辑

// 组合检测: 同周期读写相同寄存器?
rs1_new_data_req = wr_req_vd & (exu2mprf_rs1_addr_i == exu2mprf_rd_addr_i);
rs2_new_data_req = wr_req_vd & (exu2mprf_rs2_addr_i == exu2mprf_rd_addr_i);
read_new_data_req = rs1_new_data_req | rs2_new_data_req;

// 打拍对齐 RAM 读延迟
always_ff @(posedge clk) begin
    rs1_addr_vd_ff      <= rs1_addr_vd;
    rs2_addr_vd_ff      <= rs2_addr_vd;
    rs1_new_data_req_ff <= rs1_new_data_req;
    rs2_new_data_req_ff <= rs2_new_data_req;
end

// 旁路寄存器: 锁存新写数据
always_ff @(posedge clk) begin
    if (read_new_data_req)
        rd_data_ff <= exu2mprf_rd_data_i;
end

// 输出 MUX: 旁路优先 → RAM 读 → 零 (x0)
mprf2exu_rs1_data_o = rs1_new_data_req_ff ? rd_data_ff
                    : rs1_addr_vd_ff       ? rs1_data_ff
                                           : '0;

时序实例: 同周期读写冲突

拍rs1_addrrd_addrwr_reqwr_datanew_reqnew_req_ffrd_data_ffRAM 读 rs1最终输出
T0x5x510xAA10 (旧)旧值——
T1x6x610xBB110xAA旧 x5 值0xAA (旁路!)
T2x7—0—010xBBx6 新值 0xBB0xBB (旁路!)
旁路为什么是 1 拍而非 0 拍?
RAM 同步读本身有 1 拍延迟: T0 发地址 → T1 获得 RAM 数据。写操作 T0 写入 RAM, 写入的 0xAA 在 T1 才可在读端口看到 (写优先模式下)。
但 rd_data_ff 在 T0 锁存 0xAA, T1 输出。RAM 读出的仍是旧值 (如果写入与读取地址相同)。MUX 选 rd_data_ff 的 0xAA → 正确的新值。
如果不用 rd_data_ff 旁路, T1 输出的是 RAM 读出的旧值 → 读后写 (RAW) 冒险!

旁路优先级的 MUX 树

mprf2exu_rs1_data_o:
  ├── rs1_new_data_req_ff=1 → rd_data_ff         (旁路, 优先级最高)
  ├── rs1_new_data_req_ff=0, rs1_addr_vd_ff=1 → rs1_data_ff (正常 RAM 读)
  └── rs1_new_data_req_ff=0, rs1_addr_vd_ff=0 → 0          (x0)

第十四课: 分布逻辑实现 — 异步读, 零延迟

// 异步组合读: 当拍即可得数据
mprf2exu_rs1_data_o = rs1_addr_vd ? mprf_int[rs1_addr] : '0;

// 同步写: 支持可选复位
always_ff @(posedge clk, negedge rst_n) begin
    if (~rst_n)
        mprf_int <= '{default: '0};      // 复位清零 (可选)
    else if (wr_req_vd)
        mprf_int[rd_addr] <= rd_data;
end
分布逻辑实现不需要旁路
异步读 + 同步写 = 同周期读写数据天然可见 (综合为 FF + MUX), 无需像 RAM 实现那样做冲突检测和延迟旁路。代价: 面积大, 功耗高 (LUT 实现寄存器 vs RAM 块)。

时序对比

RAM 实现时序:
  T0: rs1_addr→RAM 地址端口    (输入)
  T1: RAM 数据输出→rs1_data_ff (读回)
  T2: MUX→mprf2exu_rs1_data_o  (输出)
  → 2 拍从地址到数据

分布逻辑时序:
  T0: rs1_addr→MUX→mprf_int[addr] (组合读)
  T0: →mprf2exu_rs1_data_o        (当拍输出)
  → 0 拍从地址到数据
RAM 实现的 EXU 约束
1 拍读延迟意味着 EXU 必须在 EXE 阶段之前的一拍发出读地址。SCR1 通过 ~NO_EXE_STAGE 约束实现: 即 ID 阶段发出地址, EXE 阶段获得数据。分布逻辑无此约束。
