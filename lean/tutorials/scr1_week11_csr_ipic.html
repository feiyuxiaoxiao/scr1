第三课: CSR 12-bit 地址编码全解析 新增

RISC-V 的 CSR 地址空间为 12-bit (SCR1_CSR_ADDR_WIDTH = 12)。12-bit 地址编码由 RISC-V 特权规范定义, 高 4-bit [11:8] 确定功能大类, 低 8-bit [7:0] 确定大类内的具体寄存器。

第五课: MSCRATCH — 异常处理器的上下文交换 新增

MSCRATCH (0x340) 的设计意图

MSCRATCH 是一个 32-bit 读写寄存器, 用于存放指向 per-hart 上下文保存区的指针。陷阱处理程序用它做 原子 sp 交换, 一步完成"保存旧 sp + 获取上下文指针"。

标准陷阱入口序列 (csrrw 原子交换)

// === 陷阱入口: 用 csrrw 原子交换 sp 和 mscratch ===
// 执行前: sp = 用户栈指针, mscratch = &trap_frame
csrrw sp, mscratch, sp
// 执行后: sp = &trap_frame, mscratch = 用户栈指针 (保存完成)

// === 保存上下文到 trap_frame ===
sw   ra,  0(sp)                    // x1
sw   gp,  4(sp)                    // x3
sw   tp,  8(sp)                    // x4
sw   t0, 12(sp)                    // x5
sw   t1, 16(sp)                    // x6
sw   t2, 20(sp)                    // x7
// ... 保存 a0-a7, s0-s11 等

// === 陷阱退出: 恢复上下文 ===
lw   t2, 20(sp)
lw   t1, 16(sp)
lw   t0, 12(sp)
lw   tp,  8(sp)
lw   gp,  4(sp)
lw   ra,  0(sp)
csrrw sp, mscratch, sp            // 恢复 sp, mscratch 回到初始值
mret

MSCRATCH 硬件实现

// scr1_pipe_csr.sv:755-761 — 简单 RW FF, 无事件触发
always_ff @(negedge rst_n, posedge clk) begin
    if (~rst_n) begin
        csr_mscratch_ff <= '0;
    end else if (csr_mscratch_upd) begin
        csr_mscratch_ff <= csr_w_data;
    end
end
csrrw 的原子性: 为什么不用两条指令?
csrrw sp, mscratch, sp 在单周期内完成: 读 mscratch → 写到 sp, 同时把旧 sp 写入 mscratch。如果拆成 csrr + csrw 两条指令, 中间可能被中断打断, 导致上下文丢失。csrrw 利用 CSR RMW 接口的原子性保证安全。

WFI (Wait For Interrupt) 唤醒路径

虽然 SCR1 的 CSR 模块不直接处理 WFI 指令 (由流水线控制逻辑执行), 但 CSR 提供了唤醒所需的所有信号。WFI 的硬件唤醒条件:

// WFI 唤醒条件 = 任意中断挂起且局部使能
// 注意: WFI 不要求 MSTATUS.MIE=1 ! 即便全局关中断, WFI 也会唤醒
wake_up = csr2exu_ip_ie_o       // 只要有 pending&enabled 就唤醒
        | csr_eirq_pnd_en
        | csr_sirq_pnd_en
        | csr_tirq_pnd_en;

// WFI 唤醒后的行为:
//   1. MIE=1 → 直接跳到陷阱处理 (csr2exu_irq_o=1)
//   2. MIE=0 → 继续执行 WFI 后面的指令 (无陷阱)

MIP 组合直通 vs MIE 寄存器

特性MIP (Machine Interrupt Pending)MIE (Machine Interrupt Enable)
存储方式纯组合逻辑 (assign)时序 FF (always_ff)
来源soc2csr_irq_{ext,soft,mtimer}_iCSR 写命令 (WRITE/SET/CLEAR)
写入行为静默忽略 (case 中无 csr_mip_upd)取 csr_w_data 对应位
读取返回 SOC 输入实时值返回 FF 值

为什么 MIP 不用 FF?
MIP 反映的是外部中断线的实时状态。如果用 FF 寄存一拍, 会引入额外延迟, 且外部中断可能在 FF 采样前后变化造成亚稳态 — 但这其实不是问题, 因为 IPIC 内部已有专门同步器处理。CSR 选择组合直通是为了降低中断响应延迟。

位名称含义复位

第十二课: 性能计数器扩展 — mhpmcounter3/HPM 机制 新增

SCR1 的 HPM 计数器架构

第十四课: CSR 原子读-改-写 — CSRRW/CSRRS/CSRRC 新增

三条 CSR 指令的硬件实现

RISC-V 定义了三条 CSR 原子操作指令, 在 SCR1 中通过 type_scr1_csr_cmd_sel_e 枚举和 csr_w_data 组合逻辑实现:

指令命令枚举csr_w_data 公式语义
CSRRWSCR1_CSR_CMD_WRITEexu2csr_w_data_i写 rs1 到 CSR, 旧值返回 rd
CSRRSSCR1_CSR_CMD_SETexu2csr_w_data_i | csr_r_dataCSR 中 rs1 置位的位置 1, 旧值返回 rd
CSRRCSCR1_CSR_CMD_CLEAR~exu2csr_w_data_i & csr_r_dataCSR 中 rs1 置位的位置 0, 旧值返回 rd

硬件实现: 3 路 MUX (纯组合)

// scr1_pipe_csr.sv:474-481 — CSR 写数据的原子 RMW 逻辑
always_comb begin
    case (exu2csr_w_cmd_i)
        SCR1_CSR_CMD_WRITE  : csr_w_data =  exu2csr_w_data_i;              // CSRRW: 直接替换
        SCR1_CSR_CMD_SET    : csr_w_data =  exu2csr_w_data_i | csr_r_data;  // CSRRS: 按位 OR
        SCR1_CSR_CMD_CLEAR  : csr_w_data = ~exu2csr_w_data_i & csr_r_data;  // CSRRC: 按位清除
        default             : csr_w_data = '0;
    endcase
end

为什么这是"原子"的?

CSRRW/CSRRS/CSRRC 在整个流水线中作为单条指令执行: IDU 解码 → EXU 发 CSR 读请求 → 同周期 (或下一拍) CSR 返回旧值到 rd, 同时按 cmd 计算新值写入 CSR。整个过程不可拆分, 中间不会被中断打断 (中断只在指令边界响应)。

实际使用示例

# 使能外部中断 (MEIE=bit11), 不影响其他位
li   t0, 0x800          # bit[11]=1
csrrs zero, mie, t0    # MIE |= 0x800, 旧值丢弃 (rd=zero)

# 禁用定时器中断 (MTIE=bit7), 不影响其他位
li   t0, 0x80           # bit[7]=1
csrrc zero, mie, t0    # MIE &= ~0x80

# 保存旧 MSTATUS 并写入新值 (如初始化 SCR1 中断)
li   t0, 0x8            # MIE=1, MPIE=0
csrrw t1, mstatus, t0  # t1=旧mstatus, mstatus=0x8

# 读 MIE 当前值, 不修改
csrr  t0, mie           # 伪指令 → csrrs t0, mie, zero
CSRRS/CSRRC 与 rs1=x0 的特例
当 rs1=x0 (zero) 时: CSRRS 不修改 CSR (OR with 0), CSRRC 不修改 CSR (AND NOT 0)。这两条伪指令即为 csrr (CSR Read) — 只读不写。

第十五课: 新 PC 生成 — Direct vs Vectored

// 异常: 一律跳 BASE
new_pc = {csr_mtvec_base, 6'b0};

// 中断 (Direct): 跳 BASE
new_pc = {csr_mtvec_base, 6'b0};

// 中断 (Vectored): 跳 BASE + 4×mcause.EC[3:0]
new_pc = {csr_mtvec_base[31:8], (4 * csr_mcause_ec_new[3:0])};

// MRET: 跳 MEPC
new_pc = {csr_mepc, {SCR1_CSR_MEPC_W{1'b0}}};  // 低位补 0
Vectored 模式的有效性
向量模式仅对中断有效 (I=1),异常仍然跳 Direct 地址。这是 RISC-V 规范定义的: 向量模式将 4 * mcause.EC 加到 BASE 上, 自然区分了异常和中断。

search_one_16 是纯 function automatic 组合逻辑, 单周期完成 16 路优先级搜索。高优先级 = 低索引号 (中断 0 优先于中断 15)。

第十九课: search_one_16 完整门级逻辑展开 新增

基础单元: search_one_2 的门级实现

// scr1_ipic.sv:89-98 — 2 选 1 优先级编码器
function automatic type_scr1_search_one_2_s scr1_search_one_2(input logic [1:0] din);
    tmp.vd  = |din;          // vd = din[1] | din[0]          (1 级 OR)
    tmp.idx = ~din[0];       // idx = ~din[0] = !din[0]      (1 级 NOT)
    return tmp;                // 若 din[0]=1 → idx=0; 若 din[0]=0 → idx=1
endfunction

// 真值表:
// din[1:0] | tmp.vd | tmp.idx | 选中
//    00    |   0    |   1     | 无效
//    01    |   1    |   0     | din[0]=1 → idx=0 (优先)
//    10    |   1    |   1     | din[1]=1 → idx=1
//    11    |   1    |   0     | din[0]=1 → idx=0 (优先)

Stage 1 (16→8): 8 个并行 search_one_2

// for (i=0; i<8; ++i) — 生成 8 组门级逻辑
// din_pair_i = din[(i+1)*2-1 : i*2]  = din[2i+1 : 2i]

// i=0: din[1:0]  → s1_vd[0] = din[1]|din[0],  s1_idx[0] = ~din[0]
// i=1: din[3:2]  → s1_vd[1] = din[3]|din[2],  s1_idx[1] = ~din[2]
// i=2: din[5:4]  → s1_vd[2] = din[5]|din[4],  s1_idx[2] = ~din[4]
// i=3: din[7:6]  → s1_vd[3] = din[7]|din[6],  s1_idx[3] = ~din[6]
// i=4: din[9:8]  → s1_vd[4] = din[9]|din[8],  s1_idx[4] = ~din[8]
// i=5: din[11:10]→ s1_vd[5] = din[11]|din[10], s1_idx[5] = ~din[10]
// i=6: din[13:12]→ s1_vd[6] = din[13]|din[12], s1_idx[6] = ~din[12]
// i=7: din[15:14]→ s1_vd[7] = din[15]|din[14], s1_idx[7] = ~din[14]

// 门数: 8 个 OR2 + 8 个 NOT = 16 gates

Stage 2 (8→4): 4 个 search_one_2 + 索引拼接

// for (i=0; i<4; ++i) — 在 s1_vd 上搜索, 拼接子索引

// i=0: pair = s1_vd[1:0]
//   tmp.vd  = s1_vd[1] | s1_vd[0]
//   tmp.idx = ~s1_vd[0]
//   s2_idx[0] = (tmp.idx==0) ? {0, s1_idx[0]} : {1, s1_idx[1]}
//              = ~tmp.idx ? {tmp.idx, s1_idx[2i]} : {tmp.idx, s1_idx[2i+1]}

// 展开 i=0:
//   s2_vd[0]  = s1_vd[1] | s1_vd[0]
//   s2_idx[0] = s1_vd[0] ? {1'b0, s1_idx[0]} : {1'b1, s1_idx[1]}
//   (若低对 s1_vd[0]=1 → 选低对索引, 否则选高对索引)

// i=1: s2_vd[1] = s1_vd[3]|s1_vd[2],  s2_idx[1] = s1_vd[2]?{0,s1_idx[2]}:{1,s1_idx[3]}
// i=2: s2_vd[2] = s1_vd[5]|s1_vd[4],  s2_idx[2] = s1_vd[4]?{0,s1_idx[4]}:{1,s1_idx[5]}
// i=3: s2_vd[3] = s1_vd[7]|s1_vd[6],  s2_idx[3] = s1_vd[6]?{0,s1_idx[6]}:{1,s1_idx[7]}

// 门数: 4×(OR2 + MUX2) = 4×(1+3) ≈ 16 gates

Stage 3 (4→2): 2 个 search_one_2 + 索引拼接

// for (i=0; i<2; ++i) — 在 s2_vd 上搜索

// i=0: s3_vd[0] = s2_vd[1]|s2_vd[0]
//   s3_idx[0] = s2_vd[0] ? {1'b0, s2_idx[0]} : {1'b1, s2_idx[1]}

// i=1: s3_vd[1] = s2_vd[3]|s2_vd[2]
//   s3_idx[1] = s2_vd[2] ? {1'b0, s2_idx[2]} : {1'b1, s2_idx[3]}

search_one_16 的关键特性
  1. 纯组合: function automatic, 无 clk/rst, 单周期完成
  2. 低索引优先: din[0] 优先级最高, din[15] 最低
  3. O(log N) 深度: 16 路仅需 4 级逻辑深度 (~44 gates)
  4. 可扩展: 同模式可扩展到 32/64/128 路

第二十课: CSR-IPIC 中断处理完整流程 + 信号时序

7 步中断处理流程

1 IRQ 到来: soc_irq_lines 进入 IPIC → 同步/反相 → 边沿/电平检测 → IPR 更新
2 优先级仲裁: IPR & IER & ~ISVR → 优先级树搜索 → 选出最高优先级中断号
3 中断请求: IPIC → ipic2csr_irq_m_req_o=1 → CSR 的 MIP 线
4 CSR 仲裁: CSR 生成 csr2exu_ip_ie_o + csr2exu_irq_o → EXU
5 PC 跳转: CSR 输出 csr2exu_new_pc_o (MTVEC.BASE / vectored) → IFU
6 SOI: 中断处理程序写 SOI → 标记中断开始, CICSR 更新
7 EOI: 处理完毕写 EOI → ISVR 清除 → IPR 清除 → 下一中断开始

中断响应延迟的关键路径
  1. IPIC 同步 + 检测: 2~3 周期 (如果 SCR1_IPIC_SYNC_EN 开启)
  2. 优先级树搜索: 0 周期 (纯组合, 与 IPR 更新同拍)
  3. CSR 仲裁 + 事件处理: 1~2 周期 (pnd_en 组合 → MSTATUS 更新 → new_pc 输出)
  4. IFU 取指跳转: 1 周期
总延迟约 5-6 周期。如果关闭 IPIC 同步 (SCR1_IPIC_SYNC_EN=0), 可减少 2 周期, 但需外部确保 IRQ 信号满足建立/保持时间。

# === 陷阱向量表 (MTVEC=0x1C0, Direct 模式) ===
.section .text.trap, "ax"
.align 6          # MTVEC 要求 64-byte 对齐
trap_entry:
    # 1. 原子上下文交换: sp↔mscratch
    csrrw   sp, mscratch, sp     # sp ← trap_frame_ptr, mscratch ← old_sp

    # 2. 保存被调用者寄存器到 trap frame
    sw      ra,  0(sp)
    sw      t0,  4(sp)
    sw      t1,  8(sp)
    sw      t2, 12(sp)
    sw      a0, 16(sp)
    sw      a1, 20(sp)

    # 3. 读 MCAUSE 判断中断类型
    csrr    t0, mcause           # mcause = 0x342
    srli    t1, t0, 31           # 取 bit[31] = I 位
    beqz    t1, .not_irq          # I=0 → 异常, 跳到异常处理
    andi    t1, t0, 0xF          # 取 exception code [3:0]
    li      t2, 11                # IRQ_M_EXTERNAL = 11
    bne     t1, t2, .not_ext_irq  # 不是外部中断 → 跳过

    # 4. 读 CISV 确认中断号
    li      t0, 0xBF0             # SCR1_CSR_ADDR_IPIC_CISV
    csrr    t0, 0xBF0             # 读 CISV
    andi    t0, t0, 0xF          # 取低 4 位 = 中断号
    li      t1, 5                 # 期望中断号 = 5
    bne     t0, t1, .not_irq5    # 不是 IRQ5 → 跳过

    # 5. 写 SOI 开始服务
    li      t0, 0xBF5             # SCR1_CSR_ADDR_IPIC_SOI
    csrw    0xBF5, zero          # 写任意值, 标记中断开始

    # 中断处理: 向 0x90000000 写入标记
    li      t0, 0x90000000
    li      t1, 0xCAFE
    sw      t1, 0(t0)

    # 6. 写 EOI 结束服务
    li      t0, 0xBF4             # SCR1_CSR_ADDR_IPIC_EOI
    csrw    0xBF4, zero          # 写任意值, 结束当前中断

    j       .restore

.not_irq5:
.not_ext_irq:
.not_irq:
    # 未处理的异常/中断: 死循环 (实际应跳转到错误处理)
    j       .restore

.restore:
    # 7. 恢复上下文并 mret 返回
    lw      a1, 20(sp)
    lw      a0, 16(sp)
    lw      t2, 12(sp)
    lw      t1,  8(sp)
    lw      t0,  4(sp)
    lw      ra,  0(sp)
    csrrw   sp, mscratch, sp     # 恢复 sp, mscratch 复原
    mret

# === 数据段: trap frame ===
.section .bss
.align 4
trap_frame:
    .space 64    # 足够的栈帧空间

# === 初始化代码 ===
.section .text.init
_start:
    # 设置 MTVEC = 0x1C0 (Direct 模式, 指向 trap_entry)
    la      t0, trap_entry
    csrw    mtvec, t0

    # 设置 MSCRATCH = &trap_frame
    la      t0, trap_frame
    csrw    mscratch, t0

    # 使能 IPIC 中断线 5: 写 IDXR=5, 再写 IER[5]=1 (通过 ICSR[IE])
    li      t0, 5
    csrw    0xBF6, t0           # IDXR = 5 (SCR1_IPIC_IDXR = 0xBF6)
    li      t0, 0x2               # bit[1] = IE
    csrw    0xBF7, t0           # ICSR = {..., ie=1} (SCR1_IPIC_ICSR = 0xBF7)

    # 使能 CSR 级外部中断 (MIE[11]=MEIE=1)
    li      t0, 0x800
    csrs    mie, t0              # MIE |= MEIE (bit 11)

    # 使能全局中断 (MSTATUS[3]=MIE=1)
    li      t0, 0x8
    csrs    mstatus, t0          # MSTATUS |= MIE

    # 主循环: 等待中断
1:  wfi
    j       1b
