第二课: HDU 调试状态机 — 4 个状态

                   haltreq
                     │
    ┌────────────────┼───────────────┐
    ▼                │               │
┌──────────┐   ┌──────────┐   ┌───────────┐
│ RUN      │──▶│ DBG_RUN  │──▶│ DBG_HALTED│
│(正常运行) │   │(调试运行) │   │(调试暂停)  │
└──────────┘   └──────────┘   └───────────┘
    ▲                │               │
    │                │  resumereq     │
    └────────────────┴───────────────┘
状态含义exu_no_commitirq_dsblpc_advmt_dsbl
RUN正常执行, 可退休指令000
DBG_RUN调试下运行 (resume)010
DBG_HALTED暂停, 所有指令被禁止提交111

状态转移触发条件

转移触发说明
RUN → DBG_RUN → DBG_HALTEDDM 发 haltreqDM 主动中断
RUN → DBG_HALTEDTDU 硬件断点触发模块请求进入调试
RUN → DBG_HALTEDEBREAK 指令 + DRET 未激活软件断点
DBG_HALTED → DBG_RUNDM 发 resumereq / 单步完成恢复执行
三步进调试模式
HDU 先进入 DBG_RUN (恢复) → 执行一条指令 (单步) → 指令退休后回到 DBG_HALTED。单步使能 dmode_sstep_en 来自 DCSR.STEP。

第三课: Program Buffer — 在调试模式下注入指令

// Program Buffer 是一条走旁路的指令注入路径
// 当 HDU 处于 DBG 状态, 且 pbuf 指令 valid 时:

hdu2ifu_pbuf_fetch_o = 1'b1;     // 告诉 IFU 从 pbuf 取指令
ifu2idu_instr_o      = pbuf_instr;  // 覆写正常取指路径

// 调试器通过 DM 接口写 pbuf 地址, 读回指令
hdu2dm_pbuf_addr_o   = {2'b00, dm_abstract_cmd_aarsize};  // 调试 Abstract Command
信号方向含义
hdu2ifu_pbuf_fetch_oHDU → IFU从 Program Buffer 取指令
hdu2ifu_pbuf_vd_iDM → IFU注入指令有效
hdu2ifu_pbuf_instr_iDM → IFU注入的 32 位指令
hdu2ifu_pbuf_err_iDM → IFU注入指令有错误
pbuf 的本质
调试器 (DM) 通过 DMI 总线将要执行的调试指令写入 pbuf。HDU 拉高 pbuf_fetch_o, IFU 输出 MUX 切换到 pbuf 通路。调试指令经 IDU/EXU 正常执行, 结果写入寄存器。这是 不侵入流水线 FSM 的前提下执行任意指令 的手段。

第四课: HDU 调试 CSR — DCSR / DPC / DSCRATCH0/1

CSR地址功能
DCSR0x7B0调试控制状态: CAUSE/STEP/STOPEVEN/STOPTIME/NMIP/PRV/EBREAKM/EBREAKU/...
DPC0x7B1调试 PC: 保存进入调试模式时的 PC (类似 MEPC 但用于调试)
DSCRATCH00x7B2调试暂存器 0: 通用 32 位 (调试器临时存储)
DSCRATCH10x7B3调试暂存器 1: 通用 32 位

DCSR 关键位域

位名称含义
[8:6]CAUSE调试进入原因: 1=EBREAK, 2=Trigger, 3=Haltreq, 4=Step
[2]STEP单步使能: 1=调试器请求单步执行
[3]STOPEVEN停机时间选择
[9]STOPTIME定时器在调试期间停止
[15]EBREAKMM-mode 下 EBREAK 进入调试模式
DCSR 的 WARL 行为
许多 DCSR 位是 WARL (Write Any, Read Legal)。例如 PRV 固定为 M-mode (11), NMIP 硬连线为零。写入不受支持的值被静默转换为合法值。

第五课: 调试模式进入与退出 — 完整 6 步流程

1 触发: haltreq / EBREAK / 硬件断点 → HDU 检测触发条件
2 提交屏障: exu_no_commit = 1 → 流水线所有进行中的指令被阻止退休
3 Flush 流水线: 清空 IFU 队列, 停止取指, DPC 保存进入 PC
4 通知 DM: hart_event_o = 1 → DM 得知 HART 已暂停
5 调试交互: DM 通过 pbuf 注入指令 (读寄存器、写寄存器、访问内存)
6 恢复: resumereq → exu_no_commit = 0 → 从 DPC 重新取指 → 正常执行

第七课: mcontrol 触发器 — 地址/数据匹配

字段含义典型值
dmode仅 Debug Mode 可写 (0=任意, 1=仅 DM)0
match匹配方式: 0=等于, 1=NAND, 2=大于等于, 3=小于0 (精确匹配)
action动作: 0=断点异常, 1=进入调试模式0/1
chain与下一个触发器链式组合0/1
timing0=发生在指令执行前, 1=发生在执行后0
select位掩码选择匹配条件: execute/load/storebit[0]=execute
size匹配大小: 0=任意, 1=2B, 2=4B, 3=8B2 (4B)
tdata2匹配地址/值断点地址
断点异常 vs 调试模式
action=0: 触发断点异常 (BREAKPOINT, mcause=3), 由 M-mode 异常处理程序处理。
action=1: 触发进入调试模式 (DBG_HALTED), 由外部调试器 (DM) 接管。

第八课: icount 触发器 — 指令计数触发

字段含义
dmode同 mcontrol
count14-bit 递减计数器 (每条退休指令 -1)
action同 mcontrol: 断点异常 / 进入调试模式
m/u/s在哪个特权级计数? (M/U/S)
pending计数器已达到 0, 触发待处理
// icount 工作方式
count_next = count_ff - 1;     // 每条退休指令减 1
if (count_next == 0)
    pending = 1;             // 下一次匹配时触发
if (pending && match_privilege)
    trigger_fire();            // 执行动作 (断点/进入调试)

第九课: 触发器链 — 多触发器组合

// 链: 当触发器 i 匹配后, 触发器 i+1 的匹配条件才生效
// 只有链中所有触发器都匹配, 才执行最后一个触发器的 action

// 例: 两个 mcontrol 链
// T0: select=load, tdata2=0x1000, chain=1
// T1: select=store, tdata2=0x2000, chain=0
// 只有: LOAD(0x1000) 然后 STORE(0x2000) 都匹配时才触发
链的逻辑: AND 而非 OR
链中所有触发器匹配 → 最后一个触发器的 action 执行。任何一个不匹配 → 链断开, 不触发。这实现了一个简单而强大的功能: "先 Load 某地址, 再 Store 某地址" 的复合断点。

第十课: TDU ↔ LSU/EXU 接口 — 断点匹配信号流

指令断点接口 (TDU ↔ EXU)

信号方向含义
exu2tdu_imon_iEXU → TDU指令监视: vd + pc + 特权级
tdu2exu_ibrkpt_match_oTDU → EXU指令断点匹配位掩码
tdu2exu_ibrkpt_exc_req_oTDU → EXU指令断点异常请求
exu2tdu_bp_retire_iEXU → TDU已退休的断点位掩码 (icount 用)

数据断点接口 (TDU ↔ LSU)

信号方向含义
lsu2tdu_dmon_iLSU → TDU数据监视: vd + addr + load/store
tdu2lsu_dbrkpt_match_oTDU → LSU数据断点匹配位掩码
tdu2lsu_dbrkpt_exc_req_oTDU → LSU数据断点异常请求
权限: dmode 决定谁可以写
dmode=1 → 仅 DM (通过 pbuf) 可以写 tdata1/2/select。M-mode 软件写入被忽略。dmode=0 → 任何特权级均可写入。这保证了调试器不会因用户程序意外修改断点而失效。
