第三课: HDU 的 7 个计数使能信号 — 精确触发条件与目的地

HDU 通过 type_scr1_hdu_runctrl_s 结构体向流水线发出 7 个关键控制信号。这些信号在 hart_runctrl_upd (从 DHALTED 恢复时) 和 hart_runctrl_clr (进入 DHALTED 时) 更新。

#信号方向触发条件 (何时=1)目的模块效果
1 hdu2exu_no_commit_o HDU → EXU dmode_cause_ebreak=1 或 dmode_cause_tmreq=1
(ebreak 或 trigger 模块请求时)		 EXU retire 阻止当前指令退休, 架构状态不回写
2 hdu2exu_irq_dsbl_o HDU → EXU DBG_RUN/DBG_HALTED 状态; RESUME 到 RUN 时 step ? (~stepie) : 0 EXU 中断控制器 禁止所有外部中断 (定时器/软件/外部)
3 hdu2exu_pc_advmt_dsbl_o HDU → EXU DBG_RUN (DRUN) 状态 (hart_runctrl 更新时设 1) EXU PC 逻辑 PC 不递增, 配合 pbuf 指令执行
4 hdu2exu_pbuf_fetch_o HDU → EXU hart_runctrl.fetch_src == PBUF (DRUN 期间) EXU fetch mux IFU 取指 MUX 切换到 Program Buffer 路径
5 hdu2exu_dmode_sstep_en_o HDU → EXU hart_runctrl.redirect.sstep = 1 (DCSR.STEP 使能时) EXU 单步控制 执行一条指令后自动回到 DBG_HALTED
6 hdu2tdu_hwbrk_dsbl_o HDU → TDU hart_runctrl.hwbrkpt_dsbl = 1 (DRUN 期间) TDU 调试运行期间屏蔽硬件断点 (避免自触发)
7 hdu2exu_dbg_new_pc_o HDU → EXU 始终输出 DPC 的当前值 (csr_dpc_ff) EXU PC 恢复 调试恢复时从 DPC 保存的地址重新取指
信号 1-7 的时序关系
进入 DHALTED: 先置 no_commit=1 (流水线停止提交) → timeout 后 hart_halt_ack=1 → FSM 进入 DHALTED → irq_dsbl=1。
退出 DHALTED: DM 写 resume_req → dfsm_update=1 → hart_runctrl_upd=1 → 根据 cmd 设置 4/5/6/7 信号。

第五课: HDU 的 NMI (不可屏蔽中断) 处理路径

SCR1 的 HDU 中 NMI 通过 调试模式的全局中断禁用 机制实现。RISC-V Debug Spec 0.13 定义了 DCSR.NMIP (bit 12, 非可屏蔽中断挂起), SCR1 将其硬连线为 0 (无独立 NMI 引脚)。实际的 NMI 处理通过以下三层实现:

NMI 路径架构

外部 NMI 源 (可选)
       │
       ▼
┌─────────────┐    irq_dsbl      ┌──────────┐
│  EXU 中断    │◀───────────────│   HDU    │
│  控制器      │                 │ RunCtrl  │
│             │   dmode_cause_   │          │
│  ebreak/    │───except───────▶│  FSM     │
│  trigger    │                 │          │
└─────────────┘                 └──────────┘
       │                              │
       │ irq_dsbl=1 期间:             │ dmode_cause_any
       │ 所有中断被屏蔽               │ (包含 dmode_cause_except)
       ▼                              ▼
  中断不响应                   FSM 进入 DBG_HALTED
                                      │
                              hart_event_o → DM

关键 NMI 相关行为

场景irq_dsblNMI 行为
RUN 状态0中断正常响应
DBG_HALTED1所有中断 (包括 NMI) 被屏蔽
DBG_RUN (DRUN)1所有中断被屏蔽, 硬件断点也被屏蔽 (hwbrk_dsbl=1)
单步 (step=1, stepie=0)1中断被屏蔽
单步 (step=1, stepie=1)0中断可在单步指令退休后响应
DCSR.STEPIE (Step Interrupt Enable) 的作用
DCSR.STEPIE 位控制单步执行期间是否允许中断: irq_dsbl = step ? (~stepie) : 0。当 step=1 且 stepie=1 时, 中断不会被屏蔽, NMI 可以在单步指令退休后得到处理。

DCSR 位域完整定义 (来源: scr1_hdu.svh)

位名称类型含义
[1:0]PRVWARL进入调试前的特权级: 固定为 M-mode (2'b11)
[2]STEPWARL单步使能: 1=恢复后执行 1 条指令再暂停
[5:3]rsrv0WARL保留, 硬连线为 0
[8:6]CAUSEWARL调试进入原因: 1=EBREAK, 2=Trigger, 3=Haltreq, 4=Step, 5=Reset
[10:9]rsrv1WARL保留
[11]STEPIEWARL单步中断使能: 1=单步期间允许中断
[14:12]rsrv2WARL保留
[15]EBREAKMWARLM-mode 下 EBREAK 进入调试模式: 1=进入, 0=产生异常
[27:16]rsrv3WARL保留
[31:28]XDEBUGVERRO外部调试支持版本: 固定 4'h4 (spec 0.13)
DSCRATCH0 的特殊实现 — 通过 DM Abstract Data Register
SCR1 的 DSCRATCH0 不直接存储在 HDU 中, 而是通过 DM 的 abstract data register 0 实现: 读时从 dm2hdu_dreg_rdata_i 获取, 写时通过 hdu2dm_dreg_req_o 请求 DM 写入。这使得 DSCRATCH0 天然对调试器可见。

第八课: 调试模式进入与退出 — 完整 6 步流程

1 触发: haltreq / EBREAK / 硬件断点 → HDU 检测 dmode_cause_any
2 提交屏障: ebreak/trigger 时 exu_no_commit = 1 → 当前指令不退休; haltreq 时通过 timeout 等待 EXU 空闲
3 Timeout 确认: haltreq 需等待 64 周期 timeout (halt_req_timeout_flag=1) 且 EXU 不忙; 软硬件断点可立即确认
4 状态更新: hart_halt_ack=1 → FSM 进入 DBG_HALTED → DCSR.cause 锁存 halt cause → DPC 锁存当前 PC → HART status 更新 → DM 得知暂停
5 调试交互: DM DHI FSM 通过 pbuf 注入指令 (读寄存器、写寄存器、访问内存)
6 恢复: DM 写 DMCONTROL.resumereq → DHI FSM RESUME_REQ → dm_cmd_run/drun → FSM 更新 → hart_runctrl 配置 → 从 DPC 重新取指

关键: bp_retire 的时序
exu2tdu_bp_retire_i 是指令退休时的断点位掩码, 在指令完成执行且无异常时置位。TDU 只在 bp_retire_i 对应位为 1 时才向 HDU 发送 dmode_req, 保证 触发动作发生在指令退休之后 (timing=0 时触发在指令执行前, 但 dmode 请求在退休时)。

第十一课: TDU 触发器动作 — Halt/Resume/Trigger Gen

3 种动作类型的完整流程

动作action 位信号路径最终效果
断点异常 0 csr_mcontrol_exec_hit → tdu2exu_ibrkpt_exc_req_o → EXU 产生 BREAKPOINT 异常 (mcause=3) M-mode 异常处理程序接管
进入调试模式 1 csr_mcontrol_action_ff[i] & bp_retire_i[i] → tdu2hdu_dmode_req_o → HDU dmode_cause_tmreq → FSM 进入 HALTED 外部调试器接管
Trigger Gen (icount 预留) action=1 (进入调试) 或 action=0 (断点异常) icount count→1 时 hit=1, retire 位触发 action 按 action 决定: 断点异常 或 进入调试

动作汇总逻辑 (来源: scr1_pipe_tdu.sv L533-542)

always_comb begin
    tdu2hdu_dmode_req_o = 1'b0;
    for(int i = 0; i < MTRIG_NUM; ++i)
        tdu2hdu_dmode_req_o |= (csr_mcontrol_action_ff[i]
                              & exu2tdu_bp_retire_i[i]);
    // icount 的 action 也参与 dmode_req
    tdu2hdu_dmode_req_o |= (csr_icount_action_ff
                          & exu2tdu_bp_retire_i[ALLTRIG_NUM-1]);
end

第十二课: TDU 触发器使能/禁用与过滤逻辑

三级使能过滤链

          Level 1: tdu_dsbl_i (全局 TDU 禁用)
          ────────────────────────────────────
          │ 来自顶层, 调试模式下 DM 控制的全局禁用
          │ 当 tdu_dsbl_i=1 时所有触发器失效
          ▼
          Level 2: hdu2tdu_hwbrk_dsbl_o (HDU 硬件断点禁用)
          ────────────────────────────────────
          │ hart_runctrl.hwbrkpt_dsbl = 1 (DRUN 期间)
          │ 等同于 tdu_dsbl_i 的效果
          ▼
          Level 3: csr_mcontrol_dmode_ff/M_ff (单触发器使能)
          ────────────────────────────────────
          │ dmode=1 时仅 DM 可写; M_ff=0 时触发器不参与匹配
          ▼
          Level 4: csr_mcontrol_exec_ff/load_ff/store_ff (匹配类型选择)
          ────────────────────────────────────
          │ 仅当对应的 exec/load/store 位为 1 时才参与相应匹配
          ▼
          Level 5: 地址/数据匹配 (TDATA2)
          ────────────────────────────────────
          │ exu2tdu_imon_i.addr == csr_tdata2_ff[i]
          ▼
          最终: csr_mcontrol_exec_hit[i] 置位

dmode 写保护逻辑

// dmode=1 时, 写操作仅当 tdu_dsbl_i=1 (即 DM 控制禁用) 时才生效
assign csr_mcontrol_upd[trig] = ~csr_mcontrol_dmode_ff[trig]
                              ? csr_mcontrol_wr_req[trig]        // dmode=0: 任意可写
                              : tdu_dsbl_i & csr_mcontrol_wr_req[trig]; // dmode=1: 仅 DM 可控

// icount 同理
assign csr_icount_upd = ~csr_icount_dmode_ff
                      ? csr_icount_wr_req
                      : tdu_dsbl_i & csr_icount_wr_req;

// TDATA2 同理
assign csr_tdata2_upd[trig] = ~csr_mcontrol_dmode_ff[trig]
                            ? clk_en & csr_addr_tdata2[trig] & csr_wr_req
                            : clk_en & csr_addr_tdata2[trig] & csr_wr_req & tdu_dsbl_i;
tdu_dsbl_i 的双重角色
tdu_dsbl_i 既作为全局禁用 (level 1), 也作为 dmode=1 触发器的 写使能钥匙。当 HDU 设置 hwbrkpt_dsbl=1 时 (DRUN 期间), 效果等同于 tdu_dsbl_i=1, 既禁用匹配又启用写操作。这保证了调试器在 DRUN 期间不会被自己的断点触发。

第十四课: icount 触发器 — 指令计数触发

字段位含义
type[31:28]固定 3 (icount)
dmode[27]仅 DM 可写 (同 mcontrol)

icount 递减与命中逻辑

// 递减使能: 仅在 M-mode 下, 指令有效, count>0 时
assign csr_icount_decr_en = (~tdu_dsbl_i & csr_icount_m_ff)
                          ? exu2tdu_imon_i.vd & (csr_icount_count_ff != 14'b0)
                          : 1'b0;

// 实际递减: 指令退休且 skip 未激活时
assign csr_icount_count_decr = exu2tdu_imon_i.req & csr_icount_decr_en
                             & ~csr_icount_skip_ff;

// count 下个值: 写操作时取写数据, 否则递减
csr_icount_count_next = csr_icount_count_decr
                      ? csr_icount_count_ff - 1'b1
                      : csr_icount_count_ff;

// hit 在 count==1 且非 skip 时置位, 写入时可清零
csr_icount_hit_next = exu2tdu_bp_retire_i[ALLTRIG_NUM-1]
                    ? 1'b1
                    : csr_icount_hit_ff;

// skip: 写 count 后第一条指令不计入 (避免立即触发)
csr_icount_skip_ff: 写操作后自动置 1, 第一条退休指令后清零
icount 作为单步触发器
设置 count=1 → 执行一条指令后 count→0 → hit=1 → 退休时触发。与 DCSR.STEP 的区别: icount 方案不依赖 DCSR 配置, 且可以限定在 M-mode 下生效。
