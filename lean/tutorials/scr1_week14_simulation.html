第三课: sim/Makefile -- 4 种仿真器的编译流程

支持 4 种仿真器: modelsim / vcs / ncsim / verilator

// sim/Makefile -- 核心流程
rtl_src_dir := $(root_dir)/src/
rtl_core_files ?= core.files          // 流水线核心 (IFU/IDU/EXU/LSU/MPRF/CSR...)
rtl_top_files ?= ahb_top.files        // 顶层封装 (top_ahb/dp_memory/tcm/timer...)
rtl_tb_files ?= ahb_tb.files          // Testbench (top_tb_ahb/memory_tb_ahb)

sv_list := $(rtl_core_list) $(rtl_top_list) $(rtl_tb_list)

运行一个测试的完整流程

1 编译 RISC-V 测试程序: riscv32-unknown-elf-gcc -march=rv32imc test.S -o test.elf
2 提取 hex 文件: riscv32-unknown-elf-objcopy -O verilog test.elf test.hex
3 将 hex 加载到仿真器的 IMEM 中
4 运行仿真 10000+ 时钟周期
5 检查: tohost 地址 = 0 (成功) 或 1 (失败)

Verilator 的优势
Verilator 编译的 C++ 模型比商业仿真器快 5-10 倍。适合快速迭代验证和 CI/CD 回归测试。缺点是时序精度低于事件驱动仿真器 (如 ModelSim/VCS)。

第七课: SVA 断言汇总 -- 11 个模块的验证覆盖

模块断言数量验证内容
IFU8X 态检测, 丢弃计数器边界, 队列不上溢, 错误后回 IDLE
IDU2X 态检测, IALU 命令范围
EXU5+PC 更新之前已初始化, new_pc_req 之前已初始化, 新 PC 请求与 flush 的一致性
IALUNMDU 状态转移, 除法 CORR 前提条件
LSU2+FSM 状态 + 请求的合法性
MPRF1写请求时数据/地址无 X 态 (negedge clk)
CSR4+MRET+IRQ 互斥, MCYCLE 递增边界, MSTATUS 位域
SVA 的三个检查层次
X 态: 信号不应有未知值 → 防止未初始化的寄存器
边界: 计数器、队列、FSM 状态必须在合法范围 → 防止设计缺陷
行为: 关键时序约束 (如: 错误后必回 IDLE) → 防止功能错误

从 SCR1 到 Linux 的距离
SCR1 只实现了 M-mode。要跑 Linux 需要: S/U mode + MMU (SV32 虚拟内存) + 页故障处理 + 外部中断控制器 (PLIC) + Timer + 更多 CSR。建议从 Rocket Chip 或 CVA6 入手学习完整的特权架构。

练习

练习 1: 运行 hello 测试

用 ModelSim 或 Verilator 运行 sim/tests/hello/ 测试。记录 mcycle 和 minstret 值, 计算 IPC。在波形中查看 tohost 信号从非零变为 0 的时刻。

练习 2: 编写一个自定义测试

写一个简短的 RISC-V 汇编程序: 将 x1-x4 初始化, 计算 (x1+x2)*(x3-x4), 结果存入 x5。编译后在 SCR1 上运行, 验证 x5 的值。

练习 3: 添加一条 SVA 断言

在 scr1_pipe_ifu.sv 的断言区域添加一条断言: "指令队列的占用度永远不会超过 4"。用仿真验证断言通过。

练习 4: 修改流水线深度

修改 SCR1_NO_EXE_STAGE / SCR1_NO_DEC_STAGE 宏, 从 4 级流水线切换到 2 级流水线。重新编译和仿真, 观察 IPC 和最高频率的变化。

练习 5: 性能分析

运行 CoreMark 基准测试, 记录 CoreMark/MHz 分数。分析哪些指令类型导致了最多的流水线 Stall? 如何优化?
