第四课: RISC-V 工具链 -- 从 C/汇编到 hex 的完整链路

工具链四件套及职责

工具输入输出在 SCR1 构建中的角色
riscv32-unknown-elf-gcc .c / .S .o / .elf 编译 + 汇编 + 链接 (一步完成); 单独编译时加 -c 只出 .o
riscv32-unknown-elf-ld .o .elf 链接器 (通常由 gcc 隐式调用, 不在 Makefile 中显式出现)
riscv32-unknown-elf-objcopy .elf .hex 提取二进制段, 转为 Verilog 可读 hex (test.hex)
riscv32-unknown-elf-objdump .elf .dump 反汇编 + 符号表 (-D -w -x -S), 用于人工审查

完整构建流水线 (来自 common.mk)

.S 汇编源
GCC -c
.o 目标文件
GCC -T ld_script
.elf 可执行
OBJCOPY
.hex 加载镜像
OBJDUMP
.dump 反汇编
// common.mk 中的关键规则

// Step 1: 汇编 .S → .o
$(bld_dir)/%.o: %.S
	$(RISCV_GCC) $(CFLAGS) -D__ASSEMBLY__=1 -c -I$(incs) $< -o $@

// Step 2: C 编译 .c → .o
$(bld_dir)/%.o: %.c
	$(RISCV_GCC) $(CFLAGS) -c -I$(incs) $< -o $@

// Step 3: 链接 .o + .ld → .elf
$(bld_dir)/%.elf: $(ld_script) $(c_objs) $(asm_objs)
	$(RISCV_GCC) -o $@ -T $^ $(LDFLAGS)

// Step 4: 提取 .elf → .hex
$(bld_dir)/%.hex: $(bld_dir)/%.elf
	$(RISCV_OBJCOPY) $^ $@

// Step 5: 反汇编 .elf → .dump
$(bld_dir)/%.dump: $(bld_dir)/%.elf
	$(RISCV_OBJDUMP) -D -w -x -S $^ > $@

运行一个测试的完整流程

1 编译 RISC-V 测试程序: riscv32-unknown-elf-gcc -march=rv32imc test.S -Tlink.ld -nostdlib -o test.elf
2 提取 hex 文件: riscv32-unknown-elf-objcopy -O verilog test.elf test.hex
3 生成反汇编供审查: riscv32-unknown-elf-objdump -D test.elf > test.dump
4 将 hex 文件名写入 test_info (testbench 按行读取并逐一执行)
5 运行仿真, testbench 自动加载 hex 到 IMEM/DMEM
6 运行直到 PC 抵达 SCR1_SIM_EXIT_ADDR 或超时
7 判定: tohost / 签名比对 / 超时 → PASS / FAIL

时钟生成 -- 两种模式

// 非 Verilator 模式 (仿真器内部时钟生成)
`ifndef VERILATOR
always #5   clk     = ~clk;         // 100 MHz (10ns 周期)
always #500 rtc_clk = ~rtc_clk;     // 1 MHz (实时时钟, 用于 timer)
`endif // VERILATOR

// Verilator 模式 (由 C++ wrapper 控制, clk 作为模块输入)
`ifdef VERILATOR
    input logic clk                  // 外部时钟, 由 wrapper.c 在主循环中翻转
`endif // VERILATOR

复位序列 -- 2-bit 饱和计数器

// 复位生成: rst_cnt 从 0 饱和到 3 (0b11), rst_n = &rst_cnt
logic [1:0] rst_cnt;

assign rst_n = &rst_cnt;           // 只有 rst_cnt == 2'b11 时 rst_n=1

always_ff @(posedge clk) begin
    if (rst_init)       rst_cnt <= '0;    // 测试开始: 清零复位计数器
    else if (~&rst_cnt) rst_cnt <= rst_cnt + 1'b1;  // 饱和递增
end

// 复位时序:
// Cycle 0: rst_cnt=0, rst_n=0 (复位)
// Cycle 1: rst_cnt=1, rst_n=0
// Cycle 2: rst_cnt=2, rst_n=0
// Cycle 3: rst_cnt=3, rst_n=1 (释放复位)
// 总共 3 个周期 (30ns) 的低有效复位

测试调度状态机 -- scr1_top_tb_runtests.sv

always_ff @(posedge clk) begin
    watchdogs_cnt <= watchdogs_cnt + 'b1;       // 每个周期递增看门狗

    if (test_running) begin
        // 状态: RUNNING
        if (curr_pc == SCR1_SIM_EXIT_ADDR) begin
            // CPU 到达退出地址 → 开始判定
            test_running <= 1'b0;

            if (identify_test(test_file) == COMPLIANCE) begin
                // 合规测试: 读取 begin_signature ~ end_signature 区间
                // 与 reference_output 逐字比对
                test_pass &= (ref_data == test_data);
            end else if (identify_test(test_file) == ARCH) begin
                // 架构测试: 同上, 比对 ref_data 目录下的参考数据
                test_pass &= (ref_data == test_data);
            end else begin
                // 普通测试: 检查 x10 (a0) 寄存器 == 0
                test_pass = (mprf_int[10] == 0);
            end
            tests_passed += test_pass;
        end

    end else begin
        // 状态: IDLE → 加载下一个测试
        if ($fgets(test_file, f_info)) begin
            f_test = $fopen(test_file, "r");
            if (f_test != 0) begin
                i_memory_tb.test_file_init = 1'b1;  // 触发存储器加载 hex
                test_running <= 1'b1;
                rst_init <= 1'b1;                   // 触发复位计数器清零
            end
        end else begin
            // test_info 读完 → 打印汇总并 $finish
            $display("# Summary: %0d/%0d tests passed", tests_passed, tests_total);
            $finish();
        end
    end

    // 看门狗: TIMEOUT = 2,000,000 周期 (20ms @ 100MHz)
    if (watchdogs_cnt == TIMEOUT) begin
        $write("Error: TIMEOUT  %s\n", test_file);
        test_running <= '0;
    end
end

#include <verilated.h>
#include "Vscr1_top_tb_ahb.h"

int main(int argc, char** argv) {
    Verilated::commandArgs(argc, argv);    // 解析 +verilator+ 参数
    top = new Vscr1_top_tb_ahb;               // 实例化 Verilated 模型

#ifdef VCD_TRACE
    Verilated::traceEverOn(true);            // 启用波形追踪
    VerilatedVcdC* tfp = new VerilatedVcdC;
    top->trace(tfp, 99);                     // 追踪 99 层层次结构
    tfp->open("simx.vcd");                  // 输出 VCD 文件
#endif

    while (!Verilated::gotFinish()) {      // 主循环: 直到 $finish()
        if ((main_time % 10) == 1) top->clk = 1;   // 上升沿
        if ((main_time % 10) == 6) top->clk = 0;   // 下降沿
        top->eval();                        // 评估组合逻辑
        main_time++;
#ifdef VCD_TRACE
        tfp->dump(main_time);               // 写入 VCD 时间步
#endif
    }
    top->final();                           // 清理
#ifdef VCD_TRACE
    tfp->close();                           // 关闭 VCD 文件
#endif
}

VCD vs FST: 格式选择
Verilator 默认输出 VCD 格式。若编译时使用 --trace-fst 替代 --trace, 可输出 FST 格式 (Fast Signal Trace)。FST 文件比 VCD 小 10-50 倍, 读写更快, 可用 GTKWave 打开。VCD 是 ASCII 文本格式, 通用性好但体积大, 可用任何波形查看器或脚本处理。

常见 FPGA 陷阱
1) 忘记去掉 SCR1_TRGT_SIMULATION: SVA 和仿真逻辑占用额外资源, 且可能包含不可综合的 $fatal。
2) 顶层模块选错: 用了 scr1_top_tb_ahb 而非 scr1_top_ahb -- testbench 顶层不可综合。
3) IMEM 初始化: 需要将 hex 文件转为 FPGA BRAM 的初始化格式 (COE/MIF)。
4) 时钟域: 检查 rtc_clk 是否在 FPGA 上有实际的时钟源。

从 SCR1 到 Linux 的距离
SCR1 只实现了 M-mode。要跑 Linux 需要: S/U mode + MMU (SV32 虚拟内存) + 页故障处理 + 外部中断控制器 (PLIC) + Timer + 更多 CSR。建议从 Rocket Chip 或 CVA6 入手学习完整的特权架构。

练习

练习 1: 运行 hello 测试并分析性能

用 ModelSim 或 Verilator 运行 sim/tests/hello/ 测试。记录 mcycle 和 minstret 值, 计算 IPC (IPC = minstret / mcycle)。在波形中查看 tohost 信号从非零变为 0 的时刻, 以及 curr_pc 的执行路径。

练习 2: 编写自定义 RISC-V 汇编测试

写一个简短的 RISC-V 汇编程序: 将 x1-x4 初始化, 计算 (x1+x2)*(x3-x4), 结果存入 x5。编译后在 SCR1 上运行, 验证 x5 的值。参考 sim/tests/riscv_isa/ 中的 .S 文件格式, 确保包含 tohost 退出机制。

练习 3: 添加一条 SVA 断言

在 scr1_pipe_ifu.sv 的断言区域添加一条断言: "指令队列的占用度永远不会超过 4"。用仿真验证断言通过。尝试故意制造一个会触发断言失败的场景 (如修改队列深度上限), 确认断言能正确捕获。

练习 4: 修改流水线深度并对比性能

修改 SCR1_NO_EXE_STAGE / SCR1_NO_DEC_STAGE 宏, 从 4 级流水线切换到 2 级流水线。重新编译和仿真, 对比不同配置下 Dhrystone 和 CoreMark 的 IPC 与 DMIPS/MHz 值。用波形分析: 2 级流水线中哪个阶段成为瓶颈?

练习 5: 性能瓶颈分析

运行 CoreMark 基准测试, 记录 CoreMark/MHz 分数。分析哪些指令类型导致了最多的流水线 Stall? 在波形中追踪 LSU 的 hready 等待周期和 IFU 的 discard 计数器。提出 3 条优化建议并分析其预期收益。

练习 6: 编写 Makefile 添加新测试套件

仿照 sim/tests/hello/Makefile, 在 sim/tests/ 下新建一个 custom/ 目录, 包含一个计算斐波那契数列的 C 程序。编写 Makefile 使其能生成 .elf/.hex/.dump 并自动注册到 test_info。在 SCR1 上运行并验证结果。

练习 7: VCD 波形逆向分析

用 Verilator 带波形运行一个测试, 生成 VCD 文件。使用 GTKWave 打开, 不查看源码, 仅通过波形回答: 1) 从复位释放到第一条指令取出的延迟; 2) 第一条 Load 指令的访存延迟 (几个周期); 3) 最近一次 pipeline flush 的原因 (通过 PC 跳转模式推断)。

练习 8: 注入故障并调试

在 IALU 中故意引入一个 bug (如将某条算术指令的结果左移 1 位)。运行 riscv_isa 测试, 观察哪些测试失败。用波形定位错误指令, 追溯源码修复 bug。记录整个调试过程: 日志分析 → 波形定位 → 代码修复 → 回归验证。

练习 9: 合规测试扩展

为 SCR1 的 riscv_compliance Makefile 添加自定义 cut_list 项, 排除一个你认为不适用的合规测试。记录排除理由。然后运行完整合规套件, 确认所有保留的测试都通过。

练习 10: FPGA 综合准备

将 SCR1 的仿真配置切换为 FPGA 综合配置: 移除 testbench 文件, 关闭 SCR1_TRGT_SIMULATION, 确认顶层模块为 scr1_top_ahb。编写一个简单的 FPGA 约束文件 (XDC 或 SDC), 定义 clk 和 rst_n 的引脚与时钟周期约束 (100MHz)。
