第1课: module —— 硬件设计的基本单元

在 SystemVerilog 中，一切硬件设计都封装在 module 里。可以把 module 理解为一个"芯片"——它定义了这个硬件的输入输出接口（input/output）和内部实现逻辑。

SCR1 真实例子: scr1_pipe_lsu.sv (加载存储单元)
// 模块声明: 名称 + 端口列表
module scr1_pipe_lsu (
    // ---- 时钟与复位 ----
    input   logic                    rst_n,           // 复位 (低有效)
    input   logic                    clk,             // 时钟

    // ---- EXU <-> LSU 接口 ----
    input   logic                    exu2lsu_req_i,   // 访存请求
    input   type_scr1_lsu_cmd_sel_e  exu2lsu_cmd_i,   // 访存命令 (枚举类型)
    output  logic                    lsu2exu_rdy_o,   // LSU 就绪
    output  logic [31:0]             lsu2exu_ldata_o  // 加载数据 (32位)
);

// ====== 内部信号声明 ======
logic  lsu_cmd_upd;   // 命令更新使能
logic  dmem_resp_ok;  // 存储器响应: OK

// ====== 内部逻辑 ======
assign dmem_resp_ok = (dmem2lsu_resp_i == SCR1_MEM_RESP_RDY_OK);

endmodule : scr1_pipe_lsu
三层结构: 每个 module 都遵循这个模式
1 端口声明: 定义输入 input 和输出 output，这是模块与外界的连接点
2 内部信号: 在模块内部使用的导线和寄存器，如 logic lsu_cmd_upd
3 逻辑实现: assign (组合逻辑) + always_ff (时序逻辑) + always_comb (组合逻辑)
Verilog 旧写法 (不推荐)
input wire clk
output reg [7:0] data
SystemVerilog 推荐写法
input logic clk
output logic [7:0] data

SystemVerilog 用统一的 logic 类型替代了 wire/reg 的双轨制，编译器会自动判断是组合还是时序。

第2课: 数据类型 —— logic / enum / struct / array

2.1 基础类型: logic 和位宽声明

声明含义
logic a;1 位信号 (0 或 1)
logic [31:0] b;32 位信号, bit31 是最高位
logic [7:0] c [0:15];16 个 8 位元素的数组
logic ['SCR1_XLEN-1:0] d;参数化位宽 (SCR1_XLEN=32)
位宽陷阱: [MSB:LSB] vs [LSB:MSB]
logic [31:0] 和 logic [0:31] 都是 32 位，但 bit 编号方向相反。SCR1 统一使用 [MSB:0] 风格。
例: logic [31:0] a; → a[31] 是最高位, a[0] 是最低位。

2.2 枚举类型 enum —— 给数字取名字

SCR1 真实例子: IFU 状态机状态 (scr1_pipe_ifu.sv:91-94)
// 定义一个只有两个值的枚举
typedef enum logic {
    SCR1_IFU_FSM_IDLE,       // 逻辑值 = 0
    SCR1_IFU_FSM_FETCH       // 逻辑值 = 1
} type_scr1_ifu_fsm_e;       // _e 后缀表示枚举类型

枚举的好处: 写 ifu_fsm_curr == SCR1_IFU_FSM_IDLE 比写 ifu_fsm_curr == 1'b0 清晰得多。SCR1 全程使用枚举，代码可读性极高。

SCR1 真实例子: 指令操作码枚举 (scr1_riscv_isa_decoding.svh:25-37)
typedef enum logic [6:2] {           // 枚举基类型 = 5位
    SCR1_OPCODE_LOAD     = 5'b00000,
    SCR1_OPCODE_OP_IMM   = 5'b00100,   // ADDI, ANDI 等
    SCR1_OPCODE_AUIPC    = 5'b00101,
    SCR1_OPCODE_STORE    = 5'b01000,   // SW, SH, SB
    SCR1_OPCODE_OP       = 5'b01100,   // ADD, SUB 等
    SCR1_OPCODE_BRANCH   = 5'b11000,   // BEQ, BNE 等
    SCR1_OPCODE_JAL      = 5'b11011    // 无条件跳转
} type_scr1_rvi_opcode_e;

2.3 结构体 struct —— 把一组信号打包

SCR1 真实例子: EXU 命令结构体 (scr1_riscv_isa_decoding.svh)
typedef struct packed {           // packed = 紧密排列为位向量
    logic                   instr_rvc;    // 1位: 是否压缩指令
    logic [4:0]             ialu_cmd;     // 5位: ALU 操作码
    logic [4:0]             rs1_addr;     // 5位: 源寄存器1地址
    logic [4:0]             rs2_addr;     // 5位: 源寄存器2地址
    logic [4:0]             rd_addr;      // 5位: 目标寄存器地址
    logic [31:0]            imm;          // 32位: 立即数
} type_scr1_exu_cmd_s;                    // _s 后缀表示结构体类型

packed struct 就像一个 C 语言的 struct，所有字段紧密排列成一个位向量。在 SCR1 中, IDU 译码后把一个 packed struct 原样传给 EXU，而不是传几十根独立信号线——这就是结构化设计的优势。

2.4 localparam —— 模块内部的常量

SCR1 真实例子: IFU 队列参数 (scr1_pipe_ifu.sv:77-85)
localparam SCR1_IFU_Q_SIZE_WORD  = 2;              // 队列深度: 2个字
localparam SCR1_IFU_Q_SIZE_HALF  = SCR1_IFU_Q_SIZE_WORD * 2;  // = 4个半字
localparam SCR1_IFU_QUEUE_ADR_W  = $clog2(SCR1_IFU_Q_SIZE_HALF); // 地址位宽 = ceil(log2(4)) = 2

localparam 在模块内部有效 (外部不可见)，$clog2() 是 SystemVerilog 内置函数，计算以 2 为底的对数向上取整。

第3课: 组合逻辑 —— assign 和 always_comb

组合逻辑的特征: 输出只取决于当前输入，没有记忆。就像纯数学函数 f(a,b)=a+b，输入变了输出马上变。

3.1 assign: 最简单的连续赋值

SCR1 真实例子: LSU 的响应判断 (scr1_pipe_lsu.sv:114-117)
// 用 assign 做简单的组合逻辑判断
assign dmem_resp_ok       = (dmem2lsu_resp_i == SCR1_MEM_RESP_RDY_OK);
assign dmem_resp_er       = (dmem2lsu_resp_i == SCR1_MEM_RESP_RDY_ER);
assign dmem_resp_received = dmem_resp_ok | dmem_resp_er;

// 等价于: 任何时刻，如果输入响应 == OK，dmem_resp_ok 就 = 1
//         如果输入响应 == ER，dmem_resp_er 就 = 1

3.2 always_comb: 复杂组合逻辑

SCR1 真实例子: LSU 的三路并行判断 (scr1_pipe_lsu.sv:120-137)
// always_comb 块 = "当任何输入变化时，重新计算输出"
always_comb begin
    // 默认值: 全部清零
    dmem_cmd_load  = 1'b0;
    dmem_cmd_store = 1'b0;

    case (exu2lsu_cmd_i)
        SCR1_LSU_CMD_LB, SCR1_LSU_CMD_LBU,
        SCR1_LSU_CMD_LH, SCR1_LSU_CMD_LHU,
        SCR1_LSU_CMD_LW:          dmem_cmd_load  = 1'b1;  // 加载指令

        SCR1_LSU_CMD_SB,
        SCR1_LSU_CMD_SH,
        SCR1_LSU_CMD_SW:          dmem_cmd_store = 1'b1;  // 存储指令
    endcase
end
always_comb 的金科玉律
必须在块开头给所有输出赋默认值，否则会生成锁存器 (latch)。
SCR1 的习惯: 在 always_comb begin 后第一件事就是把所有输出信号清零。看不到这个习惯的代码几乎一定有 bug。
错误的写法 (会产生 latch)
always_comb
  if(en) y = a;
  // 缺少 else!
  // en=0 时 y 保持原值 = latch
正确的写法 (纯组合)
always_comb begin
  y = '0;     // 先设默认值
  if(en) y = a; // 再设特殊情况
end

第4课: 时序逻辑 —— always_ff 与非阻塞赋值

时序逻辑的特征: 有记忆，输出取决于当前输入 + 历史状态。信号只在时钟上升沿 (posedge clk) 更新，就像 D 触发器的行为。

4.1 always_ff: 时序逻辑的标准写法

SCR1 真实例子: LSU 命令寄存器 (scr1_pipe_lsu.sv:142-148)
// always_ff @(posedge clk, negedge rst_n) = 带异步复位的寄存器
always_ff @(posedge clk, negedge rst_n) begin
    if (~rst_n) begin                        // 复位 (低有效)
        lsu_cmd_ff <= SCR1_LSU_CMD_NONE;        // 复位值
    end else if (lsu_cmd_upd) begin          // 更新使能
        lsu_cmd_ff <= exu2lsu_cmd_i;            // 锁存新值
    end
end
always_ff 必须使用的敏感信号格式
写法含义适用场景
@(posedge clk)仅上升沿触发，无复位FPGA RAM、简单计数器
@(posedge clk, negedge rst_n)上升沿 + 异步复位 (低有效)绝大多数 SCR1 寄存器
@(posedge clk) + if(rst)同步复位 (复位只在时钟沿生效)FPGA 推荐 (SCR1 未使用)

4.2 阻塞赋值 (=) vs 非阻塞赋值 (<=)

这是初学者最容易出错的地方:

= (阻塞赋值)<= (非阻塞赋值)
用于组合逻辑 (always_comb)时序逻辑 (always_ff)
执行顺序立即执行，一行完后才执行下一行所有右侧先采样，时钟沿后统一更新左侧
类比串联: A更新 → B 立刻看到 A 的新值并联: A更新 和 B更新 同时发生
混用错误 (always_ff 中用 =)
always_ff @(posedge clk) begin
    a = b;       // 阻塞赋值!
    c = a;       // a 已经是新值 = b!
end
// 结果: a=b, c=b (c 拿到了本周期的新 a)
正确写法 (always_ff 中用 <=)
always_ff @(posedge clk) begin
    a <= b;      // 非阻塞赋值
    c <= a;      // a 还是旧值!
end
// 结果: a=b, c=上一拍的a (正确!)
记忆口诀
组合用 = ，时序用 <= 。永远不要混用。
every always_comb → = ; every always_ff → <=

第5课: 有限状态机 FSM —— SCR1 中最经典的模式

FSM 是数字设计的核心。SCR1 中几乎每个控制模块都使用了 FSM。我们以 IFU 和 LSU 为例，学习 SCR1 的标准三段式写法。

SCR1 真实例子: LSU 的 2 状态 FSM (scr1_pipe_lsu.sv)
// ====== 第1段: 状态寄存器 (时序逻辑) ======
always_ff @(posedge clk, negedge rst_n) begin
    if (~rst_n) begin
        lsu_fsm_curr <= SCR1_LSU_FSM_IDLE;       // 复位 → IDLE
    end else begin
        lsu_fsm_curr <= lsu_fsm_next;             // 下一状态 → 当前状态
    end
end

// ====== 第2段: 次态逻辑 (组合逻辑) ======
always_comb begin
    case (lsu_fsm_curr)
        SCR1_LSU_FSM_IDLE: begin
            if (dmem_req_vd)                          // 收到访存请求
                lsu_fsm_next = SCR1_LSU_FSM_BUSY;      // → BUSY
            else
                lsu_fsm_next = SCR1_LSU_FSM_IDLE;       // → 保持 IDLE
        end
        SCR1_LSU_FSM_BUSY: begin
            if (dmem_resp_received)                   // 收到存储器响应
                lsu_fsm_next = SCR1_LSU_FSM_IDLE;       // → IDLE
            else
                lsu_fsm_next = SCR1_LSU_FSM_BUSY;       // → 保持 BUSY
        end
    endcase
end

// ====== 第3段: 输出逻辑 或者 并行的 assign ======
assign lsu_fsm_idle = (lsu_fsm_curr == SCR1_LSU_FSM_IDLE);
// 在 always_comb 中根据 lsu_fsm_curr 生成控制信号...
SCR1 FSM 三段式标准模板
1 状态寄存器: always_ff → fsm_curr <= fsm_next (时序)
2 次态逻辑: always_comb → case(fsm_curr) → 计算 fsm_next (组合)
3 输出逻辑: always_comb 或 assign → 根据当前状态生成控制信号 (组合)
SCR1 FSM 信号命名约定
信号后缀含义示例
_curr当前状态 (寄存器输出)ifu_fsm_curr
_next下一状态 (组合逻辑输出)ifu_fsm_next
_ff寄存器输出 (flip-flop)lsu_cmd_ff

第6课: 条件编译 —— 一套代码适配多种配置

SCR1 支持 MAX/BASE/MIN 三种配置，且可选 AHB/AXI 总线、FPGA/ASIC 目标平台。这一切都通过条件编译宏实现，而不需要维护多套代码。

SCR1 真实例子: 条件编译的三种用法 (scr1_pipe_ifu.sv)
// 用法1: `ifdef 控制端口存在与否
`ifdef SCR1_DBG_EN
    input  logic   hdu2ifu_pbuf_fetch_i,   // 只有调试使能时才有这个端口
    output logic   ifu2hdu_pbuf_rdy_o,
`endif // SCR1_DBG_EN

// 用法2: `ifdef 控制内部信号
`ifdef SCR1_NO_DEC_STAGE
    type_scr1_bypass_e   instr_bypass_type;      // 无译码级才需要的信号
`endif

// 用法3: 配置宏定义在头文件中 (scr1_arch_description.svh)
`define SCR1_DBG_EN          // 使能调试子系统
`define SCR1_RVM_EXT         // 使能乘除法扩展
`define SCR1_IPIC_EN         // 使能中断控制器
// `define SCR1_TCM_EN         // 禁用 TCM (注释掉即禁用)
三个编译指令的职责
指令作用SCR1 中的例子
`define MACRO定义一个宏 (开关)`define SCR1_RVM_EXT
`ifdef MACRO ... `endif如果宏已定义，包含这段代码`ifdef SCR1_DBG_EN
`include "file.svh"包含另一个文件 (类似 C 的 #include)`include "scr1_memif.svh"

注意: 宏之间的依赖顺序很重要。比如 SCR1_IPIC_EN 依赖于 SCR1_RVI_EXT，SCR1 在 scr1_arch_description.svh 中集中管理这些依赖。

第7课: generate —— 用代码生成硬件

当需要根据参数重复生成相似的硬件结构时，generate 是关键工具。SCR1 在 MPRF 中用它来适配 RAM 和分布式逻辑两种实现。

SCR1 真实例子: MPRF 的双路实现选择 (scr1_pipe_mprf.sv:90-152)
`ifdef SCR1_MPRF_RAM
// ====== 路径A: 用 FPGA 内嵌 RAM 块实现 (带写优先逻辑) ======
always_ff @(posedge clk) begin
    rs1_data_ff <= mprf_int[exu2mprf_rs1_addr_i];   // 同步读出
end
always_ff @(posedge clk) begin
    if (wr_req_vd) begin
        mprf_int[exu2mprf_rd_addr_i] <= exu2mprf_rd_data_i; // 写操作
    end
end

`else  // 路径B: 用分布式逻辑实现 (异步读出)
assign mprf2exu_rs1_data_o = rs1_addr_vd ? mprf_int[exu2mprf_rs1_addr_i] : '0;
`endif

这段代码的精妙之处: 同一个寄存器文件 (mprf_int)，根据 SCR1_MPRF_RAM 宏，自动选择:

  • FPGA 上: 使用内嵌 RAM 块 (面积小、速度快)，但需要同步读出 + 写优先旁路逻辑
  • ASIC/仿真: 使用分布式寄存器 (代码最简单)，异步读出无需额外逻辑
generate vs ifdef
generate 用于需要参数化生成多个实例的场景 (如 genvar 循环)，SCR1 中较少使用。
`ifdef/`else 用于编译期二选一，SCR1 大量使用这种方式切换实现路径。
MPRF 示例中的 `ifdef SCR1_MPRF_RAM 就属于 `ifdef 用法，不是真正的 generate。

第8课: 信号命名规范 —— SCR1 的代码为什么这么好读

SCR1 接口信号命名模板
<源模块>2<目标模块>_<信号名>_<方向后缀>
元素含义示例
源模块信号从哪里来exu, idu, mprf
2"to" 的缩写，读作 "to"--
目标模块信号到哪里去ifu, idu, csr
信号名这个信号做什么pc_new, rdy, instr
_iinput (本模块视角的输入)dmem2lsu_rdata_i
_ooutput (本模块视角的输出)lsu2exu_rdy_o
实战解读: 看信号名就能还原拓扑
信号名自动解读
exu2ifu_pc_new_req_o在 EXU 模块的输出端口，通知 IFU 有新的 PC 请求
mprf2exu_rs1_data_o在 MPRF 模块的输出端口，给 EXU 的 rs1 数据
hdu2exu_dbg_halted_o在 HDU 模块的输出端口，告诉 EXU 调试暂停了
dmem2lsu_rdata_i在 LSU 模块的输入端口，来自 DMEM 的读数据

有了这个命名规范，你在任何一个模块中看到 xxx2yyy_signal_i，立刻就知道: "我 (当前模块) 正在接收 xxx 发来的 signal 信号"。完全不需要查文档或画连线图。

第9课: 高级语法速览 —— SCR1 中用到的其他 SystemVerilog 特性

9.1 位拼接 { } 与位选择 [ ]

SCR1 用法
logic [31:0] word;
logic [15:0] lo = word[15:0];        // 位选择: 取低16位
logic [31:0] merged = {hi, lo};       // 位拼接: {16bits, 16bits} = 32bits
logic [31:0]  replicated = {4{byte}};  // 位复制: byte 重复4次 = 32位

9.2 缩减运算符 (Reduction Operators)

SCR1 真实例子: MPRF 的地址有效性判断 (scr1_pipe_mprf.sv:71)
assign  rs1_addr_vd = |exu2mprf_rs1_addr_i;     // | = 按位 OR 缩减
// 等价于: rs1_addr_vd = (addr != 5'b00000)
// 如果 addr 的任意位=1，结果=1; 全零则=0

assign  wr_req_vd   = exu2mprf_w_req_i & |exu2mprf_rd_addr_i;
// 写请求 & rd地址非零 → 有效的写请求 (rd=x0 时不写)
运算符含义示例
&a所有位按位与&4'b1101 = 0
|a所有位按位或|4'b0000 = 0
^a所有位按位异或 (奇偶)^4'b1101 = 1

9.3 signed (有符号) 处理

SCR1 用法
logic signed [31:0] s_val;   // 有符号 32 位整数
$signed(unsigned_val);        // 强制类型转换为有符号
$unsigned(signed_val);        // 强制类型转换为无符号

// SCR1 IALU 中比较指令的核心逻辑
assign ge = ~slt;                       // >=  等价于 ~(<)
assign ltu = ~($unsigned(op1) >= $unsigned(op2));  // 无符号比较

9.4 SystemVerilog 断言 (SVA)

SCR1 真实例子: MPRF 写操作检查 (scr1_pipe_mprf.sv:159-162)
// 仿真时检查写数据不能有未知态 (X 或 Z)
SCR1_SVA_MPRF_WRITEX : assert property (
    @(negedge clk) disable iff (~rst_n)
    exu2mprf_w_req_i |-> !$isunknown({exu2mprf_rd_addr_i, exu2mprf_rd_data_i})
) else $error("MPRF error: unknown values");

这段断言的含义: 每当写请求有效 (exu2mprf_w_req_i)，必须确保写地址和写数据中没有 X 态。如果有，仿真器报错。|-> 读作 "如果前件成立，则后件必须在同一周期成立"。

总结: SystemVerilog 语法速查表

语法作用SCR1 中的典型位置
module name (...); ... endmodule定义硬件模块所有的 .sv 文件
input/output logic端口方向声明每个 module 的前 30 行
logic [WIDTH-1:0]声明位宽信号全部信号声明
localparam X = value;模块内部常量IFU 的队列参数
typedef enum logic {...} type_e;定义枚举状态机状态、操作码、命令
typedef struct packed {...} type_s;定义结构体EXU 命令结构体
assign signal = expression;简单组合逻辑LSU 响应判断
always_comb begin ... end复杂组合逻辑IDU 译码、EXU 仲裁
always_ff @(posedge clk, negedge rst_n)带异步复位的时序逻辑绝大多数寄存器
= (阻塞赋值)组合逻辑赋值always_comb 内部
<= (非阻塞赋值)时序逻辑赋值always_ff 内部
{a, b}位拼接指令拼接、数据拼接
|signal缩减 OR (任意位=1?)MPRF 地址有效性判断
`define MACRO定义编译宏scr1_arch_description.svh
`ifdef MACRO ... `endif条件编译IFU、LSU 的调试/配置开关
`include "file.svh"包含头文件每个模块文件的开头
case (expr) ... endcase多路选择FSM 次态逻辑、译码逻辑
assert property (...)仿真断言MPRF 写操作检查
