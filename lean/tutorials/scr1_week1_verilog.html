第1课: module —— 硬件设计的基本单元

在 SystemVerilog 中，一切硬件设计都封装在 module 里。可以把 module 理解为一个"芯片"——它定义了这个硬件的输入输出接口（input/output）和内部实现逻辑。

SCR1 真实例子: scr1_pipe_lsu.sv (加载存储单元, 351行)
// 模块声明: 名称 + 端口列表
module scr1_pipe_lsu (
    // ---- 时钟与复位 ----
    input   logic                    rst_n,           // 复位 (低有效)
    input   logic                    clk,             // 时钟

    // ---- EXU <-> LSU 接口 ----
    input   logic                    exu2lsu_req_i,   // 访存请求
    input   type_scr1_lsu_cmd_sel_e  exu2lsu_cmd_i,   // 访存命令 (枚举类型)
    output  logic                    lsu2exu_rdy_o,   // LSU 就绪
    output  logic [31:0]             lsu2exu_ldata_o  // 加载数据 (32位)
);

// ====== 内部信号声明 ======
logic  lsu_cmd_upd;   // 命令更新使能
logic  dmem_resp_ok;  // 存储器响应: OK

// ====== 内部逻辑 ======
assign dmem_resp_ok = (dmem2lsu_resp_i == SCR1_MEM_RESP_RDY_OK);

endmodule : scr1_pipe_lsu

源文件: src/core/pipeline/scr1_pipe_lsu.sv:30-61 (端口声明) / 114 (assign 逻辑)

三层结构: 每个 module 都遵循这个模式
1 端口声明: 定义输入 input 和输出 output，这是模块与外界的连接点
2 内部信号: 在模块内部使用的导线和寄存器，如 logic lsu_cmd_upd
3 逻辑实现: assign (组合逻辑) + always_ff (时序逻辑) + always_comb (组合逻辑)
Verilog 旧写法 (不推荐)
input wire clk
output reg [7:0] data
SystemVerilog 推荐写法
input logic clk
output logic [7:0] data

SystemVerilog 用统一的 logic 类型替代了 wire/reg 的双轨制，编译器会自动判断是组合还是时序。

wire vs logic vs reg 对比 (以 SCR1 实际用法为准)
类型含义能否被过程赋值 (always_ff/always_comb)能否被连续赋值 (assign)SCR1 中的实际用法
wire 传统 Verilog 网线类型 不能 能 SCR1 几乎不用，仅在 scr1_pipe_hdu.sv 的个别 generate 块中用于参数化连线
logic SV 统一类型, 最常用 能 能 SCR1 全部模块的默认选择: logic rst_n(lsu:32)、logic [31:0] lsu2exu_ldata_o(lsu:41)、所有内部信号
reg 传统 Verilog 寄存器类型 能 不能 SCR1 完全不用，全部被 logic 替代

关键结论: SCR1 采用 logic 一统天下，只需区分方向——input logic 和 output logic 是端口的主宰。即使内部信号需要被多个驱动源赋值，SCR1 也通过结构化设计避免了信号冲突，而非依赖 wire 的多驱动特性。

2.2 packed array (打包数组) vs unpacked array (非打包数组) —— SCR1 MPRF 中的关键区别

SCR1 真实例子: MPRF 寄存器的两种数组形态 (scr1_pipe_mprf.sv:52-64)
// ====== packed array (打包数组): 连续位存储 ======
logic [`SCR1_XLEN-1:0]    mprf_int   [1:`SCR1_MPRF_SIZE-1];
// 类型 = logic [31:0] mprf_int [1:31] —— 即 31 个 32 位寄存器
// 每个元素是 32 位宽，整体是一个存储器阵列

// mprf_int 的每次索引访问返回 32 位数据:
assign mprf2exu_rs1_data_o = mprf_int[exu2mprf_rs1_addr_i];  // 读操作 (133行)
always_ff @(posedge clk) begin
    mprf_int[exu2mprf_rd_addr_i] <= exu2mprf_rd_data_i;        // 写操作 (142行)
end

源文件: src/core/pipeline/scr1_pipe_mprf.sv:52-64, 133-142

packed/unpacked 的核心区别:

特性logic [31:0] a; (packed)logic a [0:31]; (unpacked)
存储连续 32 位, 可整体按位操作32 个独立位, 不可整体按位操作
位选择a[5:3] 取出 3 位a[5] 只能取 1 位, 不能取多位
SCR1 用法所有总线、寄存器的默认方式几乎不用; MPRF 的 RAM 阵列是 logic [31:0] arr[1:31]——元素是 packed, 整体是 unpacked
综合综合为连续位向量综合为独立寄存器/存储器
MPRF RAM 双副本设计: 写优先的经典实现

MPRF 在 RAM 模式下使用 两份 RAM 副本 (mprf_int 和 mprf_int2, mprf.sv:53-60), 因为需要同时支持 3 个独立操作:

  • rs1_data_ff <= mprf_int[rs1_addr] — 同步读 rs1 (116行)
  • rs2_data_ff <= mprf_int2[rs2_addr] — 同步读 rs2 (117行)
  • mprf_int[rd_addr] <= rd_data — 写入 rd (123行, 同时写入 int 和 int2)

写优先逻辑 (mprf.sv:100-106): 检测到读写地址冲突时, 旁路输出刚写入的数据 rd_data_ff, 而不是从 RAM 中读出的旧值。

2.3 位宽陷阱: [MSB:LSB] vs [LSB:MSB]

位宽陷阱: [MSB:LSB] vs [LSB:MSB]
logic [31:0] 和 logic [0:31] 都是 32 位，但 bit 编号方向相反。SCR1 统一使用 [MSB:0] 风格。
例: logic [31:0] a; → a[31] 是最高位, a[0] 是最低位。
使用 +: / -: 变址选择 (mprf.sv:71-72, 缩减操作符 |exu2mprf_rs1_addr_i) 可以避免固定位宽硬编码。

3.3 assign vs always_comb: 什么时候用哪个

assignalways_comb
一行能写完的逻辑 需要多行或 case 的逻辑
assign lsu_fsm_idle = (lsu_fsm_curr == SCR1_LSU_FSM_IDLE); (lsu.sv:191) 例外: 直接比较赋值优先用 assign
assign dmem_resp_received = dmem_resp_ok | dmem_resp_er; (lsu.sv:116) always_comb case(fsm_curr) ... endcase (lsu.sv:178-189)
赋值左侧的网线信号是组合的连续驱动 必须给所有输出赋默认值, 否则综合出 latch
always_comb 必须避免 latch
必须在块开头给所有输出赋默认值。SCR1 的习惯: 在 always_comb begin 后第一件事就是把所有输出信号清零 (如 idu.sv:96-100 对 idu2exu_cmd_o 所有字段设默认值)。看不到这个习惯的代码几乎一定有 latch bug。
错误写法 (产生 latch)
always_comb
  if(en) y = a;
  // 缺少 else!
  // en=0 时 y 保持原值 = latch
正确写法 (纯组合, SCR1 风格)
always_comb begin
  y = '0;     // 先设默认值
  if(en) y = a; // 再设特殊情况
end

第4课: 时序逻辑 —— always_ff 与非阻塞赋值 (深度解析)

时序逻辑的特征: 有记忆，输出取决于当前输入 + 历史状态。信号只在时钟边缘更新，对应硬件 D 触发器。

4.2 always_comb vs always_ff 时序行为对照

组合 vs 时序: 同一信号的两面视角

同一个 logic 信号, 在 always_comb 和 always_ff 中的行为完全不同:

// 组合逻辑: dmem_cmd_load 随输入即时变化
assign dmem_cmd_load = (exu2lsu_cmd_i == SCR1_LSU_CMD_LB) | ...;  // lsu.sv:120-124

// 时序逻辑: lsu_cmd_ff 仅在时钟沿更新
always_ff @(posedge clk, negedge rst_n) begin                    // lsu.sv:142-148
    if (~rst_n) lsu_cmd_ff <= SCR1_LSU_CMD_NONE;
    else if (lsu_cmd_upd) lsu_cmd_ff <= exu2lsu_cmd_i;
end
信号类型与 excu2lsu_cmd_i 的关系更新时机
dmem_cmd_load组合始终等于 decode(exu2lsu_cmd_i)输入变化后 delta 时间
lsu_cmd_ff时序等于上一拍 exu2lsu_cmd_i (当 upd=1 时)仅在 posedge clk

4.3 always_ff 敏感信号格式速查

always_ff 必须使用的敏感信号格式
写法含义适用场景SCR1 实例

4.4 阻塞赋值 (=) vs 非阻塞赋值 (<=) —— 深挖信号传递链

= (阻塞赋值)<= (非阻塞赋值)
用于组合逻辑 (always_comb)时序逻辑 (always_ff)
执行顺序立即执行，一行完后才执行下一行所有右侧先采样，时钟沿后统一更新左侧

SCR1 跨模块信号传递链: 非阻塞赋值在流水线中的作用

SCR1 的流水级通过 always_ff 寄存器分隔, 形成 组合→时序→组合→时序 的信号链:

// IDU stage (组合): 译码生成 exu_cmd_s
always_comb begin   // idu.sv:95
    idu2exu_cmd_o.ialu_op  = SCR1_IALU_OP_REG_REG;   // = 阻塞赋值
    idu2exu_cmd_o.ialu_cmd = SCR1_IALU_CMD_NONE;      // = 阻塞赋值
end

// EXU stage (时序): 锁存命令
always_ff @(posedge clk, negedge rst_n) begin   // exu.sv (内部)
    exu_cmd_ff <= idu2exu_cmd_i;                      // <= 非阻塞: 这拍的组合结果, 下拍才生效
end

如果 EXU 中误用 =: exu_cmd_ff = idu2exu_cmd_i —— 仿真中 exu_cmd_ff 会立刻更新, 导致本拍就执行错误指令。

混用错误 (always_ff 中用 =)
always_ff @(posedge clk) begin
    a = b;       // 阻塞赋值!
    c = a;       // a 已经是新值 = b!
end
正确写法 (always_ff 中用 <=)
always_ff @(posedge clk) begin
    a <= b;      // 非阻塞赋值
    c <= a;      // a 还是旧值!
end
记忆口诀
组合用 = ，时序用 <= 。永远不要混用。
every always_comb → = ; every always_ff → <=
