一、为什么学 RISC-V (源码: scr1_arch_description.svh)

本课程目标
理解 SCR1 能执行的所有指令，阅读 RISC-V 汇编代码，知道每条指令在 SCR1 硬件中经历了哪些模块。

RISC-V 由 UC Berkeley 于 2010 年发布，设计哲学是精简、模块化、可扩展。与 x86 上千条指令不同，RV32I 基础整数指令集仅 40 条。SCR1 支持的扩展:

扩展全称指令数说明
RV32IBase Integer40基础整数集，所有 RISC-V 核必须实现
RV32EEmbedded40仅 16 个寄存器，嵌入式精简版 (SCR1 可选)
MMultiply/Divide8整数乘除 (SCR1_CFG_RV32IMC_MAX 含此扩展)
CCompressed~2616 位压缩指令，代码体积减少 25-30%

SCR1 三档配置: MIN=RV32EC (2级) / BASE=RV32IC (3级) / MAX=RV32IMC (4级)。

SCR1 源码线索
打开 src/includes/scr1_arch_description.svh，搜索 SCR1_RVM_EXT 和 SCR1_RVC_EXT —— 编译宏控制 M/C 扩展开关。各模块通过 `ifdef SCR1_RVM_EXT 等条件编译选择是否包含乘除法硬件。

为什么分"调用者保存"和"被调用者保存"?

假设函数 A 调用函数 B。A 用 t0 存了重要数据，B 可能也会用 t0。如果 A 在调用 B 之前不保存 t0，B 返回后 t0 就被破坏了。但 s0-s11 不同: B 承诺"我如果用，走之前会恢复"。

这种分工减少不必要的保存/恢复: 临时变量用 t 寄存器 (只在使用者需要时才保存)，跨函数变量用 s 寄存器 (保证不被破坏)。

x0 硬连线零 -- MPRF 的实现 (scr1_pipe_mprf.sv:71-74)

assign rs1_addr_vd = |exu2mprf_rs1_addr_i;  // |5'b00000 = 0 → 输出 '0
assign rs2_addr_vd = |exu2mprf_rs2_addr_i;  // |5'bxxxxx = 1 → 正常读
assign wr_req_vd   = exu2mprf_w_req_i & |exu2mprf_rd_addr_i;  // 写 x0 → addr=0 → wr_req_vd=0 → 抑制写入

关键: 寄存器数组从索引 1 开始 (mprf_int[1:31])，x0 不占物理存储。归约或 | 把 5 位地址全部或起来: 只有 5'b00000 得 0，其余都得 1。三行代码实现 x0 全部特性，不消耗额外硬件。

三、六大指令格式 R/I/S/B/U/J (译码: scr1_pipe_idu.sv)

RISC-V 只有 6 种基本格式。核心设计: rs1、rs2、rd 在所有格式中位位置固定 (bit 19-15, 24-20, 11-7)，译码器不需判断指令类型就能直接提取寄存器地址。

R-type: 寄存器-寄存器操作 (opcode=0110011)

| 31......25 | 24.....20 | 19.....15 | 14....12 | 11.......7 | 6......0 |
|   funct7   |    rs2    |    rs1    |  funct3  |     rd     |  opcode |
   7 bits       5 bits     5 bits      3 bits      5 bits       7 bits

三个寄存器均参与: rs1 和 rs2 是源操作数，rd 是目标。funct7 与 funct3 组合决定具体运算。例如: ADD 是 funct7=0000000+funct3=000，SUB 是 funct7=0100000+funct3=000 —— 同一个 funct3=000，靠 funct7 的最高位区分加法和减法。

包含: ADD, SUB, AND, OR, XOR, SLL, SRL, SRA, SLT, SLTU, MUL, DIV 等。

I-type: 立即数操作 (opcode=0010011/0000011/1100111)

| 31..............20 | 19.....15 | 14....12 | 11.......7 | 6......0 |
|     imm[11:0]      |    rs1    |  funct3  |     rd     |  opcode |
      12 bits           5 bits     3 bits      5 bits       7 bits

把一个 12 位立即数符号扩展到 32 位后与 rs1 运算，结果写入 rd。注意: I-type 也是 Load 和 JALR 的格式 —— opcode 区分功能 (OP-IMM / LOAD / JALR)。

包含: ADDI, ANDI, ORI, XORI, SLLI(只有低 5 位有效), SRLI, SRAI, SLTI, SLTIU, LW/LH/LB/LHU/LBU, JALR, CSR 指令系列。

S-type: 存储指令 (opcode=0100011) -- 详细解析

| 31......25 | 24.....20 | 19.....15 | 14....12 | 11.......7 | 6......0 |
|  imm[11:5] |    rs2    |    rs1    |  funct3  |  imm[4:0]  |  opcode |
   7 bits       5 bits     5 bits      3 bits      5 bits       7 bits

S-type 只有 3 条: SB (存字节, funct3=000), SH (存半字, funct3=001), SW (存字, funct3=010)。共同点是: 没有 rd 字段 (bit 11-7 借给立即数低位)，存储不写寄存器。

立即数拼接: 为什么要拆成两段?

imm = {instr[31:25], instr[11:7]}   // = imm[11:5] + imm[4:0]
       高 7 位       低 5 位

不是乱切的 -- 看 R-type 的同位置: bit 31-25 是 funct7, bit 11-7 是 rd。S-type 不写寄存器, 这两个字段正好借给立即数。这样 rs1/rs2/funct3/opcode 六种格式完全对齐, 硬件译码极度简洁。

IDU 译码 S-type (scr1_pipe_idu.sv:206-223)

SCR1_OPCODE_STORE : begin
    idu2exu_use_rs1_o  = 1'b1;      // rs1 = 基地址
    idu2exu_use_rs2_o  = 1'b1;      // rs2 = 存储数据
    idu2exu_cmd_o.imm  = {{21{instr[31]}}, instr[30:25], instr[11:7]};
    case (funct3)
        3'b000: lsu_cmd = SCR1_LSU_CMD_SB;  // 字节
        3'b001: lsu_cmd = SCR1_LSU_CMD_SH;  // 半字
        3'b010: lsu_cmd = SCR1_LSU_CMD_SW;  // 字
    endcase
end

LSU 未对齐检查 (scr1_pipe_lsu.sv:206-209)

assign dmem_addr_mslgn = exu2lsu_req_i & (
    (dmem_wdth_hword & exu2lsu_addr_i[0])              // SH 地址 bit0 必须为 0
  | (dmem_wdth_word  & |exu2lsu_addr_i[1:0])       // SW 地址 bit1:0 必须为 00
);

半字必须对齐到 2 字节边界 (bit0=0)，字必须对齐到 4 字节边界 (bit1:0=00)。字节无对齐要求。RISC-V 不强制自然对齐，但 SCR1 选择抛出异常而非支持未对齐访问。

S-type 数据流: 一条 SW 指令的旅程

1IFU: 根据 PC 从 IMEM 取指令 → 入队列 → 判断为 RV32I (instr[1:0]=11)
2IDU: opcode=0100011 → STORE 分支。从 instr[19:15] 取 rs1_addr, instr[24:20] 取 rs2_addr, 拼接 imm
3EXU: 同时读 MPRF -- rs1 输出给地址加法器, rs2 输出给 LSU 的写数据通路
4EXU sum2 加法器: dmem_addr = rs1_data + imm (地址计算)
5LSU: 检查未对齐 → 无异常 → 发 DMEM 写请求: cmd=WR, addr=计算地址, wdata=rs2_data
6写回阶段: SW 不写寄存器 → rd_wb_sel=NONE → MPRF 无写入

B-type: 条件分支 (opcode=1100011)

| 31......25 | 24.....20 | 19.....15 | 14....12 | 11.......7 | 6......0 |
|imm[12|10:5]|    rs2    |    rs1    |  funct3  |imm[4:1|11]|  opcode |
   7 bits       5 bits     5 bits      3 bits      5 bits       7 bits

立即数被切成 4 段 (imm[12]+imm[10:5]+imm[4:1]+imm[11])。B-type 偏移总是 2 字节对齐 (imm[0] 固定为 0, 不编码), 所以实际范围是 ±4KB。6 条指令: BEQ, BNE, BLT, BGE, BLTU, BGEU。

分支在 SCR1 硬件中的处理 (scr1_pipe_exu.sv)

IALU 用减法计算 rs1 - rs2, 同时产生 4 个比较标志位: eq, lt, ltu, ge, geu, ne。EXU 根据 funct3 选择对应标志:

unique case (exu2ialu_cmd_o)
    SCR1_IALU_CMD_SUB_EQ: beq = rs1_eq;
    SCR1_IALU_CMD_SUB_LT: blt = rs1_lt;
    SCR1_IALU_CMD_SUB_LTU: bltu = rs1_ltu;
    // ...
endcase

条件成立 → new_pc_req → IFU 更新 PC → 清空流水线 (flush)。不成立 → PC+4 照常递增。

U-type: 高位立即数 (opcode=0110111/0010111)

| 31...................................12 | 11.......7 | 6......0 |
|              imm[31:12]                 |     rd     |  opcode |
               20 bits                      5 bits       7 bits

20 位立即数左移 12 位, 无 rs1 和 rs2。仅 2 条: LUI (rd = imm<<12) 和 AUIPC (rd = PC + imm<<12)。RISC-V 没有单条"加载 32 位常数"指令, 需 LUI+ADDI 配合: LUI x5, 0x12345 然后 ADDI x5, x5, 0x678 → x5=0x12345678。

J-type: 无条件跳转 (opcode=1101111)

| 31......25 | 24.....20 | 19.....15 | 14....12 | 11.......7 | 6......0 |
|imm[20|10:1|11|19:12]|          rd          |  opcode |
   7 bits       5 bits     5 bits      3 bits      5 bits       7 bits

仅 1 条: JAL。rd=PC+4 (链接返回地址), PC=PC+offset。offset 范围 ±1MB。JALR (I-type) 是间接跳转: PC = (rs1+imm)&~1, 最低位强制清零保证 2 字节对齐。

九、RVC 压缩指令 (译码: scr1_pipe_idu.sv, 取指: scr1_pipe_ifu.sv)

RVC 将最常用的 RV32I 指令编码为 16 位。核心思想: 在 IDU 译码阶段展开为等效的 RVI 32 位指令，后续流水线完全不用改动。

IFU 的 RVC 处理: 如何区分 16 位和 32 位指令?

IFU 的指令队列是 4x16 位环形缓冲。每个半字到达时, 检查 instr[1:0]:

  • 11 → 这是 32 位 RV32I 指令的低半部, 需要与下一个半字拼接
  • 00/01/10 → 这是独立的 16 位 RVC 指令

源码: src/core/pipeline/scr1_pipe_ifu.sv, 搜索 SCR1_INSTR_RVI / SCR1_INSTR_RVC。

C.MV 的巧妙之处

C.MV rd, rs2 在 RVI 中编码为 ADD rd, x0, rs2 —— 任何数 + 0 = 自身。这是 RISC-V 的经典微架构技巧: 复用现有加法器, 零开销实现。
