第一课: 为什么学 RISC-V？

本课程目标
理解 SCR1 处理器能执行的所有指令，能够阅读 RISC-V 汇编代码，知道每条指令在 SCR1 硬件中经历了哪些模块。

RISC-V 是一个 开源 的指令集架构（ISA），由加州大学伯克利分校于 2010 年发布。和 x86（Intel/AMD）、ARM 不同，RISC-V 的设计哲学是 精简、模块化、可扩展。

SCR1 处理器支持的 RISC-V 子集:

扩展全称指令数说明
RV32IBase Integer40 条基础整数指令集，所有 RISC-V 处理器必须实现
RV32EEmbedded40 条嵌入式精简版（仅 16 个寄存器），SCR1 可选
MMultiply/Divide8 条整数乘除法扩展（MUL, DIV, REM 等）
CCompressed约 26 条16 位压缩指令，让代码体积减少 25%-30%

SCR1 预定义了三档配置:

  • MIN: RV32EC (2 级流水线，最小面积)
  • BASE: RV32IC (3 级流水线，平衡)
  • MAX: RV32IMC (4 级流水线，完整功能)
SCR1 源码线索
打开 src/includes/scr1_arch_description.svh，搜索 SCR1_RVM_EXT 和 SCR1_RVC_EXT 宏定义，可以看到编译开关如何控制指令扩展的启用。

第三课: 六大指令格式 R/I/S/B/U/J

RISC-V 只有 6 种基本指令格式，比 x86（上千种格式）精简得多。所有 32 位指令都用这 6 种编码:

R-type: 寄存器-寄存器操作 (opcode = 0110011) 
| 31......25 | 24.....20 | 19.....15 | 14....12 | 11.......7 | 6......0 |
|   funct7   |    rs2    |    rs1    |  funct3  |     rd     |  opcode |
   7 bits       5 bits     5 bits      3 bits      5 bits       7 bits

用途: ADD rd, rs1, rs2 —— rd = rs1 + rs2

包含: ADD, SUB, AND, OR, XOR, SLL, SRL, SRA, SLT, SLTU, MUL, DIV 等

I-type: 立即数操作 (opcode = 0010011 / 0000011 / 1100111) 
| 31..............20 | 19.....15 | 14....12 | 11.......7 | 6......0 |
|     imm[11:0]      |    rs1    |  funct3  |     rd     |  opcode |
      12 bits           5 bits     3 bits      5 bits       7 bits

用途: ADDI rd, rs1, imm —— rd = rs1 + imm

包含: ADDI, ANDI, ORI, XORI, SLLI, SRLI, SRAI, SLTI, LW, JALR, CSR 指令

S-type: 存储指令 (opcode = 0100011) 
| 31......25 | 24.....20 | 19.....15 | 14....12 | 11.......7 | 6......0 |
|  imm[11:5] |    rs2    |    rs1    |  funct3  |  imm[4:0]  |  opcode |
   7 bits       5 bits     5 bits      3 bits      5 bits       7 bits

用途: SW rs2, offset(rs1) —— MEM[rs1+offset] = rs2

包含: SW, SH, SB

B-type: 条件分支 (opcode = 1100011) 
| 31......25 | 24.....20 | 19.....15 | 14....12 | 11.......7 | 6......0 |
|imm[12|10:5]|    rs2    |    rs1    |  funct3  |imm[4:1|11]|  opcode |
   7 bits       5 bits     5 bits      3 bits      5 bits       7 bits

用途: BEQ rs1, rs2, offset —— if rs1==rs2 then PC = PC+offset

包含: BEQ, BNE, BLT, BGE, BLTU, BGEU

U-type: 高位立即数 (opcode = 0110111 / 0010111) 
| 31...................................12 | 11.......7 | 6......0 |
|              imm[31:12]                 |     rd     |  opcode |
               20 bits                      5 bits       7 bits

用途: LUI rd, imm —— rd = imm << 12 (高 20 位写入，低 12 位清零)

包含: LUI, AUIPC

J-type: 无条件跳转 (opcode = 1101111) 
| 31......25 | 24.....20 | 19.....15 | 14....12 | 11.......7 | 6......0 |
|imm[20|10:1|11|19:12]|          rd          |  opcode |
   7 bits       5 bits     5 bits      3 bits      5 bits       7 bits

用途: JAL rd, offset —— rd = PC+4; PC = PC+offset

包含: JAL

为什么立即数要打乱？
看起来立即数字段被切得很散（尤其是 S-type 和 B-type），这是为了 简化硬件译码。所有格式的 rs1、rs2、rd 字段都在相同位置（bit 19-15, 24-20, 11-7），译码器不用判断指令类型就能直接提取寄存器地址。这就是 RISC-V "精简"哲学的体现 —— 用编码复杂度换取硬件简洁性。

如何加载 32 位立即数？
RISC-V 没有单条 "加载 32 位常数" 指令，需要两条配合:
LUI x5, 0x12345 → x5 = 0x12345000
ADDI x5, x5, 0x678 → x5 = 0x12345678
（这是一个经典面试题: LUI + ADDI 组合，注意 ADDI 的立即数是有符号 12 位的，会有符号扩展干扰。实际用伪指令 LI，汇编器自动处理。）

SCR1 中的乘除法实现

SCR1_FAST_MUL: 单周期乘法器（用 FPGA DSP 块），速度快但面积大
默认: 32 周期迭代乘法器（移位加），面积小但慢
除法器始终是 33 周期的非恢复除法算法，不支持单周期。

第五课: 访存指令

RISC-V 是 Load-Store 架构: 只有 Load/Store 指令可以访问内存，ALU 指令只能操作寄存器。

加载指令 (I-type)

指令操作说明
LW rd, offset(rs1)rd = MEM[rs1 + offset] (32 位)加载字
LH rd, offset(rs1)rd = 符号扩展(MEM[rs1 + offset]) (16 位)加载半字, 有符号
LHU rd, offset(rs1)rd = 零扩展(MEM[rs1 + offset]) (16 位)加载半字, 无符号
LB rd, offset(rs1)rd = 符号扩展(MEM[rs1 + offset]) (8 位)加载字节, 有符号
LBU rd, offset(rs1)rd = 零扩展(MEM[rs1 + offset]) (8 位)加载字节, 无符号

存储指令 (S-type)

指令操作说明
SW rs2, offset(rs1)MEM[rs1 + offset] = rs2 (32 位)存储字
SH rs2, offset(rs1)MEM[rs1 + offset] = rs2[15:0] (16 位)存储半字
SB rs2, offset(rs1)MEM[rs1 + offset] = rs2[7:0] (8 位)存储字节
一条 SW 指令在 SCR1 中的旅程
1 IFU: 根据 PC 从指令存储器取出指令字，放入指令队列
2 IDU: 解析 opcode=0100011, funct3 确定是 SW → 生成 lsu_cmd=SW
3 EXU: 从 MPRF 读出 rs1_data (基址) 和 rs2_data (存储数据)
4 IALU: sum2 加法器计算地址 = rs1 + imm
5 LSU: 向数据存储器发起写请求, addr=IALU 地址, wdata=rs2_data
6 写回阶段: SW 指令不写寄存器 (rd_wb_sel=NONE)

第六课: 分支与跳转

条件分支 (B-type)

指令条件说明
BEQ rs1, rs2, offsetrs1 == rs2相等则分支
BNE rs1, rs2, offsetrs1 != rs2不等则分支
BLT rs1, rs2, offsetrs1 < rs2 (有符号)小于则分支
BGE rs1, rs2, offsetrs1 >= rs2 (有符号)大于等于则分支
BLTU rs1, rs2, offsetrs1 < rs2 (无符号)无符号小于则分支
BGEU rs1, rs2, offsetrs1 >= rs2 (无符号)无符号大于等于则分支

无条件跳转

指令格式操作
JAL rd, offsetJrd = PC+4; PC = PC + offset
JALR rd, rs1, offsetIrd = PC+4; PC = (rs1 + offset) & ~1
JAL 和 JALR 的区别
JAL: 目标地址 = PC + 偏移（立即数编码在指令中），±1MB 范围
JALR: 目标地址 = 寄存器值 + 偏移，最低位强制清零（对齐到 2 字节）
两者都会把 PC+4 写入 rd，形成 "链接" —— 就是函数调用的返回地址。
JAL x0, offset 等价于无条件跳转（因为 x0 丢弃了返回值）。
JALR x0, ra, 0 等价于函数返回（ret 伪指令）。
分支指令在 SCR1 中的处理
条件分支在 EXU 中:
1. IALU 计算 rs1 - rs2，产生比较标志 (eq, lt, ltu, ge, geu, ne)
2. EXU 根据 funct3 选择对应的标志位
3. 如果条件成立: 产生 new_pc_req → IFU 更新 PC → 清空流水线 (flush)
4. 如果条件不成立: PC 照常递增 → 无 flush

源码: src/core/pipeline/scr1_pipe_exu.sv 中的 always_comb 块，搜索 SCR1_IALU_CMD_SUB_EQ。

第八课: CSR 控制状态寄存器

CSR (Control and Status Register) 是 RISC-V 的核心配置机制。SCR1 仅支持 M-mode，所以只有 M-mode CSR。

核心 CSR 寄存器速览

寄存器地址描述
MSTATUS0x300机器状态: MIE(全局中断使能), MPIE(先前中断使能), MPP(先前特权级)
MIE0x304中断使能: MSIE(软件), MTIE(定时器), MEIE(外部)
MIP0x344中断挂起: MSIP, MTIP, MEIP
MTVEC0x305陷阱向量基址 + 模式 (direct=00 / vectored=01)
MEPC0x341异常返回地址 (保存触发异常的 PC)
MCAUSE0x342异常原因: bit31=1中断, bit30:0=异常编号
MTVAL0x343异常附加值 (如未对齐地址、非法指令编码)
MISA0x301ISA 和扩展: MXL(XLEN编码) + Extensions 位掩码
MVENDORID0xF11厂商标识 (SCR1 为 0)
MARCHID0xF12架构标识
MIMPID0xF13实现标识
MHARTID0xF14硬件线程 ID

CSR 操作指令

指令操作
CSRRW rd, csr, rs1tmp=CSR[csr]; CSR[csr]=rs1; rd=tmp (原子读后写)
CSRRS rd, csr, rs1tmp=CSR[csr]; CSR[csr]=tmp|rs1; rd=tmp (读后置位)
CSRRC rd, csr, rs1tmp=CSR[csr]; CSR[csr]=tmp&~rs1; rd=tmp (读后清零)
CSRRWI rd, csr, zimm立即数版本的 CSRRW (rs1 字段用作 5 位无符号立即数)
CSRRSI rd, csr, zimm立即数版本的 CSRRS
CSRRCI rd, csr, zimm立即数版本的 CSRRC
CSR 的三种写命令 (SCR1 实现)
SCR1 CSR 模块支持三种原子写操作:
WRITE: CSR = wdata (直接覆盖)
SET: CSR = CSR | wdata (按位或，置位某些位)
CLEAR: CSR = CSR & ~wdata (按位清除)

源码: src/core/pipeline/scr1_pipe_csr.sv 中的 type_scr1_csr_cmd_sel_e 枚举。

第九课: RVC 压缩指令扩展

RVC (RISC-V Compressed) 将常用指令编码为 16 位，让代码体积减少约 25%-30%。在嵌入式场景中，这直接等于节省 Flash 成本。

关键设计: 所有 RVC 指令在译码阶段展开为对应的 32 位 RVI 指令，后续流水线完全不需要修改。SCR1 的 IDU 模块有专门的 RVC 解压缩逻辑:

// IDU 中的 RVC 处理: 将 16 位压缩指令展开为 32 位等价指令
if (instr_rvc) begin
    unique case (funct3)  // RVC funct3 在 bit[15:13]
        3'b000: // C.ADDI4SPN, C.FLD 等
        3'b010: // C.LW, C.SW 等
        // ... 根据 funct3 和 opcode 展开为对应 RVI 指令
    endcase
end
RVC 指令展开为说明
C.ADDI4SPN rd', immADDI rd', sp, imm栈指针 + 立即数, rd' 只有 s0-s1, a0-a5 (3位编码)
C.LW rd', offset(rs1')LW rd', offset(rs1')加载字, 寄存器子集
C.SW rs2', offset(rs1')SW rs2', offset(rs1')存储字, 寄存器子集
C.ADDI rd, immADDI rd, rd, immrd != x0
C.JAL offsetJAL x1, offset函数调用 (RV32 专用)
C.LI rd, immADDI rd, x0, imm加载小立即数
C.LUI rd, immLUI rd, immrd != {x0, x2}, imm != 0
C.ADDI16SP immADDI sp, sp, imm16 字节对齐的栈调整
C.JR rs1JALR x0, rs1, 0函数返回
C.JALR rs1JALR x1, rs1, 0间接函数调用
C.BEQZ rs1', offsetBEQ rs1', x0, offset等于零则分支
C.BNEZ rs1', offsetBNE rs1', x0, offset不等于零则分支
C.NOPADDI x0, x0, 0空操作 (是 C.ADDI 的特例)
IFU 中的 RVC 处理
RVC 的 16 位指令给取指带来了一个难题: 指令队列是 4x16 位，需要判断每个半字是独立的 RVC 指令还是 32 位指令的一半。
SCR1 IFU 的做法: 根据每个半字的 instr[1:0] 判断 —— 如果是 11，说明是 RVI 的低半部，需要与下一个半字拼接成 32 位。
源码: src/core/pipeline/scr1_pipe_ifu.sv，搜索 SCR1_INSTR_RVI。

第十课: 手工编码实战 -- 一条 ADDI 是怎么变成 32 位二进制数的

以 ADDI x5, x1, 10 为例，我们手工编码。

ADDI 编码过程
1 确定格式: ADDI 是 I-type, opcode = 0010011 (OP-IMM)
2 rd = x5 = 5 → bit[11:7] = 00101
3 funct3 = 000 (ADDI 的 funct3 是 0)
4 rs1 = x1 = 1 → bit[19:15] = 00001
5 imm = 10 = 0b000000001010 → bit[31:20] = 000000001010
6 opcode = 0010011 → bit[6:0]
最终编码:
000000001010 00001 000 00101 0010011
  imm[11:0]     rs1  f3    rd   opcode

= 0x00A28293

SCR1 的 IDU 看到这 32 位，译码过程:

// instr[1:0] = 11 → 这是 RV32I 指令
// instr[6:2] = 00100 → SCR1_OPCODE_OP_IMM
// instr[14:12] = 000 → funct3 → ADDI 操作
// instr[19:15] = 00001 → rs1 = x1
// instr[11:7]  = 00101 → rd = x5
// instr[31:20] = 0x00A → imm = 10 (有符号扩展)

exu_cmd.ialu_cmd  = SCR1_IALU_CMD_ADD;   // ALU 做加法
exu_cmd.ialu_op   = SCR1_IALU_OP_REG_IMM; // 操作数来自寄存器和立即数
exu_cmd.rs1_addr  = 1;                   // 读 x1
exu_cmd.rd_addr   = 5;                   // 写到 x5
exu_cmd.imm       = 10;                   // 立即数 = 10
exu_cmd.rd_wb_sel = SCR1_RD_WB_IALU;    // 写回来自 ALU 结果

第十一课: 动手练习

练习 1: 手工编码 (15 分钟)

练习 2: C 转汇编 (20 分钟)
将以下 C 函数翻译为 RISC-V 汇编 (假设 a0=x, a1=y, 返回值在 a0):
int max(int x, int y) {
    if (x > y) return x;
    else return y;
}

int sum_array(int *arr, int n) {
    int sum = 0;
    for (int i = 0; i < n; i++) {
        sum += arr[i];
    }
    return sum;
}
提示: 用 t0 做中间变量；数组访问 = LW 配合偏移；循环用条件分支 + JAL 组合。
