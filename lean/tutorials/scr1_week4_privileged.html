第二课: RISC-V 特权模式

三种标准特权模式

模式缩写用途SCR1 支持?
Machine 模式M-mode最高特权，固件/操作系统底层是
Supervisor 模式S-mode操作系统内核否
User 模式U-mode用户应用程序否
SCR1 的设计哲学
SCR1 是一个 MCU 级处理器核心，只实现 M-mode，这意味着所有代码都在最高特权级运行：
  • mstatus.MPP（先前特权级）硬连线为 2'b11（固定 Machine）
  • 没有特权级切换，不需要 mret 改回 U-mode 或 S-mode
  • 所有 CSR 读写均无特权级检查

在 SCR1 的 RTL 中，异常和中断的检测路径完全不同，这决定了它们的"同步"或"异步"属性：

CSR 端的中断优先使能判断 (异步检测)

中断信号来自 SOC 外部线，需要经过三层使能条件才能被 CPU 响应：

// 第1层: MIP 挂起 AND MIE 本地使能 (scr1_pipe_csr.sv:300-302)
assign csr_eirq_pnd_en = csr_mip_meip & csr_mie_meie_ff;
assign csr_sirq_pnd_en = csr_mip_msip & csr_mie_msie_ff;
assign csr_tirq_pnd_en = csr_mip_mtip & csr_mie_mtie_ff;

// 第2层: "有挂起且使能" OR 生成 ip_ie 信号 (scr1_pipe_csr.sv:992)
assign csr2exu_ip_ie_o  = csr_eirq_pnd_en | csr_sirq_pnd_en | csr_tirq_pnd_en;

// 第3层: ip_ie AND 全局使能 MIE -> 最终中断请求 (scr1_pipe_csr.sv:993)
assign csr2exu_irq_o    = csr2exu_ip_ie_o & csr_mstatus_mie_ff;

// 第4层: EXU 端还要检查 busy/调试状态 (scr1_pipe_exu.sv:973-981)
assign exu2csr_take_irq_o = csr2exu_irq_i & ~exu2pipe_exu_busy_o;
关键设计: 为什么中断有 4 层条件?
这是为了允许软件分层地管理中断响应：MIP 表示"外设发了请求"、MIE 表示"软件愿意响应这类中断"、MSTATUS.MIE 表示"软件当前允许任何中断"、EXU busy 表示"当前周期是否可以切走执行"。每一层可以独立开关，灵活且高效。

MSTATUS CSR 实现的完整 RTL (scr1_pipe_csr.sv:612-653)

MSTATUS 由两个独立触发器 csr_mstatus_mie_ff 和 csr_mstatus_mpie_ff 驱动，通过 always_comb 的 case 语句决定 next 值：

// scr1_pipe_csr.sv:617-625 -- MSTATUS 触发器实例化
always_ff @(negedge rst_n, posedge clk) begin
    if (~rst_n) begin
        csr_mstatus_mie_ff  <= SCR1_CSR_MSTATUS_MIE_RST_VAL;   // = 1'b0
        csr_mstatus_mpie_ff <= SCR1_CSR_MSTATUS_MPIE_RST_VAL;  // = 1'b1
    end else begin
        csr_mstatus_mie_ff  <= csr_mstatus_mie_next;
        csr_mstatus_mpie_ff <= csr_mstatus_mpie_next;
    end
end

// scr1_pipe_csr.sv:627-646 -- MSTATUS next 值逻辑
always_comb begin
    case (1'b1)
        e_exc, e_irq  : begin                            // 陷阱进入
            csr_mstatus_mie_next  = 1'b0;                   // 关全局中断
            csr_mstatus_mpie_next = csr_mstatus_mie_ff;      // 保存旧 MIE
        end
        e_mret        : begin                            // MRET 返回
            csr_mstatus_mie_next  = csr_mstatus_mpie_ff;     // 恢复旧 MIE
            csr_mstatus_mpie_next = 1'b1;                   // MPIE 复位
        end
        csr_mstatus_upd: begin                           // 软件写入 CSR
            csr_mstatus_mie_next  = csr_w_data[3];          // offset=3
            csr_mstatus_mpie_next = csr_w_data[7];          // offset=7
        end
        default       : begin
            csr_mstatus_mie_next  = csr_mstatus_mie_ff;     // 保持
            csr_mstatus_mpie_next = csr_mstatus_mpie_ff;    // 保持
        end
    endcase
end

// scr1_pipe_csr.sv:648-653 -- MSTATUS 读值组合 (MPP 硬连线)
always_comb begin
    csr_mstatus[3]         = csr_mstatus_mie_ff;      // offset=3
    csr_mstatus[7]         = csr_mstatus_mpie_ff;     // offset=7
    csr_mstatus[12:11]   = SCR1_CSR_MSTATUS_MPP;     // 硬连线 2'b11
end
MSTATUS 组合逻辑读值的关键设计
MSTATUS 的"聚合"输出信号 csr_mstatus 是纯组合逻辑 —— 它不由触发器直接驱动，而是通过 always_comb 从实际触发器 csr_mstatus_mie_ff、csr_mstatus_mpie_ff 和硬连线 MPP 拼接而成。这保证 CSR 读指令能立即看到最近更新的值。源文件 scr1_csr.svh:142-145 定义了各字段的 offset 常量。

MSTATUS 的陷阱自动切换（SCR1 真实逻辑）

三种事件（异常/中断/MRET）对 MSTATUS.MIE 和 MPIE 的影响来源于 scr1_pipe_csr.sv:626-639：

// scr1_pipe_csr.sv:629-639 -- MSTATUS 在事件时的更新
always_comb begin
    case (1'b1)
        e_exc, e_irq  : begin           // 进入陷阱时
            csr_mstatus_mie_next  = 1'b0;  // 关全局中断
            csr_mstatus_mpie_next = csr_mstatus_mie_ff; // 保存旧 MIE
        end
        e_mret        : begin           // MRET 返回时
            csr_mstatus_mie_next  = csr_mstatus_mpie_ff; // 恢复旧 MIE
            csr_mstatus_mpie_next = 1'b1; // MPIE 重置为 1
        end
        default       : begin
            csr_mstatus_mie_next  = csr_mstatus_mie_ff;
            csr_mstatus_mpie_next = csr_mstatus_mpie_ff;
        end
    endcase
end
一句话理解
进入陷阱 = MIE→0, MPIE→old_MIE（关门并记住之前门的状态）；
MRET 返回 = MIE→MPIE, MPIE→1（恢复之前门的状态）。

MIE 更新时的流水线停顿

关键机制
SCR1 在检测到 mstatus 更新的同一周期，EXU 会停止提交指令。源码在 scr1_pipe_exu.sv:804： 
// scr1_pipe_exu.sv:804
csr2exu_mstatus_mie_up_i : exu_rdy = 1'b0; // mstatus 更新周期不允许提交
这是必要的设计——MRET 指令修改 MIE 后，流水线需要额外一个周期让新 MIE 值生效。

中断触发条件： 挂起 + 使能 + 全局开关

一个中断要被 CPU 响应，必须同时满足三层条件（源码 scr1_pipe_csr.sv:300-302）：

// scr1_pipe_csr.sv:300-302 -- 中断挂起且本地使能
assign csr_eirq_pnd_en = csr_mip_meip & csr_mie_meie_ff;   // 外部中断：挂起 AND 使能
assign csr_sirq_pnd_en = csr_mip_msip & csr_mie_msie_ff;   // 软件中断：挂起 AND 使能
assign csr_tirq_pnd_en = csr_mip_mtip & csr_mie_mtie_ff;   // 定时器中断：挂起 AND 使能
"pnd_en" 命名解读
pnd = pending（挂起），en = enabled（本地使能）。三个 pnd_en 信号同时作为 csr2exu_ip_ie_o 的源（scr1_pipe_csr.sv:992），发给 EXU 判断是否有待处理中断。

第五课: MTVEC -- 机器陷阱向量基址寄存器 (0x305)

MTVEC 决定 CPU 遇到异常或中断后 "跳到哪里去" 执行处理程序。

31 ........................ 6 5 4 3 2 1 0
BASE[31:6] (可配可写位数) 0 0 0 0 0 0 MODE
字段位含义
BASE[31:6]陷阱向量基址。高 WR_BITS 位可写，低 RO_BITS 位硬连线为复位值
MODE[0]0=Direct（统一入口），1=Vectored（按中断类型分流）

Direct 模式 vs Vectored 模式

模式异常外部中断软件中断定时器中断

Vectored (mode=1)BASE + 0BASE + 0x2CBASE + 0x0CBASE + 0x1C

MTVEC Vectored 模式的完整 RTL (scr1_pipe_csr.sv:998-1020)

源码级: Vectored 模式新 PC 生成
// scr1_pipe_csr.sv:998-1020 -- MTVEC 新 PC 多路选择
ifndef SCR1_MTVEC_MODE_EN
assign csr2exu_new_pc_o = (exu2csr_mret_instr_i & ~exu2csr_take_irq_i)
                        ? csr_mepc                                   // MRET: 跳到 MEPC
                        : {csr_mtvec_base, SCR1_CSR_MTVEC_BASE_ZERO_BITS'(0)}; // Direct: BASE+0
else // SCR1_MTVEC_MODE_EN

        csr2exu_new_pc_o  = csr_mepc;                                // MRET: 跳到 MEPC

                csr_eirq_pnd_en   : csr2exu_new_pc_o = {csr_mtvec_base, 4'd11, 2'd0}; // 外部中断: BASE+0x2C
                csr_sirq_pnd_en   : csr2exu_new_pc_o = {csr_mtvec_base, 4'd3, 2'd0};  // 软件中断: BASE+0x0C
                csr_tirq_pnd_en   : csr2exu_new_pc_o = {csr_mtvec_base, 4'd7, 2'd0};  // 定时器中断: BASE+0x1C
                default           : csr2exu_new_pc_o = {csr_mtvec_base, 6'd0};
            endcase
        end else begin // direct mode
            csr2exu_new_pc_o = {csr_mtvec_base, 6'd0};
        end
    end
end
endif // SCR1_MTVEC_MODE_EN
Vectored 模式地址计算公式
BASE + 4 × exception_code。对于中断，外部中断 code=11 → 0x2C，软件中断 code=3 → 0x0C，定时器中断 code=7 → 0x1C。乘法通过左移 2 位实现（源码中 {csr_mtvec_base, exc_code, 2'd0}）。

如果 SCR1_MTVEC_MODE_EN 宏未定义，MODE 字段硬连线为 0（仅支持 Direct 模式）。Vectored 模式通过向量地址公式 BASE + 4 × IRQ_exc_code 计算，不同中断跳转到不同的偏移地址。

第六课: MEPC -- 机器异常程序计数器 (0x341)

MEPC 保存 "返回地址"——处理完异常后 MRET 指令应该跳回哪里继续执行。

事件MEPC 保存的值原因
e_exc（异常）curr_pc异常指令本身需要被重试，返回当前 PC
e_irq_nmret（中断且非 MRET）next_pc被中断的指令尚未执行，返回下条指令 PC
// scr1_pipe_csr.sv:776-783 -- MEPC 保存策略 (完整逻辑)
always_comb begin
    case (1'b1)
        e_exc       : csr_mepc_next = exu2csr_pc_curr_i[`SCR1_XLEN-1:PC_LSB];
        e_irq_nmret : csr_mepc_next = exu2csr_pc_next_i[`SCR1_XLEN-1:PC_LSB];
        csr_mepc_upd: csr_mepc_next = csr_w_data[`SCR1_XLEN-1:PC_LSB];   // 软件写入
        default     : csr_mepc_next = csr_mepc_ff;                    // 保持
    endcase
end
为什么异常保存 curr_pc 而中断保存 next_pc？
异常是当前指令本身触发的（如除零、非法指令），处理完后可能需要重试该指令，所以保存当前 PC。中断是外部信号打断正常流程，被中断的指令还 没执行完，所以保存下一条。

PC_LSB 低位补零

MEPC 只存储 [31:PC_LSB] 位，低 PC_LSB 位补 0：RVC 扩展时 PC_LSB=1（低 1 位补 0），无 RVC 时 PC_LSB=2（低 2 位补 0），保证地址对齐。

e_irq_nmret 信号的定义 (scr1_pipe_csr.sv:297)

为什么需要 e_irq_nmret 而不是直接使用 e_irq?
// scr1_pipe_csr.sv:297 -- MRET + 中断 同时发生时的保护
assign e_irq_nmret = e_irq & ~exu2csr_mret_instr_i;

如果 MRET 指令本身被中断（MRET 执行周期同时来了 IRQ），SCR1 的做法是优先处理中断，但 MEPC 不能被 MRET 指令覆盖。换言之：中断打断 MRET 时，MEPC 应保持 MRET 之前的值，指向原本要返回的地址。e_irq_nmret 信号确保这种情况下的 MEPC 不被错误更新。

SVA 断言验证 (scr1_pipe_csr.sv:1099-1103)
// scr1_pipe_csr.sv:1099-1103 -- SVA: MRET+IRQ 行为检查
SCR1_SVA_CSR_MRET_IRQ : assert property (
    @(negedge clk) disable iff (~rst_n)
    (exu2csr_mret_instr_i & e_irq)
    |=> ($stable(csr_mepc_ff) & (exu2csr_pc_curr_i != csr_mepc))
    ) else $error("CSR Error: MRET+IRQ wrong behavior");
这个断言在仿真中验证：当 MRET 和中断同时发生，MEPC 在下个周期保持不变（$stable），且当前 PC 已经不等于旧的 MEPC（说明中断确实被处理了，但 MEPC 没被覆盖）。

WFI 的关键时序
WFI 暂停流程: (1) WFI 指令进入 EXU → (2) 无挂起中断 → (3) wfi_halt_req=1 → (4) wfi_halted_ff=1, exu2pipe_wfi_run2halt_o=1 → (5) 流水线停止。
唤醒流程: (1) 中断信号到达 csr2exu_ip_ie_i → (2) wfi_run_req=1 → (3) wfi_halted_ff=0 → (4) wfi_run_start_ff=1 一周期 → (5) PC=pc_curr_ff (WFI地址) → (6) 执行 WFI 指令 → (7) 下一条指令正常执行 (或立即被中断夺取)。

第十二课再补充: IPIC search_one_16 优先级树

16 路中断的硬件优先级编码器 (scr1_ipic.sv)

SCR1 的 IPIC 支持最多 16 路可编程中断。当多路中断同时挂起且使能时，需要从中选出优先级最高的那一路。这个选优逻辑通过 search_one_16 函数实现（scr1_ipic.sv:100-143）。

search_one_16 的 4 级树形结构

该函数分 4 级对 16 个输入位进行查找：

// scr1_ipic.sv:113-142 -- search_one_16 优先级树
// 输入: din[15:0] -- 16 位的中断请求向量 (irq_req_v = IPR & IER)
// 输出: result.vd -- 是否有有效请求; result.idx -- 优先级最高的中断号

// Stage 1: 16 -> 8 (8 个 scr1_search_one_2)
for (int unsigned i=0; i<8; ++i) begin
    tmp = scr1_search_one_2(din[(i+1)*2-1-:2]);  // 相邻 2 位一组
    stage1_vd[i]  = tmp.vd;                    // 每组是否有请求
    stage1_idx[i] = tmp.idx;                   // 每组中位0或位1被选中
end

// Stage 2: 8 -> 4
for (int unsigned i=0; i<4; ++i) begin
    tmp = scr1_search_one_2(stage1_vd[(i+1)*2-1-:2]);
    stage2_idx[i] = (~tmp.idx) ? {tmp.idx, stage1_idx[2*i]}
                               : {tmp.idx, stage1_idx[2*i+1]};
end

// Stage 3: 4 -> 2
for (int unsigned i=0; i<2; ++i) begin
    tmp = scr1_search_one_2(stage2_vd[(i+1)*2-1-:2]);
    stage3_idx[i] = (~tmp.idx) ? {tmp.idx, stage2_idx[2*i]}
                               : {tmp.idx, stage2_idx[2*i+1]};
end

// Stage 4: 2 -> 1 (最终选出优先级最高者)
result.vd = |stage3_vd;
result.idx = (stage3_vd[0]) ? {1'b0, stage3_idx[0]} : {1'b1, stage3_idx[1]};

search_one_2 基本单元

// scr1_ipic.sv:89-98 -- 2 位查找基本单元
function automatic type_scr1_search_one_2_s scr1_search_one_2(
    input logic [1:0] din
);
    tmp.vd  = |din;               // 两位中任意一位为1 -> vd=1
    tmp.idx = ~din[0];             // din[0]=1 -> idx=0; din[0]=0,din[1]=1 -> idx=1
    return tmp;
endfunction
idx 的物理含义: 越低编号优先级越高
search_one_2 中 tmp.idx = ~din[0]：如果 din[0]=1，idx=0（选低位）；如果 din[0]=0 但 din[1]=1，idx=1。这意味着中断线 0 优先级高于线 1, 线 2 高于线 3，以此类推 —— 中断号越小，优先级越高。

优先级比较在 IPIC 中的应用 (scr1_ipic.sv:587-601)

// scr1_ipic.sv:587-601 -- 中断请求优先级链
assign irq_req_v = ipic_ipr_ff & ipic_ier_ff;          // 挂起 AND 使能的交集

assign irr_priority        = scr1_search_one_16(irq_req_v);  // 从挂起使能中选出最高优先级
assign irq_req_vd          = irr_priority.vd;                // 有有效请求?
assign irq_req_idx         = irr_priority.idx;               // 最高优先级中断号

assign isvr_priority_eoi   = scr1_search_one_16(ipic_isvr_eoi);  // EOI 时查找仍在服务中的中断
assign irq_eoi_req_vd      = isvr_priority_eoi.vd;
assign irq_eoi_req_idx     = isvr_priority_eoi.idx;

// 抢占判断: 新请求的中断号 < 当前服务的中断号 -> 高优先级抢占
assign irq_hi_prior_pnd     = irq_req_idx < irq_serv_idx;

// 最终中断请求: 有挂起请求 AND (无在服务中断 OR 新请求优先级更高)
assign ipic2csr_irq_m_req_o = irq_req_vd & (~irq_serv_vd | irq_hi_prior_pnd);

assign irq_start_vd         = ipic2csr_irq_m_req_o & ipic_soi_req;
search_one_16 vs MCAUSE 优先级的不同
注意有两个独立的优先级仲裁：
  • search_one_16 (IPIC 内部): 16 路中断中选优先级最高的中断号 (中断线 0 最高)
  • MCAUSE 优先级仲裁 (CSR 层): 三种中断类型中选一种存入 MCAUSE (外部 > 软件 > 定时器)
这两个不矛盾：search_one_16 从 16 路中选出编号最小的挂起中断；MCAUSE 层则根据中断类型（外部/软件/定时器）决定优先级。外部中断通过 IPIC 可选 16 路，而软件和定时器中断是 CSR 直接处理的。

假设 MTVEC=0x100（Direct 模式），编写一段汇编代码实现以下功能：

  2. 使用 mscratch 保存栈指针
  3. 读取 mcause 判断是异常还是中断
  4. 如果是定时器中断（MIP.MTIP），增加一个全局计数器的值
  5. 如果是 ECALL，什么都不做

# 陷阱处理程序模板 (.section .text.trap)
trap_handler:
    # 交换 sp 和 mscratch (保存用户栈指针，切换到陷阱栈)
    csrrw   sp, mscratch, sp           # sp=陷阱栈顶, mscratch=旧sp

    # 保存调用者保存寄存器
    addi    sp, sp, -64
    sw      ra, 0(sp)
    sw      t0, 4(sp)
    sw      t1, 8(sp)
    sw      t2, 12(sp)
    sw      a0, 16(sp)
    sw      a1, 20(sp)
    # ... 继续保存 a2-a7

    # 读取 mcause
    csrr    t0, mcause
    srli    t1, t0, 31                   # t1 = I 位 (bit31)
    andi    t0, t0, 0x7FF               # t0 = exception code

    beqz    t1, handle_exception        # I=0: 异常

# 中断处理
handle_interrupt:
    li      t1, 7                        # MTIP 编码=7
    bne     t0, t1, check_soft_irq      # 不是定时器中断则继续判断
    # 定时器中断处理:
    la      t1, timer_counter
    lw      t2, 0(t1)
    addi    t2, t2, 1
    sw      t2, 0(t1)
    j       trap_exit

check_soft_irq:
    li      t1, 3                        # MSIP 编码=3
    bne     t0, t1, check_ext_irq
    # 软件中断处理: 清除 MSIP (向特定地址写入 0)
    li      t1, 0x02000000               # CLINT MSIP 地址 (示例)
    sw      x0, 0(t1)
    j       trap_exit

check_ext_irq:
    # ... 外部中断处理
    j       trap_exit

handle_exception:
    li      t1, 11                       # ECALL_M 编码=11
    bne     t0, t1, check_other_exc
    # ECALL 处理: 什么都不做 (或执行系统调用)
    j       trap_exit

check_other_exc:
    # 非法指令等异常处理
    # 可读取 mtval 获取非法指令编码
    j       trap_exit

trap_exit:
    # 恢复寄存器
    lw      ra, 0(sp)
    lw      t0, 4(sp)
    lw      t1, 8(sp)
    lw      t2, 12(sp)
    lw      a0, 16(sp)
    lw      a1, 20(sp)
    addi    sp, sp, 64

    # 恢复 sp 并返回
    csrrw   sp, mscratch, sp           # 恢复用户栈指针
    mret                                # pc=mepc, mstatus.mie=mstatus.mpie
练习 8: 嵌套中断处理

在执行陷阱处理程序期间，如果又来一个更高优先级的中断，需要支持嵌套。编写代码实现：

  1. 进入陷阱处理程序后，重新打开 MSTATUS.MIE（允许嵌套）
  2. 在栈上按层次保存 MEPC 和 MSTATUS（每嵌套一层保存一对）

    addi    sp, sp, -80
    sw      ra, 0(sp)
    # 保存 mepc (当前这是嵌套前一层保存的地址)
    csrr    t0, mepc

    csrr    t0, mstatus
    sw      t0, 8(sp)

    li      t0, 0x8

    lw      t0, 4(sp)

SCR1 嵌套中断的注意事项
重新打开 MIE 意味着处理程序运行期间可被更高优先级中断抢占。SCR1 中外部中断 > 软件中断 > 定时器中断，所以定时器处理程序中应允许被外部或软件中断抢占。但注意 IPIC 层还有 16 路中断编号优先级（编号越小越高），这与 MCAUSE 层的中断类型优先级（外部>软件>定时器）应配合使用。
