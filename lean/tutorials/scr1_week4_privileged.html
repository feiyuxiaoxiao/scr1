一、CPU 里的"控制面板"

你已经学过 RISC-V 的基本指令——ADD 做加法、LW 从内存读取、BEQ 做分支跳转。这些指令操作的对象是 x0-x31 通用寄存器和内存。但 CPU 里还有另一套东西，它不参与数据运算，而是控制 CPU 自身的行为。比如：

  • CPU 现在是否允许响应中断？
  • 如果发生了错误（比如读写非法地址），应该跳到哪里去处理？
  • 这个错误是什么原因导致的？
  • CPU 运行了多少个时钟周期？执行了多少条指令？

这些问题的答案都存在CSR（Control and Status Register，控制与状态寄存器）里面。本周我们就来搞懂这套机制。

和通用寄存器的区别
x0-x31 是给指令做运算用的——它们存的是"数据"。CSR 存的是"配置和状态"——不能直接用 ADD/LW/BEQ 访问，必须用专门的 csrrw/csrrs/csrrc 指令读写。

二、用"门铃 + 日志本"来理解整套机制

在你深入看每个 CSR 之前，先用一个生活中的比喻建立直觉。这套比喻贯穿本周所有内容。

比喻：CPU 是一间办公室
CPU 概念比喻
CPU 正常执行指令员工正在办公桌前工作
异常 (Exception)员工自己犯错了——拿错了文件、填错了表格。他自己发现问题，停下来处理。
中断 (Interrupt)门铃响了——外面有人找。员工被打断，去开门。
陷阱处理程序处理"出错"或"门铃"的标准操作流程（SOP）手册
MSTATUS门铃开关——允许/禁止门铃响
MIE门禁分类——三类访客（快递/保洁/访客）分别允不允许按门铃
MIP门禁指示灯——哪类访客现在正等在门口
MTVECSOP 手册放在哪个抽屉里（地址）
MEPC书签——记录"刚才做到哪里了"，处理完回来继续
MCAUSE事件日志——"发生了什么"（门铃/犯错）
MTVAL事件详情——"具体什么错"（比如拿错了哪个文件）

后面每讲到一个 CSR，请回到这个表对照看一眼——它就是你在 CPU 里的"办公室管理员工具包"。

三、特权模式：为什么 CPU 要分"级别"

想象一个操作系统：用户程序 (比如浏览器) 不应该能随意关掉 CPU 的中断、也不该能直接读写硬盘。所以 RISC-V 设计了三种特权级别：

级别名称谁在用能做什么
最高Machine (M-mode)固件、bootloader、裸机程序一切——操作所有 CSR、关中断、复位
中Supervisor (S-mode)操作系统内核管理虚拟内存、进程调度
最低User (U-mode)普通应用程序只能算数、访存，不能碰 CSR
SCR1 的情况
SCR1 是一个单片机级别的 CPU 核心（MCU 级），它只实现了 M-mode。这意味着你的程序运行在最高权限——可以直接读/写任何 CSR、开关中断、操作所有硬件。没有"用户程序被限制"的概念——你就是系统的主人。
这对你的意义
不需要理解 S-mode 和 U-mode 的复杂交互。你写的每一条 CSR 指令都直接生效，没有"权限不足"这回事。

四、CSR 到底是什么——12 个特殊寄存器一览

CSR 就是一组"编号特殊的 32 位寄存器"，用 csrrw 等指令访问。SCR1 实现了约 12 个核心 CSR，按功能分四类：

第一类：陷阱配置（出事了怎么办）
CSR一句话
MSTATUS (0x300)总开关——当前是否允许中断
MTVEC (0x305)出事后跳到哪里——处理程序的地址
MIE (0x304)分类门禁——三类中断分别允不允许
第二类：陷阱记录（出了什么事）
CSR一句话
MEPC (0x341)书签——"之前执行到哪了"，MRET 时跳回去
MCAUSE (0x342)事件类型——是什么触发的（异常还是中断+具体编码）
MTVAL (0x343)附加信息——非法指令编码 / 错误地址等
MSCRATCH (0x340)纯粹暂存——处理程序拿它临时存点东西
第三类：中断状态（门铃状态）
CSR一句话
MIP (0x344)门禁指示灯——哪些中断现在正挂着（只读）
第四类：计数器（CPU 运行了多久）
CSR一句话
MCYCLE (0xB00)CPU 跑了多少个时钟周期
MINSTRET (0xB02)CPU 成功执行了多少条指令

五、MSTATUS -- 总开关（地址 0x300）

它在控制什么

MSTATUS 在 SCR1 中只有 两个有效位：

位名称含义复位值
bit 3MIE全局中断开关。1=允许中断，0=禁止所有中断0（默认关）
bit 7MPIE"之前的 MIE"。进入陷阱时自动保存旧 MIE 到这里1
31 ........ 8 7 6 5 4 3 2 1 0
0 ........ 0 MPIE 0 0 0 MIE 0 0 0

MIE 和 MPIE 配合的故事

这两个位是成对使用的：MIE 是"现在"，MPIE 是"之前"。

正常运行
MIE=1, MPIE=0
ECALL / 中断
进入陷阱
MIE=0（关门）
MPIE=1（记住之前开着）
MRET
恢复正常
MIE=1（恢复）
MPIE=1
比喻：出门关灯
MIE = 灯现在是亮是灭。MPIE = 出门前灯的状态（写在便签上）。
进入陷阱 = 出门：把灯关掉 (MIE=0)，在便签上写"刚才亮着" (MPIE=1)。
MRET = 回家：看便签 (MPIE=1)，把灯打开 (MIE=1)。
为什么进陷阱要关中断？
如果处理程序执行到一半又来个中断，CPU 的状态会乱套——就像你正在修电路板，突然又有个新故障要修，你第一个还没修完呢。所以默认先关掉，处理完再开。如果你确实需要"中断嵌套"（修一个故障时允许更紧急的打断），可以在处理程序里手动重新打开 MIE。

怎么读写 MSTATUS

# 读 MSTATUS 到 t0
csrr    t0, mstatus

# 设置 MIE=1（打开全局中断）—— bit 3
li      t0, 0x8       # 0x8 = 1<<3
csrs    mstatus, t0    # CSR Set: mstatus = mstatus | t0

# 清除 MIE=0（关闭全局中断）
li      t0, 0x8
csrc    mstatus, t0    # CSR Clear: mstatus = mstatus & ~t0

六、MIE 和 MIP -- 门铃的分类控制（地址 0x304 / 0x344）

为什么需要"分类控制"

不是所有中断都一样重要。定时器中断可能是用来做任务调度的（重要），外部中断可能是串口收了个字符（一般）。你希望"只响应重要的，忽略不重要的"。

SCR1 支持 3 类中断，每类有两个控制位：

中断类型来源使能位 (MIE)挂起位 (MIP)发生条件
外部中断片外设备（GPIO/UART等）MEIE (bit 11)MEIP (bit 11)外部引脚电平变化
定时器中断内部定时器到时间MTIE (bit 7)MTIP (bit 7)mtime >= mtimecmp
软件中断另一个 CPU 核或程序自己MSIE (bit 3)MSIP (bit 3)软件写入特定地址触发
比喻：三类门铃
你的办公室有三类门铃：快递铃、保洁铃、访客铃。
MIE = 你设置"快递可以按 (MSIE=1)"、"保洁可以按 (MSIE=0，别烦我)"、"访客可以按 (MEIE=1)"。
MIP = 现在哪个铃在响（红灯亮着）。这是硬件直接驱动的，你只能读不能写。
MSTATUS.MIE = 总闸——你把整个门铃系统断电了，任何铃都不响。

一个中断要真正触发，必须满足三个条件

1. 挂起
MIP.xxx=1
"有人在按铃"
&
2. 分类使能
MIE.xxx=1
"你允许这类铃"
&
3. 全局使能
MSTATUS.MIE=1
"总闸开着"

三个条件都满足，CPU 才真正响应。

# 示例：使能定时器中断
li      t0, 0x80       # bit 7 = MTIE
csrs    mie, t0        # 打开 MIE.MTIE

# 再开全局中断
li      t0, 0x8        # bit 3 = MIE
csrs    mstatus, t0    # 打开 MSTATUS.MIE

七、MTVEC -- 出事了往哪跑（地址 0x305）

它存的是什么

MTVEC 存一个内存地址。当异常或中断发生时，CPU 就会跳到这个地址开始执行你的处理程序。

31 .................................. 2 1 0
基地址 BASE[31:2] 0 0 MODE
  • BASE：陷阱处理程序的入口地址（必须 4 字节对齐）
  • MODE：SCR1 默认用 Direct 模式（MODE=0），所有异常和中断都跳到同一个地址 BASE
比喻：消防示意图上标的"紧急出口"
不管是什么紧急情况（火灾/地震/煤气泄漏），你都跑到同一个"紧急集合点"。MTVEC 就是这个集合点的地址。
Direct 模式 = 只有 1 个集合点。Vectored 模式 = 不同紧急情况去不同集合点（火灾去东门，地震去广场）——SCR1 可选支持。

基本用法

# 设置陷阱处理程序入口为 0x200
la      t0, trap_handler     # t0 = 陷阱处理程序地址
csrw    mtvec, t0             # MTVEC = t0

# trap_handler 函数（放在 .text 段的某个位置）
trap_handler:
    # 读取 mcause 判断原因
    # 执行相应处理
    # mret 返回

八、MEPC -- 书签，记录"刚才到哪了"（地址 0x341）

为什么需要它

处理完异常或中断后，CPU 得知道"回哪去"。这就是 MEPC 的作用。

事件类型MEPC 存什么为什么
异常触发异常的那一条指令的地址异常指令可能需要被重试（比如修好错误后再执行一次）
中断被中断的指令的下一条地址被中断的指令还没执行完，中断后应该接着往下走
比喻：书签
你读到一本书第 50 页，突然有事离开。你夹一张书签。回来时看书签，从第 50 页继续。
异常 = 你读到这一页发现印刷错误，夹书签在第 50 页（错误页面），去投诉，回来重新读第 50 页。
中断 = 你正要翻到第 51 页但还没翻，书签夹在第 51 页（下一页），回来直接开始读第 51 页。

MRET 返回就是跳到 MEPC

# 陷阱处理程序末尾
mret           # PC = MEPC; MSTATUS.MIE = MSTATUS.MPIE

MRET 做两件事：1) 把 PC 设为 MEPC（回到家），2) 恢复 MIE（重新开灯）。

九、MCAUSE 和 MTVAL -- 事件记录本（地址 0x342 / 0x343）

MCAUSE：记录"发生了什么"

31 30 ........................................ 4 3 2 1 0
I 0..........................0 Exception Code [3:0]
  • bit 31 (I 位)：0=异常（自己犯错），1=中断（门铃响）
  • bit [3:0] (异常编码)：具体是什么事
I编码含义谁触发的
00指令地址未对齐跳转到非 4 字节对齐地址
02非法指令CPU 不认识这条指令的操作码
03断点 (EBREAK)调试器设的断点
04Load 地址未对齐LW 访问非 4 字节对齐地址
06Store 地址未对齐SW 访问非 4 字节对齐地址
011ECALL（来自 M 模式）程序主动调用
13软件中断MSIP 引脚
17定时器中断MTIP 引脚
111外部中断MEIP 引脚
编码 3/7/11 复用了
注意编码 3、7、11 被异常和中断共用——区别看 I 位。I=0 是异常（BREAKPOINT/ECALL），I=1 是中断（SOFTWARE/TIMER/EXTERNAL）。

MTVAL：记录"具体细节"

事件MTVAL 的值
非法指令异常那条非法指令的 32 位编码（可以看看"到底是什么奇怪的指令"）
地址未对齐异常出错的访存地址
ECALL0（无额外信息）
任何中断0（中断不附额外信息）

读 MCAUSE 判断事件类型

# 处理程序中判断事件类型
csrr    t0, mcause
srli    t1, t0, 31         # t1 = I 位（bit 31）
beqz    t1, is_exception  # I=0 -> 异常

# I=1 -> 中断
andi    t0, t0, 0xF       # 取低 4 位 = 中断编码
li      t1, 7
beq     t0, t1, timer_irq # 编码 7 = 定时器中断

十、完整故事：从 ECALL 到 MRET -- 一次完整旅程

现在把所有 CSR 串起来，用一个具体例子走一遍。

场景
CPU 在地址 0x100 执行 ecall 指令。MTVEC 已设为 0x200。

时间线（5 步走）

第 1 步
执行 ECALL
PC=0x100
→
第 2 步
自动保存现场
到 CSR
→
第 3 步

第 4 步

每一步 CSR 的变化

步骤PCMEPCMCAUSEMSTATUS.MIEMSTATUS.MPIE说明
1. 执行前0x100??1?正常执行中，MIE 开着
2. 保存0x1000x100I=0,ec=1101硬件自动完成所有写入
3. 跳转0x2000x100I=0,ec=1101开始执行你的处理程序
4. MRET0x???0x100I=0,ec=110→11→1MRET 恢复 MIE
5. 返回0x1000x100I=0,ec=1111回到原点，MIE 恢复

你不需要在汇编代码里写 csrw mepc, pc——CPU 硬件在检测到 ECALL 的瞬间自动完成了 MEPC/MCAUSE/MTVAL/MSTATUS 的所有更新。你的处理程序只需要读它们来判断情况。

最小的陷阱处理程序

# 最简单的陷阱处理程序：什么都不做，直接返回
trap_handler:
    mret          # PC=MEPC, MSTATUS.MIE=MSTATUS.MPIE

就这一行。mret 自动完成 PC 跳转和 MIE 恢复。

十一、中断来了怎么办 -- 与异常的异同

和异常的差异

注意 MEPC 存的是 0x408（下一条），而不是 0x404（当前）。

最小的定时器中断处理程序

# 定时器中断处理框架
timer_handler:
    # 保存用到的寄存器到栈上
    addi    sp, sp, -16
    sw      ra, 0(sp)
    sw      t0, 4(sp)

    # 处理定时器业务（比如点亮一个 LED）
    # ...

    # 恢复寄存器
    lw      t0, 4(sp)
    lw      ra, 0(sp)
    addi    sp, sp, 16

    mret                     # 返回
为什么要保存 ra 和 t0？
你的处理程序可能会修改 ra 和 t0——但被中断的程序还指望这些值不变。所以处理程序开头要存起来，末尾要恢复。这和在 C 函数调用中保存寄存器是同一个道理。

assign csr2exu_ip_ie_o  = csr_eirq_pnd_en | csr_sirq_pnd_en | csr_tirq_pnd_en;

// scr1_pipe_csr.sv:993 -- 第 3 层：加上全局使能
assign csr2exu_irq_o    = csr2exu_ip_ie_o & csr_mstatus_mie_ff;
