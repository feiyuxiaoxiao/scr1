第一课: 为什么先看架构？

第二课: SCR1 的市场定位

维度SCR1 的特征对比桌面 CPU

面积< 20K 门（最小配置）数百万门

顺序流水线 = 简单可靠
SCR1 的指令 严格按程序顺序 执行，没有乱序发射、没有推测执行、没有分支预测器。这意味着：
  • 无数据冲突（操作数获取和结果提交在同一阶段执行）
  • 代码就是时间线：你写的顺序就是 CPU 执行的顺序
  • 调试友好：PC 永远指向正在执行的指令
代价是：分支和跳转必须等待前序指令全部完成，无法像桌面 CPU 那样提前"猜测"。

第六课: scr1_pipe_top 内部信号连线

scr1_pipe_top.sv 本身不存在任何逻辑，它是 7 个子模块之间的"接线板"。看懂它的关键在于理解信号组。

信号组连接方向说明
curr_pc / next_pc / new_pcEXU → IFUPC 值从 EXU 传回 IFU，控制下一条取哪条指令
ifu2idu_*IFU → IDU指令字（32/16 位）、有效标志、错误标志
idu2ifu_rdyIDU → IFUIDU 是否准备好接收下一条指令（反压信号）
idu2exu_cmd / idu2exu_reqIDU → EXU译码后的 EXU 命令结构体 + 有效请求
exu2idu_rdyEXU → IDUEXU 是否接受新指令（反压信号）
exu2mprf_* / mprf2exu_*EXU ↔ MPRF读 rs1/rs2 数据 + 写 rd 数据
exu2csr_* / csr2exu_*EXU ↔ CSRCSR 读写请求 + 事件信号（exc/irq/mret）
pipe2imem_* / imem2pipe_*IFU ↔ IMEM指令存储器接口（取指请求/地址/读数据/响应）
pipe2dmem_* / dmem2pipe_*LSU(EXU内) ↔ DMEM数据存储器接口（通过 EXU 透传到 LSU）
命名规律小结
信号名遵循 源2目标_信号名_方向 的格式：ifu2idu_vd = IFU 到 IDU 的有效数据信号；idu2ifu_rdy = IDU 到 IFU 的就绪信号。方向后缀 _i（输入）、_o（输出）让每个模块的端口声明自洽。

第七课: scr1_core_top 包裹层

scr1_core_top 在 scr1_pipe_top 之外额外提供三个关键功能：

1 复位逻辑：当 SCR1_DBG_EN 使能时，由 SCU（系统控制单元）管理上电复位/系统复位/CPU 复位/调试复位的多级复位链。无调试时使用精简的两级同步器。
2 调试子系统集成：TAPC（JTAG 接口）→ DM（调试模块）→ HDU（硬件调试单元）→ scr1_pipe_top 的调试端口。走 JTAG 的 DMI 通道实现非侵入式调试。
3 时钟门控：当 SCR1_CLKCTRL_EN 使能时，根据 WFI 暂停状态和 IMEM 事务是否待处理来控制 clk_pipe 门控，降低动态功耗。

配置怎么选？
MIN 用于极致面积和功耗的 IoT 传感器节点；BASE 是常规 MCU 配置（对标 Cortex-M0/M3）；MAX 用于需要乘法加速和高级调试的场合。核心选择因素：加法运算交给软件还是硬件乘法器。

`endif
为什么 RAM MPRF 强制保留 EXE 寄存器？
RAM 模块本身有一级读延迟。如果 IDU 到 EXU 不加寄存器，组合逻辑路径会走过 IDU 译码 + MPRF RAM 读访问 + IALU 运算，时序很难收敛。增加 SCR1_NO_EXE_STAGE 把 RAM 读延迟切分为独立流水级。

第九课: 8 个功能阶段

SCR1 的指令执行在 逻辑上 分为 8 个功能阶段（摘自官方 EAS 文档第 6.1 节），在实际硬件中被合并为 2/3/4 个物理流水级。

#功能阶段实现模块做什么
1指令请求IFU用 IMEM_ADDR 寄存器中的地址向指令存储器发起读请求
2指令接收IFU接收指令字，放入取指队列；处理跨边界未对齐 RVI 指令的拼接
3指令译码IDU解析指令字段（opcode/funct3/rd/rs1/rs2/imm），生成控制信号
4操作数获取EXU(MPRF)从通用寄存器文件读取 rs1 和 rs2 的值
5算术逻辑操作EXU(IALU)执行 ALU 运算：加减、逻辑、移位、乘法、除法
6加载/存储操作EXU(LSU)向数据存储器发起 LOAD/STORE 请求，等待响应
7指令流控制EXU判断分支/跳转/异常/中断/MRET/WFI/调试事件，生成新 PC
8写回MPRF + CSR将计算结果写入目的寄存器（GPR 或 CSR）
阶段 vs 物理流水级的区别
功能阶段是逻辑概念，物理流水级是实际的寄存器边界。MIN 配置把 1-2-8 全部合并到同一级，MAX 配置用寄存器把它们隔开。关键是：无论几级流水，阶段 5-8 永远在 EXU 内部一起完成，这就是 SCR1 "无数据冲突" 的根本原因。

EXU 是流水线的核心枢纽
EXU 是唯一同时连接 IFU（PC）、IDU（命令）、MPRF（寄存器）、CSR（控制）、LSU（访存）、DMEM（存储）、HDU（调试）、TDU（断点）的模块。理解 EXU 的数据通路就等于理解了整条流水线。

第十课（补二）: 流水线时序与寄存器放置

2 级流水线（MIN）：IFU | IDU+EXU

IFU 和 IDU+EXU 在两个不同的物理流水级中。IDU、EXU、MPRF、CSR 在同一个周期内完成。DEC 和 EXE 寄存器都被旁路。

周期 Cycle 0 Cycle 1 Cycle 2 Cycle 3 ─────────────────────────────────────────────────── IFU [取指 insn0] [取指 insn1] [取指 insn2] [取指 insn3] │ └── ifu2idu_instr ──┐ (无 DEC 寄存器，直接连线) ↓ IDU/EXU [译码+执行 insn0] [译码+执行 insn1] ├─ 读 MPRF ├─ IALU 运算 ├─ LSU 访存 ├─ PC 控制 └─ 写回 MPRF 关键: IDU和EXU之间没有寄存器隔开，指令在IDU译码的同时就开始在EXU中执行。 DEC寄存器: SCR1_NO_DEC_STAGE = 定义 → 旁路 EXE寄存器: SCR1_NO_EXE_STAGE = 定义 → 旁路

3 级流水线（BASE）：IFU+IDU | EXU

IFU 和 IDU 在同一个物理级，EXU 在下一级。DEC 寄存器被旁路，EXE 寄存器保留。

周期 Cycle 0 Cycle 1 Cycle 2 Cycle 3 ──────────────────────────────────────────────────────────────────── IFU/IDU [取指+译码 insn0] [取指+译码 insn1] [取指+译码 insn2] │ └── idu2exu_cmd ──[EXE_REG]──┐ (EXE 寄存器延迟一拍) ↓ EXU [执行 insn0] [执行 insn1] ├─ 读 MPRF ├─ IALU 运算 ├─ LSU 访存 ├─ PC 控制 └─ 写回 MPRF 关键: DEC 被旁路(IFU直接连IDU)，EXE 寄存器保留。 DEC寄存器: SCR1_NO_DEC_STAGE = 定义 → 旁路 EXE寄存器: SCR1_NO_EXE_STAGE = 未定义 → 保留

4 级流水线（MAX）：IFU | IDU | EXU

三个物理级各有一个模块。DEC 寄存器和 EXE 寄存器都保留。

周期 Cycle 0 Cycle 1 Cycle 2 Cycle 3 Cycle 4 ─────────────────────────────────────────────────────────────── IFU [取指 insn0] [取指 insn1] [取指 insn2] [取指 insn3] │ └── ifu2idu_instr ──[DEC_REG]──┐ (DEC 寄存器延迟一拍) ↓ IDU [译码 insn0] [译码 insn1] [译码 insn2] │ └── idu2exu_cmd ──[EXE_REG]──┐ ↓ EXU [执行 insn0] [执行 insn1] ├─ 读 MPRF ├─ IALU 运算 ├─ LSU 访存 ├─ PC 控制 └─ 写回 MPRF 关键: DEC 和 EXE 寄存器都保留，三个模块各独立一级。 DEC寄存器: SCR1_NO_DEC_STAGE = 未定义 → 保留 EXE寄存器: SCR1_NO_EXE_STAGE = 未定义 → 保留

exu2mprf_rd_data = 32'd8            // 5 + 3 = 8

// EXU → IFU (新 PC):
new_pc_req = 1'b1                  // 新 PC 请求
new_pc     = 32'h204               // PC + 4

命令结构体如何在 EXU 中驱动执行
EXU 收到 idu2exu_cmd 后做三件事并行执行：
  1. 将 rs1_addr/rs2_addr 发给 MPRF 读端口，下周期收到 mprf2exu_rs1_data/mprf2exu_rs2_data
  2. 将 ialu_cmd/ialu_op 送给 IALU，选择操作数和运算函数
  3. 根据 rd_wb_sel 选择写回 MPRF 的数据源（wdata mux），通过 exu2mprf_w_req + exu2mprf_rd_data 写回

第十四课（补二）: 时钟与复位架构

时钟树

SCR1 使用统一的系统时钟 clk，但通过 scr1_clk_ctrl 模块（仅在 SCR1_CLKCTRL_EN 使能时）产生门控时钟 clk_pipe。调试子系统使用独立的不门控时钟 clk_dbgc。

scr1_clk_ctrl 模块（src/core/scr1_clk_ctrl.sv）

// 时钟控制器输出 4 路时钟/控制信号
assign clkctl2pipe_clk_alw_on_o = clk;           // 始终运行: 给 IPIC 和 CSR 计数器
assign clkctl2pipe_clk_dbgc_o   = clk;           // 调试时钟: 给 HDU

// clk_pipe_en 状态机 (scr1_clk_ctrl.sv:30-44):
always_ff @(posedge clk, negedge ctrl_rst_n) begin
    if (~ctrl_rst_n) begin
        clkctl2pipe_clk_en_o <= 1'b1;              // 复位后时钟使能
    end else begin
        if (clkctl2pipe_clk_en_o) begin
            // 当前时钟开着: 仅当 sleep_req 有效且 wake_req 无效时关断
            if (pipe2clkctl_sleep_req_i & ~pipe2clkctl_wake_req_i) begin
                clkctl2pipe_clk_en_o <= 1'b0;
            end
        end else begin
            // 当前时钟关着: wake_req 有效即恢复
            if (pipe2clkctl_wake_req_i) begin
                clkctl2pipe_clk_en_o <= 1'b1;
            end
        end
    end
end

// 时钟门控单元
scr1_cg i_scr1_cg_pipe (
    .clk        (clk                 ),
    .clk_en     (clkctl2pipe_clk_en_o),
    .test_mode  (test_mode           ),
    .clk_out    (clkctl2pipe_clk_o   )     // → clk_pipe
);

睡眠/唤醒机制

信号来源含义
pipe2clkctl_sleep_req_opipe_topWFI 已暂停 + 无待处理 IMEM 事务 → 请求关断时钟
pipe2clkctl_wake_req_opipe_top有挂起中断且全局使能 → 请求恢复时钟
clkctl2pipe_clk_alw_on_iclk_ctrl始终运行的时钟（给 IPIC / CSR 计数器）
clkctl2pipe_clk_en_iclk_ctrl当前时钟是开着的标志（给 EXU 判断）
clkctl2pipe_clk_dbgc_iclk_ctrl调试时钟（给 HDU）
WFI 到时钟关断的完整流程
  1. EXU 执行 WFI 指令 → wfi_run2halt 拉高
  2. pipe_top 中 WFI 暂停状态机进入 halted → wfi_halted=1
  3. 当所有待处理 IMEM 事务完成 → imem_txns_pending=0
  4. pipe2clkctl_sleep_req = wfi_halted & ~imem_txns_pending → 发给 clk_ctrl
  5. clk_ctrl 在下一个周期关断 clk_pipe_en → clk_pipe 停止翻转
  6. 中断到达 → CSR 检测 ip_ie → pipe2clkctl_wake_req → clk_ctrl 恢复时钟

复位架构（src/core/primitives/scr1_reset_cells.sv）

SCR1 定义了 6 种复位处理原语，在 scr1_core_top.sv 和 scr1_top_ahb.sv 中被实例化使用：

原语模块功能使用场景
scr1_reset_sync_cell复位同步器（可配级数 STAGES_AMOUNT），消除亚稳态顶层复位输入同步（2 级）
scr1_reset_buf_cell复位缓冲器：寄存器打拍 + 状态输出 + test_mode 支持复位输出缓冲、qualifier 适配
scr1_reset_qlfy_adapter_cell_sync复位限定适配器：前级同步 + 缓冲输出 + RDC 限定器无调试时的 core_rst_n 生成
scr1_data_sync_cell数据同步器（可配级数）跨复位域状态信号同步
scr1_reset_and2_cell双输入复位与门TAPC 复位 = trst_n & pwrup_rst_n
scr1_reset_and3_cell三输入复位与门SCU 内部多源复位组合
scr1_reset_mux2_cell二选一复位多路器调试复位源切换

两种复位策略

有调试 (SCR1_DBG_EN) -- SCU 集中管理: pwrup_rst_n ─┐ rst_n ─┤ ┌─ core_rst_n (流水线) cpu_rst_n ─┤→ scr1_scu → 多级 ──┼─ sys_rst_n (系统复位输出) ndm_rst_n ─┤ (SCU) 复位链 ─┼─ dm_rst_n (调试模块) hart_rst_n ─┘ └─ hdu_rst_n (硬件调试单元) 无调试 -- 两级同步器: rst_n & cpu_rst_n → scr1_reset_qlfy_adapter_cell_sync → core_rst_n (前级同步 + 缓冲 + RDC限定器) ↓ scr1_data_sync_cell → core_rst_status
所有复位单元的关键特性
  • 全部支持 test_mode + test_rst_n DFT 测试模式
  • 异步复位（negedge rst_n）、同步释放（posedge clk）
  • 复位同步器默认 2 级触发器（可配置 STAGES_AMOUNT）
  • 复位输出在 DFT 模式下 bypass 到 test_rst_n
