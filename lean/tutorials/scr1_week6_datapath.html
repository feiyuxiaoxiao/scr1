流水线架构回顾

4 级流水线核心信号路径

SCR1 的 4 级流水线并非 5 级经典流水线的删减版，而是将 EX/MEM/WB 三阶段合并到 EXU 内部，形成独特的 IFU-IDU-EXU 三级 + IFU 内部一级的结构。

第二课: ADD x5, x1, x2 -- 算术指令追踪

RTL 表示

// ADD x5, x1, x2 的 RTL 表示
// 设 x1 = 5, x2 = 3
T2 (IDU):  idu2exu_cmd_o = {
    rs1_addr=<x1>, rs2_addr=<x2>, rd_addr=<x5>,
    ialu_op=REG_REG, ialu_cmd=ADD, rd_wb_sel=IALU,
    jump_req=0, branch_req=0, lsu_cmd=NONE, csr_cmd=NONE
};
if (exu_rdy) begin                              // T2→T3 posedge
    exu_queue <= idu2exu_cmd_o;                   // 指令入 EXU 队列
    exu_queue_vd <= 1;
end

T3 (EXU):  // exu_queue_vd = 1, 同周期完成读→算→写
    exu2mprf_rs1_addr_o = <x1>;                  // 发起 rs1 读取
    exu2mprf_rs2_addr_o = <x2>;                  // 发起 rs2 读取
    rs1_val = mprf2exu_rs1_data_i;                // 异步读取 = 5
    rs2_val = mprf2exu_rs2_data_i;                // 异步读取 = 3
    ialu_main_op1 = rs1_val;                      // = 5
    ialu_main_op2 = rs2_val;                      // = 3
    ialu_main_res = 5 + 3;                        // IALU 组合逻辑 = 8
    exu2mprf_w_req_o   = 1;                       // rd_wb_sel=IALU, 非 NONE
    exu2mprf_rd_addr_o = <x5>;
    exu2mprf_rd_data_o = ialu_main_res;           // = 8 (default case)
    exu2pipe_instret_o = 1;                       // exu_queue_vd & exu_rdy
    // T3→T4 posedge: MPRF[x5] <= 8

ADD 同周期读-算-写的奥秘
ADD 在 T3 周期同时完成三个操作：异步读 MPRF → 组合逻辑 IALU 运算 → 同步写 MPRF。读是异步组合逻辑，写是 posedge 触发。读操作在 T3 电平期间完成（看到的是 T2 posedge 写入的旧值），ALU 运算也是组合逻辑，写请求在 T3 周期拉高，但实际写入发生在 T3→T4 的 posedge。 对于 x0 寄存器的处理：mprf_rs1_req 信号要求 |exu2mprf_rs1_addr_i 非零才拉高。如果 rs1 是 x0，读地址为 0，rs1_addr_vd=0，MPRF 返回 0。同理，exu2mprf_w_req_o 要求 |exu2mprf_rd_addr_i 非零才写——写入 x0 始终被忽略。

第三课: LW x6, 4(x1) -- LOAD 指令追踪

假设 x1 = 0x1000，目的：从地址 0x1004 读 32 位数据到 x6，DMEM 返回 0xDEADBEEF。

RTL 表示

// LW x6, 4(x1) 的 RTL 表示
T2 (IDU):  idu2exu_cmd_o = {
    rs1_addr=<x1>, rd_addr=<x6>,
    sum2_op=REG_IMM, rd_wb_sel=LSU, lsu_cmd=LW,
    ialu_cmd=NONE, jump_req=0, branch_req=0
};
if (exu_rdy) begin
    exu_queue <= idu2exu_cmd_o;
    exu_queue_vd <= 1;
end

T3 (EXU): // exu_queue_vd = 1
    // 地址加法器计算 DMEM 地址
    ialu_addr_op1 = mprf2exu_rs1_data_i;           // = 0x1000 (x1)
    ialu_addr_op2 = exu_queue.imm;                 // = 4
    ialu_addr_res = 0x1000 + 4;                    // = 0x1004
    // 发起 LSU 请求
    lsu_req = (lsu_cmd != NONE) & exu_queue_vd;     // = 1
    exu2lsu_req_i = 1;
    exu2lsu_addr_i = ialu_addr_res;                // = 0x1004
    exu2lsu_cmd_i = LW;
    lsu_fsm_curr → BUSY;                           // T3→T4 posedge
    exu_rdy = lsu_rdy | lsu_exc_req;               // = 0 (LSU 等待)
    exu2pipe_instret = 0;                          // exu_rdy=0

T4 (EXU stall): // exu_queue_vd 保持, exu_rdy = 0
    lsu_fsm_curr = BUSY;
    dmem_resp_received = 0;                        // DMEM 响应未到
    // IDU 不发送新指令: idu2exu_req 被阻塞

T5 (EXU): // exu_queue_vd = 1, DMEM 响应到达
    lsu_fsm_curr = BUSY;
    dmem2lsu_resp_i = SCR1_MEM_RESP_RDY_OK;
    dmem_resp_received = 1;
    lsu_rdy = 1;
    lsu_l_data = dmem2lsu_rdata_i;                 // = 0xDEADBEEF
    exu_rdy = lsu_rdy | lsu_exc_req;               // = 1
    exu2mprf_w_req_o = 1;                          // rd_wb_sel=LSU
    exu2mprf_rd_addr_o = <x6>;
    exu2mprf_rd_data_o = lsu_l_data;               // = 0xDEADBEEF
    exu2pipe_instret_o = 1;
    lsu_fsm_curr → IDLE;                           // T5→T6 posedge

LOAD 的 EXU 反压传导
T3 周期 LSU 忙后，exu_rdy=lsu_rdy=0 → exu2idu_rdy=0 → idu2ifu_rdy=0。反压在 同周期（T3） 即传导到 IFU，T4 周期 IFU 停止取指。T5 当 LSU 收到 DMEM 响应后，lsu_rdy=1，反压解除，流水线恢复。

连续 LOAD 的吞吐量分析

指令1: LW x5, 0(x1) | IF | ID | EX(LSU_req) | EX(BUSY) | EX(rdy+WB) | 指令2: LW x6, 4(x1) | | IF | ID(stall) | ID | EX(LSU_req)| EX(BUSY) | EX(rdy+WB) clk: T0 T1 T2 T3 T4 T5 T6 T7 吞吐量 = 2 (两条 LOAD 完成需要 5+2=7 周期, 平均 3.5 周期/条, CPI=2 DMEM 响应周期)

第四课: SW x2, 8(x1) -- STORE 指令追踪

假设 x1 = 0x1000, x2 = 0xABCD，目标：把 0xABCD 写入地址 0x1008。

RTL 表示

// SW x2, 8(x1) 的 RTL 表示
T2 (IDU):  idu2exu_cmd_o = {
    rs1_addr=<x1>, rs2_addr=<x2>,
    sum2_op=REG_IMM, lsu_cmd=SW,
    rd_wb_sel=NONE,    // STORE 不写回 MPRF!
    ialu_cmd=NONE
};

T3 (EXU): // 与 LOAD 相似但 rd_wb_sel=NONE
    // 地址加法器
    ialu_addr_op1 = mprf2exu_rs1_data_i;           // = 0x1000 (x1)
    ialu_addr_op2 = exu_queue.imm;                 // = 8
    ialu_addr_res = 0x1000 + 8;                    // = 0x1008
    // DMEM 写数据 = rs2
    exu2lsu_sdata_i = mprf2exu_rs2_data_i;         // = 0xABCD (x2)
    lsu_req = 1;
    lsu_fsm → BUSY;
    exu2mprf_w_req_o = 0;                          // rd_wb_sel=NONE!

T4 (EXU stall): exu_rdy = 0;                       // 等待 DMEM 写完成

T5 (EXU): // DMEM 写完成
    dmem_resp_received = 1;
    lsu_rdy = 1;
    exu_rdy = 1;
    exu2pipe_instret_o = 1;                        // 指令退休
    // 无 MPRF 写回

STORE vs LOAD 的关键差异
STORE 在 IDU 译码时即设 rd_wb_sel = SCR1_RD_WB_NONE，因此 EXU 中 exu2mprf_w_req_o 始终为 0。它只消费两个源操作数（rs1=基址, rs2=写入数据），不产生寄存器写入。指令在 T5 退休仅通过 exu2pipe_instret_o 标记，PC 推进到 T2 的取指 PC（0x200+4=0x204）。

第五课: BEQ x1, x2, label -- 分支指令追踪

假设 x1 = x2 = 5, label 偏移 = -8 (即跳转到 PC-8)。条件满足，分支采用。

RTL 表示

// BEQ x1, x2, label 的 RTL 表示
T2 (IDU):  idu2exu_cmd_o = {
    rs1_addr=<x1>, rs2_addr=<x2>,
    ialu_op=REG_REG, ialu_cmd=SUB,   // IALU 做减法比较
    sum2_op=PC_IMM,                   // 地址加法器计算目标 PC
    branch_req=1, jump_req=0,
    rd_wb_sel=NONE,                   // BEQ 不写回
    imm=B-type 符号扩展               // = -8
};

T3 (EXU): // exu_queue_vd = 1
    // IALU 比较
    ialu_main_op1 = mprf2exu_rs1_data_i;           // = 5 (x1)
    ialu_main_op2 = mprf2exu_rs2_data_i;           // = 5 (x2)
    ialu_cmp = (5 == 5);                           // = 1 (BEQ 条件满足)
    branch_taken = exu_queue.branch_req & ialu_cmp; // = 1
    jb_taken = jump_req | branch_taken;            // = 1
    // 地址加法器计算目标 PC
    ialu_addr_op1 = pc_curr_ff;                    // = 0x200
    ialu_addr_op2 = exu_queue.imm;                 // = -8 (= 0xFFFFFFF8)
    ialu_addr_res = 0x200 + (-8);                  // = 0x1F8
    jb_new_pc = ialu_addr_res & 0xFFFFFFFE;        // 确保 LSB=0
    // New PC 请求: default case → ialu_addr_res & JUMP_MASK
    exu2ifu_pc_new_o = jb_new_pc;                  // = 0x1F8
    exu2ifu_pc_new_req_o = exu_queue_vd & jb_taken;// = 1
    exu2pipe_instret_o = 1;                        // 分支指令退休

T4: exu2ifu_pc_new_req_o = 1;
    IFU: q_flush_req = 1;                          // 清空 IFU 队列
    IFU: q_rptr = 0; q_wptr = 0;                  // 读写指针归零
    PC 重定向到 0x1F8;
    exu_queue_barrier = 0;                         // 重新开始

分支惩罚详解
T3 时 IFU 已经"乐观"取了 0x204 和 0x208 的指令（因为它不知道分支会不会跳转）。T3 EXU 发现 BEQ 条件满足后，T4 必须清空流水线（flush）——0x204 的指令（译码中）和 0x208 的指令（在 IFU 队列中）全部废弃。exu2ifu_pc_new_req_o 在 T3 的 posedge 被 IFU 采样，T4 周期 IFU 执行清空操作。 分支惩罚 = 2 个周期（T4 清空 + T5 重新取指第一字节），等效于浪费了 0x204 和 0x208 两条指令的取指/译码工作。

第六课: JAL x1, label -- 无条件跳转追踪

JAL (Jump And Link) 做两件事：把返回地址（PC+4）写入 rd，然后无条件跳转到目标地址。

RTL 表示

// JAL x1, label 的 RTL 表示
T2 (IDU):  idu2exu_cmd_o = {
    rd_addr=<x1>,
    sum2_op=PC_IMM,              // 地址加法器 = PC + imm
    rd_wb_sel=INC_PC,            // 写回 PC+4, 不是 IALU 结果!
    jump_req=1, branch_req=0,
    imm=J-type 符号扩展           // 目标偏移
};

T3 (EXU): // exu_queue_vd = 1
    // 地址加法器: PC + imm → 目标地址
    ialu_addr_op1 = pc_curr_ff;                   // = 0x200
    ialu_addr_op2 = exu_queue.imm;                // J-type imm
    ialu_addr_res = 0x200 + imm;                  // = 目标地址
    jb_new_pc = ialu_addr_res & SCR1_JUMP_MASK;
    // 返回地址计算: inc_pc = 0x200 + 4 = 0x204
    inc_pc = pc_curr_ff + 4;
    // New PC 请求
    jb_taken = 1;
    exu2ifu_pc_new_o = jb_new_pc;
    exu2ifu_pc_new_req_o = 1;
    // 写回: rd_wb_sel = INC_PC
    exu2mprf_w_req_o = 1;
    exu2mprf_rd_addr_o = <x1>;

第九课: 数据冒险与 SCR1 的"零成本"转发

数据冒险类型

经典 RISC 流水线中的三种数据冒险：

  • RAW (Read After Write): 后续指令读取前一指令尚未写入的寄存器
  • WAW (Write After Write): 两条指令写入同一寄存器，乱序导致写序颠倒
  • WAR (Write After Read): 后续指令覆盖前一指令尚未读取的寄存器

SCR1 是 严格顺序发射、顺序执行、顺序写回 的流水线，WAW 和 WAR 不可能发生。唯一需要考虑的是 RAW 冒险。

SCR1 为何对单周期指令无 RAW 冒险

理解这一点需要精确的时钟边沿时序分析。

关键时序边沿分析 — 分布式逻辑 MPRF

在分布式 MPRF 模式中，读操作是 纯组合逻辑（异步）：

assign mprf2exu_rs1_data_o = (rs1_addr_vd) ? mprf_int[exu2mprf_rs1_addr_i] : '0;

写操作是 时序逻辑（同步），在时钟上升沿触发：

always_ff @(posedge clk) begin
    if (wr_req_vd) mprf_int[exu2mprf_rd_addr_i] <= exu2mprf_rd_data_i;
end

考虑背靠背的两条 ADD 指令：

指令 T2 T3 T4 ─────────────────────────────────────────────────────────────── ADD x5, x1, x2 [IDU: 译码] [EXU: 执行] 在 T3 周期（时钟高电平期间）： 1. exu_queue_vd=1, rs1_addr=x1 → MPRF 异步输出 x1=5 2. IALU 组合逻辑: 5+3 = 8 3. exu2mprf_w_req_o=1, rd_addr=5, rd_data=8 4. posedge T3→T4: mprf_int[5] ← 8 (写入生效) ADD x6, x5, x4 [IFU: 取指] [IDU: 译码] [EXU: 执行] 在 T4 周期（时钟高电平期间）： 1. exu_queue_vd=1, rs1_addr=x5 → MPRF 异步输出 x5=8 ← 新值已生效! 2. IALU 组合逻辑: 8 + x4 = ...
无冒险的根本原因
第一条 ADD 在 T3 的 posedge 写入 x5。第二条 ADD 在 T4 才进入 EXU 阶段（因 IDU 在 T3 译码，T3→T4 posedge 锁存入 exu_queue）。T4 的 posedge 之后，MPRF 中的 x5 已经更新，第二条 ADD 异步读取 MPRF 时看到的是正确的值。 这就是 SCR1 的"零成本转发"——它并非真正的转发/bypass 逻辑，而是利用 流水线寄存器天然隔离了一个周期 的写入延迟。写入在 posedge T3→T4 生效，而读取发生在 T4 电平期间，两者之间有一个 posedge 的时间差距，写入刚好在读取之前完成。

LOAD 后的 RAW 冒险

LOAD 指令在多周期执行期间，RAW 冒险通过 流水线停顿 自动解决：

LW x5, 0(x1) IF | ID | EX(LSU) | EX(BUSY)| EX(rdy+WB) | ADD x6, x5, x4 | IF | ID | stall | stall | EX | ... ↑ exu_rdy=0 → 反压 clk: T0 T1 T2 T3 T4 T5 在 T4 期间: ADD 的 IDU 已译码完成但无法发往 EXU (exu_rdy=0) 在 T5 期间: LOAD 写回 x5, exu_rdy=1, ADD 进入 EXU, 读取 x5 新值 ✓

MPRF RAM 模式下的内部转发

当使用 SCR1_MPRF_RAM 配置时，MPRF 采用同步读 RAM 块，需要 1 个周期的读取延迟。此时 RAW 冒险可能发生在同一指令的不同操作数之间，MPRF 内置了转发逻辑：

// scr1_pipe_mprf.sv — RAM 模式的转发逻辑
assign rs1_new_data_req = wr_req_vd & (exu2mprf_rs1_addr_i == exu2mprf_rd_addr_i);
assign rs2_new_data_req = wr_req_vd & (exu2mprf_rs2_addr_i == exu2mprf_rd_addr_i);

// 如果前一周期写入了本周期要读的寄存器, 直接转发写数据
assign mprf2exu_rs1_data_o = (rs1_new_data_req_ff) ? rd_data_ff
                             : ((rs1_addr_vd_ff)   ? rs1_data_ff
                                                    : '0);

当 wr_req_vd & (rs1_addr == rd_addr) 时，下一周期的 _ff 版本为 1，直接将寄存的写数据 rd_data_ff 转发到读端口，绕过了 1 周期同步读延迟。

反压信号传播延迟
exu_rdy 是组合逻辑信号（不经过寄存器），因此反压在同周期内即传导到 IFU。EXU 在 T3 周期发现 LSU 忙 → IFU 在 T3 周期就收到 idu2ifu_rdy=0 → T4 周期开始取指停止。反压延迟 = 0 周期（纯组合逻辑）。

当 exu2ifu_pc_new_req_o=1 时（分支跳转/陷阱），exu_queue_vd_next=0，新指令不会被锁存入 EXU 队列。

第十三课: Scoreboard 分析 — SCR1 为何不需要

Scoreboard 的定义与用途
Scoreboard 是一种硬件结构，用于跟踪每个寄存器是否被等待中的指令写入。在乱序执行或有多周期功能单元的处理器中，Scoreboard 用来检测 RAW/WAR/WAW 冒险并暂停相关指令。

SCR1 不需要 Scoreboard 的原因

处理器特征SCR1需要 Scoreboard 的处理器
发射方式顺序发射（In-order Issue）乱序发射（Out-of-order Issue）
执行方式顺序执行（In-order Execute）乱序执行（Out-of-order Execute）
写回方式顺序写回（In-order Write-back）乱序写回（Out-of-order Write-back）
功能单元单功能单元（IALU+MDU+LSU 共享 EXU）多功能单元（独立的 ALU, FPU, LSU）
冒险处理流水线自然隔离 + 停顿Scoreboard + 转发 + 停顿

SCR1 的"替代方案"

  1. 单周期指令 RAW: 流水线寄存器天然隔离（EXU 队列锁存延迟了 1 个周期，刚好覆盖 MPRF 写入延迟）
  2. 多周期指令 RAW: exu_rdy=0 停顿整个流水线，直到多周期指令完成
  3. WAW/WAR: 顺序发射和执行保证了写序与程序序一致，WAR 自然满足
  4. 结构冒险: 单功能单元共享 EXU，无多发射结构冲突
SCR1 的设计哲学
SCR1 是典型的 极简顺序处理器。它选择用流水线停顿（stall）替代 Scoreboard 的复杂寄存器跟踪逻辑，用流水线寄存器的天然延迟替代转发逻辑。这种设计牺牲了多周期指令期间的吞吐量，换取了极低的面积和功耗——这正是 SCR1 作为 MCU 级 RISC-V 核的核心价值。
