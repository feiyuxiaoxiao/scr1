第一课: 本周概述

本周内容
正常程序流中 PC 按顺序递增（+4 或 +2）。以下事件会改变程序流：JAL/JALR 跳转、BEQ/BNE 等分支、ECALL/MRET 陷阱、异常、中断、WFI 等待、调试暂停。本周深入理解每种事件的 PC 生成机制和流水线暂停/清空。

第二课: NEW_PC 机制 -- 谁来产生新 PC？

三层新 PC 生成体系

层级模块产生信号用途
1CSRcsr2exu_new_pc_o异常/中断/MRET 的目标地址（MTVEC 或 MEPC）
2EXU(IALU)ialu_addr_resJAL/JALR/BRANCH 的目标地址 + FENCE.I 的 inc_pc + WFI 的 curr_pc
3HDUhdu2exu_dbg_new_pc_i调试恢复时的新 PC

EXU 端的 6 路 PC 多路器（最高优先级胜出）

// scr1_pipe_exu.sv:400-411 -- 新 PC 的最终选择
always_comb begin
    case (1'b1)
        // P1: 复位
        init_pc              : exu2ifu_pc_new_o = SCR1_RST_VECTOR;
        // P2: 陷阱 (异常/中断/MRET) -- CSR 提供
        exu2csr_take_exc_o,
        exu2csr_take_irq_o,
        exu2csr_mret_instr_o : exu2ifu_pc_new_o = csr2exu_new_pc_i;
        // P3: 调试恢复
        dbg_run_start_npbuf  : exu2ifu_pc_new_o = hdu2exu_dbg_new_pc_i;
        // P4: WFI 退出 (PC 保持不变)
        wfi_run_start_ff     : exu2ifu_pc_new_o = pc_curr_ff;
        // P5: FENCE.I
        exu_queue.fencei_req : exu2ifu_pc_new_o = inc_pc;
        // P6: 普通跳转/分支
        default              : exu2ifu_pc_new_o = ialu_addr_res & SCR1_JUMP_MASK;
    endcase
end
优先级设计理念
异常/中断/MRET 的优先级高于普通跳转，因为陷阱是"强制性"改变程序流。如果一条 JAL 指令同时触发了异常（如地址未对齐），CPU 应该进入陷阱处理而不是跳转。

新 PC 请求条件

// scr1_pipe_exu.sv:428-436
assign exu2ifu_pc_new_req_o = init_pc                              // 复位
                             | exu2csr_take_irq_o                   // 中断
                             | exu2csr_take_exc_o                   // 异常
                             | (exu2csr_mret_instr_o & ~csr2exu_mstatus_mie_up_i) // MRET
                             | (exu_queue_vd & exu_queue.fencei_req) // FENCE.I
                             | (wfi_run_start_ff & clk_pipe_en)     // WFI 退出
                             | dbg_run_start_npbuf                  // 调试恢复
                             | (exu_queue_vd & jb_taken);           // 跳转/分支采用

第三课: JAL/JALR 跳转目标地址计算

// JAL:  目标 = PC + imm(J-type),  返回地址 = PC+4 写入 rd
// JALR: 目标 = (rs1 + imm) & ~1,  返回地址 = PC+4 写入 rd

地址加法器 (SUM2) 的操作数选择

指令sum2_opop1op2
JAL / BRANCH / AUIPCPC_IMMpc_curr_ffexu_queue.imm
JALR / LOAD / STOREREG_IMMmprf2exu_rs1_data_iexu_queue.imm
JALR 的地址对齐
JALR 在 RISC-V 规范中要求目标地址最低位清零（& ~1）。在 SCR1 中通过 ialu_addr_res & SCR1_JUMP_MASK 实现，SCR1_JUMP_MASK 在有 RVC 时清除 bit[0]，无 RVC 时清除 bit[1:0]。

第四课: 分支比较与方向判定

分支判定三步走

1 地址加法器 计算跳转目标：addr_res = pc_curr + imm(B-type)
2 主 ALU 做比较：rs1 vs rs2，通过减法得出标志位 (z,s,o,c)
3 EXU 判定：branch_taken = branch_req & ialu_cmp 
// IALU 中各分支命令的判定公式
// CMD_SUB_EQ:  z == 1          (op1 == op2)   → BEQ
// CMD_SUB_NE:  z == 0          (op1 != op2)   → BNE
// CMD_SUB_LT:  s ^ o == 1      (signed less)  → BLT
// CMD_SUB_GE:  s ^ o == 0      (signed >=)    → BGE
// CMD_SUB_LTU: c == 0          (unsigned <)   → BLTU
// CMD_SUB_GEU: c == 1          (unsigned >=)  → BGEU

分支未采用时的惩罚

场景周期IFU 状态惩罚
分支未采用T3 发现条件假继续顺序取指 0x2080（无惩罚）
分支采用T3 发现条件真T4 flush 队列，T5 重新取指1 周期惩罚
为什么未采用无惩罚？
因为 IFU 天然"乐观"地按顺序取下一条指令。分支未采用 = 下一条就是 0x204 (PC+4)，IFU 的推测完全正确，无需清空流水线。

第五课: 流水线暂停 (Stall)

Stall 的触发源

触发条件信号影响的模块
多周期乘除法exu_rdy = ialu_rdy (0)IDU(停发命令) → IFU(停取指)
LSU 访存未完成exu_rdy = lsu_rdy (0)同上
CSR MSTATUS/MIE 更新exu_rdy = 0同上
WFI 暂停exu_queue_barrier = 1IFU 停止 + IDU 停止
调试暂停hdu2exu_dbg_halted_i同上

Stall 的级联传播路径

EXU 忙 (exu_rdy=0)
    │
    ▼
exu2idu_rdy_o = 0    // EXU 告诉 IDU: "别发新指令"
    │
    ▼
idu2ifu_rdy = 0      // IDU 使用此信号告诉 IFU: "别取新指令"
    │
    ▼
IFU 不发新请求       // pipe2ifu_stop_fetch_i = 1
    │
    ▼
FSM 回到 IDLE       // 停止取指
EXU 队列屏障 vs 反压
exu_queue_barrier（WFI/调试暂停）比反压更强：它连 IDU 内部也不允许进行，而反压只是阻塞新指令的传递。屏障时 exu2idu_rdy_o = exu_rdy & ~exu_queue_barrier。

第六课: 流水线清空 (Flush) 的完整时序

Flush 触发链

// T3: EXU 判定跳转/分支/陷阱
exu2ifu_pc_new_req_o = 1'b1;     // 请求新 PC
exu2ifu_pc_new_o     = target;  // 目标地址

// T3: IFU 收到 flush 请求（同周期）
q_flush_req = 1'b1;             // 清空指令队列

// T3: FSM 转 IDLE（如果 jump 不被停止取指屏蔽）
ifu_fetch_req = 1'b0;          // 停止当前取指

// T4: 队列清空完成 (rptr=wptr=0)
// T4: IDU 收到清空后的无效数据
// T4: FSM 转 FETCH，从新 PC 重新取指

Flush 过程中各模块状态

周期IFU 队列IDUEXU
T3flush_req=1，清空中译码前一条（将 invalid）产生 new_pc_req
T4队列空 (wptr=rptr=0)ifu2idu_vd=0（无效）空闲或新 PC 未生效
T5收到新指令(新 PC)空闲或开始译码—
T6下一指令译码新指令—

第七课: WFI 等待中断指令的状态机

                   // 条件: 无挂起中断 AND (WFI指令 OR 刚启动)
    ┌──────────┐  wfi_halt_cond  ┌──────────┐
    │ RUNNING  │ ──────────────▶ │  HALTED  │
    │halted=0  │                 │halted=1  │
    └──────────┘ ◀────────────── └──────────┘
                   wfi_run_req
                   // 条件: ip_ie OR dbg_halt2run
// 暂停条件 (scr1_pipe_exu.sv:267-276)
wfi_halt_cond = ~csr2exu_ip_ie_i      // 无待处理中断
              & (exu_queue_vd & exu_queue.wfi_req   // WFI 指令在队列中
                 | wfi_run_start_ff)            // 或刚从暂停恢复
              & ~hdu2exu_no_commit_i;         // HDU 允许提交

// 暂停后: exu_queue_barrier = 1 → 阻塞全流水线
// 恢复时: wfi_run_start_ff 发出单周期脉冲 → 保持 PC 不跳转
WFI 不改变 PC
WFI 退出时 PC 不变（wfi_run_start_ff: pc_curr_ff），下一条执行的指令是 WFI 后面的指令。本质上 WFI 只是"停等中断"，不是"跳转"。

第八课: ECALL 进入 / MRET 返回 完整流程

ECALL 进入陷阱

1 IDU 译码 ECALL：设置 exc_req=1, exc_code=ECALL_M(11)
2 EXU 处理：异常编码通过异常优先级仲裁 → exu2csr_exc_code_i
3 CSR 事件处理：e_exc=1 → 保存上下文 → 关闭 MIE → 新 PC = MTVEC.BASE
4 EXU PC 多路器：选 csr2exu_new_pc_i (优先级 2)
5 IFU 清空队列：从 MTVEC.BASE 重新取指

MRET 返回

1 IDU 译码 MRET：设置 mret_req=1
2 CSR 事件处理：e_mret=1 → MIE=MPIE, MPIE=1
3 CSR 生成新 PC：csr2exu_new_pc_o = csr_mepc
4 EXU 延迟发送：exu2csr_mret_instr_o & ~csr2exu_mstatus_mie_up_i → 若 mstatus 更新同周期则等一拍
5 IFU 清空队列：从 MEPC 重新取指
MRET 的 2 周期延迟
MRET 指令总是占用 2 个周期（EAS 表 29）：T3 执行 MRET 逻辑 + T4 等待 mstatus 更新生效。所以 MRET 延迟 = 5（4 级流水 + 1 额外周期）。
