第一课: 本周概述

本周聚焦两个模块
IDU (Instruction Decode Unit) — 纯组合逻辑译码器,将 32 位指令编码译为一组控制信号 (type_scr1_exu_cmd_s),无内部状态。
EXU (Execution Unit) — 在第 6-7 周已覆盖数据通路和控制流,本周深入其调度仲裁机制: 就绪信号合成、EXU 队列屏障、CSR 事件处理、指令退役与 PC 推进。

第二课: IDU 架构 — 纯组合逻辑,无状态

IFU ──32-bit instr──→ IDU ──18-field exu_cmd──→ EXU │ 纯组合逻辑,单周期完成 无流水线寄存器,无状态记忆 
// scr1_pipe_idu.sv -- IDU 没有时钟/复位端口,只有组合输入输出
module scr1_pipe_idu (
    input   logic  ifu2idu_vd_i,        // IFU 指令有效
    input   logic  ifu2idu_instr_i,     // 32 位指令编码
    output  logic  idu2exu_req_o,       // 到 EXU 的请求
    output  logic  idu2exu_cmd_o        // 18 字段命令结构体
    ...
);
为什么是组合逻辑?
译码不需要时钟: 给定指令编码,译码结果瞬间确定。RISC-V 的规整编码使得大多数控制信号可以直接从 opcode/funct3/funct7 译出,无需多级状态机。唯一的"状态"来自 EXU 反压——IDU 通过 idu2ifu_rdy_o = exu2idu_rdy_i 直通反压。

第五课: 6 种立即数拼接公式

格式拼接表达式符号示例指令
I-type{ {21{instr[31]}}, instr[30:20] }有符号ADDI, LOAD, JALR
S-type{ {21{instr[31]}}, instr[30:25], instr[11:7] }有符号STORE
B-type{ {20{instr[31]}}, instr[7], instr[30:25], instr[11:8], 1'b0 }有符号BRANCH
U-type{ instr[31:12], 12'b0 }—LUI, AUIPC
J-type{ {12{instr[31]}}, instr[19:12], instr[20], instr[30:21], 1'b0 }有符号JAL
shamt{ 27'b0, instr[24:20] }零扩展SLLI, SRLI, SRAI
B-type 为什么需要 <<1?
B-type 立即数最低位永远为 0 (未编码)。因为 RISC-V 的 16 位 RVC 指令要求分支目标地址也是 2 字节对齐,bit[0] 字段被省略以扩大范围。拼好后再 <<1 恢复——公式中的 1'b0 就是这一步。

为什么立即数位域被打散?

RISC-V 故意把立即数 bit 散布到指令中不同位置,这不是随意为之——位域排布可使 RVI 和 RVC 的 rs1/rs2/rd 地址位在相同物理位置,简化寄存器文件读取逻辑。IDU 负责把散落的 bit 重新拼好。

第八课: C.MV 和 C.BEQZ 的实现技巧

C.MV = ADD rd, x0, rs2

不需要专门的 MOVE 命令
C.MV 直接复用 ALU 的 ADD 通路: ialu_op=REG_REG, ialu_cmd=ADD, rs1_addr=x0, rd=rd, rs2=rs2。x0 永远为 0,所以 ADD(x0, rs2) = rs2,完美实现寄存器复制。这是 RISC-V 设计哲学 '复用而非新增' 的体现。

C.BEQZ = SUB_EQ(rs1, x0)

// C.BEQZ/C.BNEZ 只有一个寄存器源操作数 (rs1')
// 但 IDU 始终设置 use_rs2=1, rs2_addr=x0
// 因为 IALU 需要两个操作数做减法比较
// rs1 - 0 == 0  ⇔  rs1 == 0
C.BEQZ → ialu_cmd=SUB_EQ
BEQZ 在硬件上是 SUB_EQ(rs1, x0): rs1 减 0,判断零标志。如果 rs1==0 则 z=1, SUB_EQ 为真,分支采用。

第十一课: EXU 调度仲裁 — 就绪信号与队列屏障

就绪 (Ready) 信号合成 (scr1_pipe_exu.sv:496-498)

always_comb begin
    case (1'b1)
        lsu_req :  // 访存指令
            exu_rdy = lsu_rdy | lsu_exc_req;   // LSU 就绪 或 访存异常
        csr2exu_rw_exc_req_i : // CSR 异常
            exu_rdy = 1'b1;                     // 异常直接通过
        ialu_vd :
            exu_rdy = ialu_rdy;               // IALU 就绪
        default :
            exu_rdy = 1'b1;                     // 其他 (无 ALU 操作) 直接通过
    endcase
end

队列屏障 (Queue Barrier)

// 两种场景触发队列屏障
exu_queue_barrier = wfi_halted_ff                          // WFI 暂停
                    | (hdu2exu_dbg_halted_i & ~exu_queue_vd);  // 调试暂停

// 屏障时: IDU 无法发新指令
exu2idu_rdy_o = exu_rdy & ~exu_queue_barrier;
屏障 vs 反压的区别
普通反压 (exu_rdy=0) 只阻塞新指令传递,已有的指令仍在队列中。屏障 (exu_queue_barrier=1) 连 IDU 内部都停止了——WFI 和调试暂停需要"冻结整个流水线"。

EXU → IDU 接口完整信号表

信号方向含义公式
idu2exu_req_o→ EXU指令有效= ifu2idu_vd_i (透传)
exu2idu_rdy_o← EXUEXU 可以接收= exu_rdy & ~exu_queue_barrier
