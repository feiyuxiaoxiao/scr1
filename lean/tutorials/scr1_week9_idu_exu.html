第一课: 本周概述

本周聚焦两个模块
IDU (Instruction Decode Unit) — 纯组合逻辑译码器,将 32 位指令编码译为一组控制信号 (type_scr1_exu_cmd_s),无内部状态。
EXU (Execution Unit) — 在第 6-7 周已覆盖数据通路和控制流,本周深入其调度仲裁机制: 就绪信号合成、EXU 队列屏障、CSR 事件处理、指令退役与 PC 推进。

第二课: IDU 架构 — 纯组合逻辑,无状态

IFU ──32-bit instr──→ IDU ──18-field exu_cmd──→ EXU │ 纯组合逻辑,单周期完成 无流水线寄存器,无状态记忆 
// scr1_pipe_idu.sv -- IDU 没有时钟/复位端口,只有组合输入输出
module scr1_pipe_idu (
    input   logic  ifu2idu_vd_i,        // IFU 指令有效
    input   logic  ifu2idu_instr_i,     // 32 位指令编码
    output  logic  idu2exu_req_o,       // 到 EXU 的请求
    output  logic  idu2exu_cmd_o        // 18 字段命令结构体
    ...
);
为什么是组合逻辑?
译码不需要时钟: 给定指令编码,译码结果瞬间确定。RISC-V 的规整编码使得大多数控制信号可以直接从 opcode/funct3/funct7 译出,无需多级状态机。唯一的"状态"来自 EXU 反压——IDU 通过 idu2ifu_rdy_o = exu2idu_rdy_i 直通反压。
IDU 输出信号完整列表 (除 exu_cmd 外)
信号方向公式 / 说明
idu2ifu_rdy_o→ IFU= exu2idu_rdy_i (直通反压)
idu2exu_req_o→ EXU= ifu2idu_vd_i (直通有效)
idu2exu_use_rs1_o→ EXU时钟门控: 指令确实用 rs1 时为 1
idu2exu_use_rs2_o→ EXU时钟门控: 指令确实用 rs2 时为 1
idu2exu_use_rd_o→ EXU时钟门控: 指令会写 rd (非 EXE_STAGE 时不输出)
idu2exu_use_imm_o→ EXU时钟门控: 指令用到 imm 域 (非 EXE_STAGE 时不输出)

第五课: EXU 字段详解 — 位宽、用途、IDU 中的来源

18 字段逐字段溯源: 谁在 IDU 中写它? 写什么值?

1. instr_rvc (1 bit) — 指令类型标志

位宽1
用途EXU 用此 bit 计算 inc_pc := pc + (instr_rvc ? 2 : 4); 非法指令 trap value 也用此 bit 指明高半部分格式
IDU 默认值1'b0
置 1 条件instr_type == SCR1_INSTR_RVC0|RVC1|RVC2; 若无 RVC 扩展且 instr[1:0]!=2'b11, 置 1 标记为 RVC 非法

2. ialu_op (1 bit) — IALU 操作数来源

位宽1 (enum: SCR1_IALU_OP_REG_REG / SCR1_IALU_OP_REG_IMM)
用途EXU 中: op1 始终 = mprf_rs1, op2 = (ialu_op==REG_REG) ? mprf_rs2 : exu_queue.imm
IDU 默认值SCR1_IALU_OP_REG_REG
置 REG_IMM 的条件OP_IMM 所有指令; C.ADDI / C.ADDI4SPN / C.SLLI / C.SRLI / C.SRAI / C.ANDI / C.ADDI16SP

3. ialu_cmd (5 bit) — IALU 运算命令

位宽5 (enum: 0=NONE, 1=ADD, 2=SUB, 3=SLL, ..., 最大约 17 种含 M 扩展, 或 23 种含 M 扩展)
用途直接驱动 scr1_pipe_ialu 的命令端口,选中运算器做 ADD/SUB/SLL/SRL/SRA/XOR/OR/AND/SLT/SLTU/MUL/... 等操作
IDU 默认值SCR1_IALU_CMD_NONE
赋值来源OP 类: {funct7, funct3} → 查表; OP_IMM 类: funct3 → 查表; BRANCH: funct3 → SUB_EQ/SUB_NE/SUB_LT/SUB_GE/SUB_LTU/SUB_GEU; RVC ALU: 各象限直接逐指令赋值; 非法指令: 清为 NONE

4. sum2_op (1 bit) — 地址加法器操作数来源

位宽1 (enum: SCR1_SUM2_OP_PC_IMM / SCR1_SUM2_OP_REG_IMM)
用途EXU: (PC_IMM) → ialu_addr_op1=pc_curr, op2=imm; (REG_IMM) → ialu_addr_op1=mprf_rs1, op2=imm
IDU 默认值SCR1_SUM2_OP_PC_IMM
REG_IMM 条件LOAD, STORE, JALR, C.LW, C.SW, C.LWSP, C.SWSP, C.JR, C.JALR
PC_IMM 条件JAL, BRANCH, AUIPC, C.J, C.JAL, C.BEQZ, C.BNEZ

5. lsu_cmd (4 bit) — LSU 命令

位宽4 (enum: NONE/LB/LH/LW/LBU/LHU/SB/SH/SW)
用途驱动 scr1_pipe_lsu 模块: 控制访存宽度/符号扩展/读或写
IDU 默认值SCR1_LSU_CMD_NONE
赋值来源LOAD: funct3 → {LB:000, LH:001, LW:010, LBU:100, LHU:101}; STORE: funct3 → {SB:000, SH:001, SW:010}; RVC: C.LW/LWSP→LW, C.SW/SWSP→SW

6. csr_op (1 bit) — CSR 数据来源

位宽1 (enum: SCR1_CSR_OP_REG / SCR1_CSR_OP_IMM)
用途EXU: REG → w_data = mprf_rs1; IMM → w_data = zero_extend(rs1_addr[4:0] 作 zimm)
IDU 默认值SCR1_CSR_OP_REG
IMM 条件CSRRWI/CSRRSI/CSRRCI (funct3 = 3'b101/110/111)

7. csr_cmd (2 bit) — CSR 操作类型

位宽2 (enum: NONE/WRITE/SET/CLEAR)
用途EXU 的 CSR 访问 FSM: WRITE→直接覆盖; SET→data|csr_data; CLEAR→data&~csr_data
赋值来源CSRRW/CSRRWI→WRITE; CSRRS/CSRRSI→SET; CSRRC/CSRRCI→CLEAR

8. rd_wb_sel (3 bit) — 写回源选择

位宽3 (enum: NONE/IALU/SUM2/IMM/INC_PC/LSU/CSR)
用途EXU 的 MPRF 写回多路复用器: 选择 6 个数据源之一写入 rd
赋值来源OP/OP_IMM→IALU; LUI/C.LI/C.LUI→IMM; JAL/JALR/C.JAL/C.JR/C.JALR→INC_PC; LOAD/C.LW/C.LWSP→LSU; AUIPC→SUM2; CSR→CSR

9-13. 五个控制请求位 (jump_req, branch_req, mret_req, fencei_req, wfi_req)

字段位宽置 1 条件
jump_req1JAL, JALR, C.J, C.JAL, C.JR, C.JALR
branch_req1BRANCH (全部 6 种), C.BEQZ, C.BNEZ
mret_req1funct12 == 12'h302 且 SYSTEM
字段位宽置 1 条件
fencei_req1MISC_MEM + funct3=3'b001 + 其余字段全零
wfi_req1funct12 == 12'h105 且 SYSTEM

14-16. 寄存器地址域 (rs1_addr, rs2_addr, rd_addr)

字段位宽RVI 来源RVC 来源
rs1_addr5instr[19:15]RVC0: {2'b01, instr[9:7]}; RVC1/C.SLLI: instr[11:7]; RVC2 C.LWSP/C.SWSP: SP_ADDR; C.MV/JR/JALR: instr[11:7]; C.ADD: instr[11:7]

第六课: 6 种立即数拼接公式

格式拼接表达式符号示例指令
I-type{ {21{instr[31]}}, instr[30:20] }有符号ADDI, LOAD, JALR
S-type{ {21{instr[31]}}, instr[30:25], instr[11:7] }有符号STORE
B-type{ {20{instr[31]}}, instr[7], instr[30:25], instr[11:8], 1'b0 }有符号BRANCH
U-type{ instr[31:12], 12'b0 }—LUI, AUIPC
J-type{ {12{instr[31]}}, instr[19:12], instr[20], instr[30:21], 1'b0 }有符号JAL
shamt{ 27'b0, instr[24:20] }零扩展SLLI, SRLI, SRAI
B-type 为什么需要 <<1?
B-type 立即数最低位永远为 0 (未编码)。因为 RISC-V 的 16 位 RVC 指令要求分支目标地址也是 2 字节对齐,bit[0] 字段被省略以扩大范围。拼好后再 <<1 恢复——公式中的 1'b0 就是这一步。

为什么立即数位域被打散?

RISC-V 故意把立即数 bit 散布到指令中不同位置,这不是随意为之——位域排布可使 RVI 和 RVC 的 rs1/rs2/rd 地址位在相同物理位置,简化寄存器文件读取逻辑。IDU 负责把散落的 bit 重新拼好。

第七课: 6 种立即数位级提取图

I-type 立即数 (ADDI, LOAD, JALR)

instr bit: 31 ─────────── 20 19 ── 15 14 ── 12 11 ── 7 6 ── 0 ├── sign[11:0] ──┤├─ rs1 ─┤├funct3┤├─ rd ─┤├ opcode ┤ └─ imm[11:0] ────┘ imm[31:0] = { 21{instr[31]}, instr[30:20] } ──→ 符号扩展到 32-bit: imm[11:0] 在 instr 中连续,方便直接提取

S-type 立即数 (STORE)

instr bit: 31 ────── 25 24 ── 20 19 ── 15 14 ── 12 11 ───── 7 6 ── 0 ├─ imm[11:5] ┤├─ rs2 ┤├─ rs1 ┤├funct3┤├─ imm[4:0] ┤├ opcode ┤ imm[31:0] = { 21{instr[31]}, instr[30:25], instr[11:7] } ──→ 高位段 [11:5] 在 [30:25], 低位段 [4:0] 在 [11:7] 拆成两段是为了让 rs1/rs2 字段在 RVI 中保持固定位置

B-type 立即数 (BRANCH)

instr bit: 31 30 ─── 25 24 ── 20 19 ── 15 14 ── 12 11 ── 8 7 6 ── 0 ├sgn├ imm[10:5] ┤├─ rs2 ┤├─ rs1 ┤├funct3┤├ imm[4:1] ┤ sgn ├ opcode ┤ imm[12] imm[10:5] imm[4:1] imm[11] imm[31:0] = { 20{instr[31]}, instr[7], instr[30:25], instr[11:8], 1'b0 } ──→ 5 个碎片: bit[12]→[31], [10:5]→[30:25], [4:1]→[11:8], [11]→[7] bit[0] 永远为 0, 拼好即 ×2 完成位扩展

U-type 立即数 (LUI, AUIPC)

instr bit: 31 ──────────────── 12 11 ── 7 6 ── 0 ├─── imm[31:12] ────┤├─ rd ┤├ opcode ┤ imm[31:0] = { instr[31:12], 12'b0 } ──→ 最简洁: 高 20 位是立即数,低 12 位补零 这是唯一不需要符号扩展的格式 (rd_wb_sel=IMM 直通)

J-type 立即数 (JAL)

instr bit: 31 30 ── 21 20 19 ─── 12 11 ── 7 6 ── 0 sgn ├──────┤ sgn ├────────┤├─ rd ┤├ opcode ┤ │ │[10:1]│ │[19:12] │ │ │ │ │ │ imm[20] imm[10:1] imm[11] imm[19:12] imm[31:0] = { 12{instr[31]}, instr[19:12], instr[20], instr[30:21], 1'b0 } ──→ 极度碎片化: bit[20]→[31] (符号), [19:12]→[19:12], [20]→[11], [10:1]→[30:21] 与 B-type 类似 bit[0] 永远为 0

shamt 立即数 (SLLI, SRLI, SRAI)

instr bit: 31 ── 25 24 ── 20 19 ── 15 14 ── 12 11 ── 7 6 ── 0 ├funct7 ┤├ shamt ┤├─ rs1 ┤├funct3┤├─ rd ┤├ opcode ┤ imm[31:0] = { 27'b0, instr[24:20] } ──→ 零扩展到 32-bit: shamt 在 instr[24:20], 高位补 0 注意: SLLI/SRLI/SRAI 对 funct7 有额外检查 (0000000/0100000)

第十课: C.MV 和 C.BEQZ 的实现技巧

C.MV = ADD rd, x0, rs2

不需要专门的 MOVE 命令
C.MV 直接复用 ALU 的 ADD 通路: ialu_op=REG_REG, ialu_cmd=ADD, rs1_addr=x0, rd=rd, rs2=rs2。x0 永远为 0,所以 ADD(x0, rs2) = rs2,完美实现寄存器复制。这是 RISC-V 设计哲学 '复用而非新增' 的体现。

C.BEQZ = SUB_EQ(rs1, x0)

// C.BEQZ/C.BNEZ 只有一个寄存器源操作数 (rs1')
// 但 IDU 始终设置 use_rs2=1, rs2_addr=x0
// 因为 IALU 需要两个操作数做减法比较
// rs1 - 0 == 0  ⇔  rs1 == 0
C.BEQZ → ialu_cmd=SUB_EQ
BEQZ 在硬件上是 SUB_EQ(rs1, x0): rs1 减 0,判断零标志。如果 rs1==0 则 z=1, SUB_EQ 为真,分支采用。

    if (exu_queue_en) begin
        if (idu2exu_use_rs1_i) exu_queue.rs1_addr <= idu2exu_cmd_i.rs1_addr;
        if (idu2exu_use_rs2_i) exu_queue.rs2_addr <= idu2exu_cmd_i.rs2_addr;
        if (idu2exu_use_rd_i)  exu_queue.rd_addr  <= idu2exu_cmd_i.rd_addr;

assign exu2mprf_rs2_addr_o = mprf_rs2_req ? mprf_rs2_addr : '0;

// 4. MPRF 读请求生成 (RAM 块时序路径优化)
//    当 exu_queue_en 时提前发出下一指令的地址; 否则用当前队列地址
mprf_rs1_addr = exu_queue_en ? idu2exu_cmd_i.rs1_addr : exu_queue.rs1_addr;
mprf_rs2_addr = exu_queue_en ? idu2exu_cmd_i.rs2_addr : exu_queue.rs2_addr;
MPRF RAM 读时序优化
当 MPRF 用 RAM 实现时,读操作为同步 (延迟 1 拍)。EXU 在 exu_queue_en 有效时提前将 下一指令 的 rs1/rs2 地址发送给 MPRF,这样寄存器数据在指令进入 exu_queue 的同时就绪。如果 exu_queue_en 无效 (反压),则沿用当前队列保存的地址。

4. 单周期指令: default 分支 — 单周期 ALU/CSR异常/无操作指令直接 exu_rdy=1

MUL/DIV 对流水线的反压

就绪信号的级联传播
第一阶段: scr1_pipe_ialu 内部 MUL/DIV 模块在计算中 → ialu_rdy = 0
第二阶段: EXU 就绪合成 exu_rdy = ialu_rdy = 0
第三阶段: exu2idu_rdy_o = 0 → IDU 无法发新指令
第四阶段: idu2ifu_rdy_o = 0 → IFU 停止取指
第五阶段: MUL/DIV 完成 → ialu_rdy = 1 → 整条链路恢复

当 exu_rdy=0 时 exu_queue_vd 保持,指令不会从队列中清除,WR 阶段暂停。

非 MUL/DIV 指令的 bypass 路径

注意 exu_rdy 的 case(1'b1) 优先级: LSU 请求排第一,然后才是 M 扩展的 ialu_vd。这意味着:

  • 加载/存储指令 (lsu_req=1) 直接走 LSU 就绪路径,不检查 ialu_rdy
  • 非 MUL/DIV 的 ALU 指令 — 没有 ialu_vd 信号 (M 扩展未使能时 ialu_vd 不存在) — 直接走 default 分支 exu_rdy=1
  • 仅当 M 扩展使能 且 ialu_cmd 是 MUL/DIV/REM 时 (ialu_vd=1),才进入 exu_rdy = ialu_rdy 分支
